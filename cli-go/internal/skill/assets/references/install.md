# Install or upgrade

The CLI is a single native binary (macOS arm64/x64, Linux x64/arm64, Windows x64). It does not need Node.js, npm or Python. The official installers download from the project's GitHub releases, verify the SHA-256 checksum of the binary, and install without administrator rights.

Do not pipe a downloaded script into `sh` or `iex`. When a Muvloom setup guide is available (the page that sent you here, or `/cli/setup.md` on the same origin, keeping its `?v=`), fetch `install.sh` or `install.ps1` from that same folder, verify the SHA-256 published in the guide, then run it with `MUVLOOM_MIN_VERSION` set to the guide's minimum (currently 0.2.4). That installs the latest release that meets the minimum and will not downgrade a newer CLI already on the machine. If no setup guide is at hand, open the official connect page and follow its verified command; do not skip the checksum.

- Where it installs, unless `MUVLOOM_INSTALL_DIR` says otherwise: the directory of the copy that is already installed (so an upgrade replaces it and only one copy exists), else `/usr/local/bin` when that is on PATH and writable without sudo (macOS/Linux), else `~/.local/bin` (macOS/Linux) or `%LOCALAPPDATA%\Programs\muvloom` (Windows). Prefer `MUVLOOM_MIN_VERSION=0.2.4` over pinning `MUVLOOM_VERSION` to an exact release: an exact pin can downgrade a newer install, and the installer will refuse that downgrade. For a system-wide install that needs administrator rights, run it yourself with `sudo MUVLOOM_INSTALL_DIR=/usr/local/bin sh`.
- The installer prints the installed path. On Windows it writes the user PATH. On macOS/Linux it appends the install directory to the user's shell profile when missing, and prints the exact file it changed. A new agent command may still be a new shell: also add the directory to PATH for this session (`export PATH="<that directory>:$PATH"` or refresh the user PATH in PowerShell). `MUVLOOM_NO_MODIFY_PATH=1` leaves the profile or user PATH unchanged. Do not write `MUVLOOM_API_URL` into a profile; set it before the first `auth status`, keep it through any required login, then unset it. After the target service is ready, `auth status` shows `api_url_source: connection` and works without the variable.
- If the installer warns that another `muvloom` is earlier on PATH, that copy keeps running instead; call the new one by its full path, or tell the user to remove the old one.
- Run `muvloom version` first. If the installed version is already at or above the guide's minimum, do not run the installer.

## Finding an installed CLI

Agent shells often lack the directory the CLI was installed into, so `muvloom` can be missing from PATH while it is installed. Before installing, check these locations and use the first one that exists, by full path or after adding its directory to PATH for the session: `~/.local/bin/muvloom`, `/usr/local/bin/muvloom`, `/opt/homebrew/bin/muvloom` (macOS/Linux); `%LOCALAPPDATA%\Programs\muvloom\muvloom.exe` (Windows). Run `version` on it: install only when none exists or its version is older than the minimum this task needs. Never downgrade a newer copy.

- Unsupported platforms fail with a clear message; do not try other download sources.
- Re-running the installer upgrades the CLI in place when a newer release meets the minimum; existing logins are kept. Since CLI 0.2.1 a `MUVLOOM_CONFIG_DIR` directory keeps its own login in files there and never touches the keychain login of the default directory; a login made there with an older CLI must be made again (`auth status` says so). Then run `muvloom auth status`: since CLI 0.2.2 it updates each Claude Code and Codex Skill copy the CLI installed that is of an older release (user scope, and the project-scope copy of the nearest directory above the current one holding `.git`, `go.mod` or `package.json`) to the bundled version. It leaves edited, incomplete or newer copies alone and names any copy it could not update; run a suggested project-scope `skill install` from that project's directory. A host loads the updated Skill in its next session; the current session keeps the instructions it already read. Skills installed some other way (for example WorkBuddy's or 豆包工作's) follow their own install guide. Resume the original task.
- To sign out, run `muvloom auth logout`. To uninstall, delete the binary from the install directory the installer printed, remove the PATH line it added (it printed the file), and optionally delete the config directory after logout (`credentials.json` lives there: `MUVLOOM_CONFIG_DIR` or the user config directory `/muvloom`).
