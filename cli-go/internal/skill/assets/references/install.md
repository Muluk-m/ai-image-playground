# Install or upgrade

The CLI is a single native binary (macOS arm64/x64, Linux x64/arm64, Windows x64). It does not need Node.js, npm or Python. Both the bundled Skill launcher (`scripts/muvloom` / `scripts\muvloom.cmd`) and the official installers (`install.sh` / `install.ps1`) download directly from Muvloom's CDN (with GitHub Releases fallback), verify the SHA-256 checksum of the binary, and install without administrator rights.

If this Skill is already unpacked on disk and `muvloom` is not on `PATH`, you can run `<skill-dir>/scripts/muvloom` (macOS/Linux) or `<skill-dir>\scripts\muvloom.cmd` (Windows) directly: on first call it caches the SHA-256-verified binary into `~/.local/bin/muvloom` (or `%LOCALAPPDATA%\Programs\muvloom\muvloom.exe`) and forwards all arguments without modifying shell profiles.

Do not pipe a downloaded script into `sh` or `iex`. When a Muvloom setup guide is available (the page that sent you here, or `/cli/setup.md` on the same origin, keeping its `?v=`), fetch `install.sh` or `install.ps1` from that same folder, verify the SHA-256 published in the guide, then run it without pinning `MUVLOOM_VERSION`. That always installs or upgrades to the latest stable release, skips download if already up to date, and will not downgrade a newer CLI already on the machine. For one-step onboarding after installing the binary, run `muvloom setup --origin <guide-origin>` (it installs the Skill for the active host, connects the account, reads `capabilities`, and runs the zero-cost `images validate` smoke check). If no setup guide is at hand, open the official connect page and follow its verified command; do not skip the checksum.

- Where it installs, unless `MUVLOOM_INSTALL_DIR` says otherwise: the directory of the copy that is already installed (so an upgrade replaces it and only one copy exists), else `/usr/local/bin` when that is on PATH and writable without sudo (macOS/Linux), else `~/.local/bin` (macOS/Linux) or `%LOCALAPPDATA%\Programs\muvloom` (Windows). Do not pin `MUVLOOM_VERSION` to an older release: the default installer always resolves the latest stable release and refuses to downgrade a newer copy. For a system-wide install that needs administrator rights, run it yourself with `sudo MUVLOOM_INSTALL_DIR=/usr/local/bin sh`.
- The installer prints the installed path. On Windows it writes the user PATH. On macOS/Linux it appends the install directory to the user's shell profile when missing, and prints the exact file it changed. A new agent command may still be a new shell: also add the directory to PATH for this session (`export PATH="<that directory>:$PATH"` or refresh the user PATH in PowerShell). `MUVLOOM_NO_MODIFY_PATH=1` leaves the profile or user PATH unchanged. Do not write `MUVLOOM_API_URL` into a profile; set it before the first `auth status`, keep it through any required login, then unset it. After the target service is ready, `auth status` shows `api_url_source: connection` and works without the variable.
- If the installer warns that another `muvloom` is earlier on PATH, that copy keeps running instead; call the new one by its full path, or tell the user to remove the old one.
- Re-running the verified installer is safe and idempotent: it skips download when the latest stable release is already installed, upgrades older installs in place, and never downgrades a newer copy.

## Finding an installed CLI

Agent shells often lack the directory the CLI was installed into, so `muvloom` can be missing from PATH while it is installed. Before installing, check these locations and use the first one that exists, by full path or after adding its directory to PATH for the session: `~/.local/bin/muvloom`, `/usr/local/bin/muvloom`, `/opt/homebrew/bin/muvloom` (macOS/Linux); `%LOCALAPPDATA%\Programs\muvloom\muvloom.exe` (Windows). Run the verified installer when `muvloom` is missing or when you want to update to the latest stable release. Never downgrade a newer copy.

- Unsupported platforms fail with a clear message; do not try other download sources.
- Re-running the installer upgrades the CLI in place when a newer stable release is published; existing logins are kept. Since CLI 0.2.1 a `MUVLOOM_CONFIG_DIR` directory keeps its own login in files there and never touches the keychain login of the default directory; a login made there with an older CLI must be made again (`auth status` says so). Then run `muvloom auth status`: it updates each Claude Code, Codex, and WorkBuddy Skill copy the CLI installed that is of an older release (user scope, and the project-scope copy of the nearest directory above the current one holding `.git`, `go.mod` or `package.json`) to the latest official version. It leaves edited, incomplete or newer copies alone and names any copy it could not update; run a suggested project-scope `skill install` from that project's directory. A host loads the updated Skill in its next session; the current session keeps the instructions it already read. Skills installed some other way (for example 豆包工作's) follow their own install guide. Resume the original task.
- To sign out, run `muvloom auth logout`. To uninstall, delete the binary from the install directory the installer printed, remove the PATH line it added (it printed the file), and optionally delete the config directory after logout (`credentials.json` lives there: `MUVLOOM_CONFIG_DIR` or the user config directory `/muvloom`).
