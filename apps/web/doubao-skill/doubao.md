# 豆包工作安装与授权

幕芽、muya、muvloom 是同一个服务。技能名是 `muvloom`，展示名是「幕芽 Muvloom」。

用户只要求安装、更新或验收技能时，仅执行技能安装和发现检查：保留现有 CLI、账号和服务，不运行 `auth status`、`auth login`、`capabilities` 或其他账号探测，不访问凭据存储。只有用户要求连接账号或继续生成任务时才进入账号连接流程。

## 确认技能已安装

在豆包工作「插件·技能·伙伴 → 技能」中确认「幕芽 Muvloom」已启用；在新工作任务的输入框输入 `/muv`，或输入 `/` / `@` 后搜索 muv、幕芽、muvloom，检查候选技能。账号授权成功不代表技能安装成功。只存在技能文件不算安装成功。

还未安装时，由豆包工作在对话中下载幕芽接入指南同源的 `muvloom-doubao.zip`，检查技能内容和包内路径后，用宿主提供的添加/上传技能能力导入这个 ZIP 或其中的 `muvloom/` 目录。不要写入 `~/.doubao/skills`、`.user_skills` 或其他未经验证的目录。导入后验证已发现并启用。若新工作任务输入 `/muv` 仍无候选，保留安装文件，请用户完整退出并重新打开客户端，再输入 `/muv` 验证；不要重复安装或预先宣称成功。不要把手动上传交给用户作为默认安装步骤，不要假装该包已在技能市场上架。必要确认使用宿主正常提示，不修改全局保护。

用户要求连接账号时，按当前接入指南页面的域名，为这次登录选择该页面对应的 API（在第一次 `auth status` 之前设置 `MUVLOOM_API_URL`，完成该服务的状态检查和必要登录后再取消，不要写入配置文件）。这一步也适用于已经安装 CLI 的情况。CLI 安装和服务地址选择按接入页面的安装指南执行。CLI 0.2.4 的 `skill install --host` 只支持 Claude Code 和 Codex；豆包工作通过对话安装本地技能，不发明 CLI host 参数。

## 连接账号

授权必须使用系统默认浏览器。用户可能已经在默认浏览器里登录了幕芽。不要指定 Chrome 或任何其他浏览器，不要用 `Start-Process` 或等价命令打开浏览器可执行文件，不要用「操作电脑」或「附属浏览器」去寻找或启动浏览器，不要为打开网址申请提高权限。

豆包工作经常在云端执行，通常不能在用户电脑上打开浏览器。这时采用下面的路径 A，不要依赖「前台一条最长超时的 login、且不结束回合」。

用户点完授权后你应当继续等待或检查状态。

1. 先运行 `muvloom auth status`。确认 `api_url` 对应本次接入的服务，`state: ready` 时直接验证 `muvloom capabilities`，保留已有连接。`state: unreachable` 不是未登录：按安装指南第 5 节重试（最多三次，间隔 5 秒、再 15 秒），不要发起新的授权。
2. 路径 A（无浏览器控制，推荐用于云端宿主）：在回复里告诉用户即将给出授权链接，请在系统默认浏览器中打开并点「授权」。设置 `MUVLOOM_NO_BROWSER=1`，运行 `muvloom auth login --no-wait`，把 `verification_uri_complete` 和 `user_code` 清楚贴到对话里。然后用 `muvloom auth login --timeout N` 等待（使用宿主能接受的较短时长，用户还在授权时可以重复等待）。它会接着同一次登录，不会打开新页面。
3. 路径 B（仅当确实能在用户本机打开浏览器）：先在这一条回复里告诉用户授权页马上在系统默认浏览器打开，点完会自动继续，不需要回复我。**不要结束本回合。** 紧接着前台运行 `muvloom auth login`（命令超时设为宿主允许的最长值），让 CLI 自己打开系统默认浏览器。CLI 打不开时，改走路径 A，把完整链接交给用户。
4. 等待结果：
   - `state: ready`：授权完成，取消 `MUVLOOM_API_URL`，继续第 5 步。
   - `AUTH_PENDING` 或命令被宿主截断：用户还没点完，再等一次，不要新开授权页。
   - `AUTH_DENIED`：用户拒绝了，停止并说明。
   - `AUTH_EXPIRED`：授权码已过期（有效期 20 分钟），这时才重新运行登录，并再次提示用户。
5. 运行 `muvloom auth status` 确认 `ready`，再运行 `muvloom capabilities`，并用 `muvloom images validate --prompt "setup smoke"` 做零花费报价。短暂失败按同样的三次重试策略处理；仍失败就告诉用户稍后重试，保留已有连接。

## 本地写入或清理受限

出现 `operation not permitted`、`permission denied` 或保存凭据失败时，保留并说明真实错误，暂停登录收尾。由用户按宿主的权限提示决定是否允许 CLI 对幕芽配置目录进行必要操作，确认权限后先查 `auth status` 再继续。

权限拒绝、保存失败或命令未完成，只能说明该次状态检查未完成，不能据此断言账号未登录、原连接丢失或授权已过期。

凭据由 CLI 管理。不要手动读取、复制、覆盖或删除凭据文件，不把 token 写入 Skill、提示词或聊天，也不修改全局权限或安全规则来绕过拦截。`auth status` 里若出现 `credential_store: file` 且 `credential_store_issue: unavailable`，只表示当前环境无法使用系统钥匙串、登录改存在配置目录的文件里，不是安装失败。

`AUTH_REQUIRED` 提示码无效或已使用时，先检查现有连接；它不等于码过期。只有 CLI 明确返回 `AUTH_EXPIRED` 才按过期处理。确认本地权限问题已经解决、状态仍未登录后，再向用户说明需要重新授权一次。

## 安装完成条件

技能安装以已启用且新工作任务输入 `/muv`（或 `/` / `@` 搜索）能找到幕芽为准；用户要求账号接入时，还需确认 `auth status` 为 `ready`、`capabilities` 成功，以及零花费的 `images validate` 成功。安装验收不生成图片。完成后回到用户原来的图片任务；仅安装请求则停止。
