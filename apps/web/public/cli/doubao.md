# 在豆包工作中接入幕芽

默认完成 CLI 安装、技能导入和账号连接；不生成图片。

如果用户只要求安装或验收技能，直接执行第 2 节：保留已有 CLI、服务地址和账号，不运行 `auth status`、`auth login` 或 `capabilities`，不访问凭据存储。此时完成条件仅为技能已安装、启用，并且新工作任务中输入 `/muv`（或用 `/` / `@` 搜索 muv、幕芽、muvloom）能找到幕芽。

## 1. 安装 CLI

先运行 `muvloom version`；未安装，或版本低于 0.2.4 时，按 [CLI 安装指南](setup.md) 第 1 节安装（取 `setup.md` 时用与本页相同的地址、只替换文件名，并沿用本页网址里的 `?v=`：它随指南内容变化，能避免读到缓存的旧指南）（安装器原地升级并保留已有登录；已比 0.2.4 更新的版本不要重装，以免降级）。无论 CLI 是否已安装，都先按该指南第 2 节，根据当前豆包工作指南页面的域名为本次登录选择服务（在第一次 `auth status` 之前设置 `MUVLOOM_API_URL`，完成该服务的状态检查和必要登录后再取消，不要写入配置文件）；只有服务一致时才复用已有连接。然后回到本文继续。

## 2. 在对话中安装幕芽技能

由你（豆包工作）完成安装，不要让用户去技能管理页上传 ZIP。先下载本页同源的 [幕芽技能包](muvloom-doubao.zip)。这是幕芽提供的本地技能包，不需要去技能市场搜索同名技能。

再用宿主提供的添加/上传技能能力导入这个 ZIP，或导入解压后的 `muvloom/` 目录（目录内必须有带 YAML `name` 与 `description` 的 `SKILL.md`）。不要把文件写入未经验证的目录（例如 `~/.doubao/skills` 或 `.user_skills`）作为默认安装方式。下载和解压使用当前宿主可用的文件工具或命令：

- 解压前确认只有 `muvloom/` 根目录，拒绝绝对路径、`..` 路径和符号链接；先阅读 `SKILL.md` 和引用的安装说明，再安装。不要执行包内命令来完成安装。
- 已有正确安装的幕芽技能时复用；若已有不同内容，先核对版本和用户改动，不删除其他技能或覆盖无法确认来源的文件。
- 遇到必要的确认时，使用宿主正常的权限提示；不要关闭安全检查、改全局权限或把手动上传当作默认下一步。
- 安装后确认技能已被发现并启用。不能把文件落盘或“新开对话即可加载”当作发现成功。成功标准是：技能已启用，并且新工作任务中输入 `/muv`，或输入 `/` / `@` 后搜索 muv、幕芽、muvloom，能找到幕芽。若仍无候选，保留已安装文件，请用户完整退出并重新打开豆包客户端，再输入 `/muv` 验证。不要重复安装，也不要仅凭磁盘上的文件宣告成功。

CLI 0.2.4 不支持 `muvloom skill install --host doubao`，不要发明这个命令，也不要修改客户端内部数据库或未知配置。只有用户选择「我自己来」时才提供手动路径：插件·技能·伙伴 → 技能 → +添加 → 上传技能。

## 3. 按技能完成账号连接

按包内 `references/doubao.md` 执行账号连接与本地权限错误处理。关键顺序：

1. 前台运行 `muvloom auth status`，已经 `ready` 就保留连接。`unreachable` 是短暂的服务或网络问题，不是未登录：按安装指南第 5 节重试，不要因此发起新的 `auth login` 或再打开授权页。
2. 豆包工作经常在云端执行，通常不能在用户电脑上打开浏览器，也控制不了用户的浏览器。这时走安装指南第 4 节路径 A：设置 `MUVLOOM_NO_BROWSER=1`，运行 `muvloom auth login --no-wait`，把 `verification_uri_complete` 和 `user_code` 清楚贴到对话里，请用户在**系统默认浏览器**中打开并授权，再用 `muvloom auth login --timeout N` 等待。不要用「前台跑一条最长超时的 login、且不结束回合」作为默认办法，宿主超时杀掉命令时这条路很脆。
3. 仅当当前环境确实能在用户本机打开浏览器时，才走路径 B：先在这一条回复里告诉用户「授权页马上在系统默认浏览器打开，你点完授权我会自动继续，不需要回复我」；**不要结束本回合**；紧接着前台执行 `muvloom auth login`，让 CLI 自己打开系统默认浏览器。
4. 授权必须使用系统默认浏览器。用户可能已经在默认浏览器里登录了幕芽。不要指定 Chrome 或任何其他浏览器，不要用 `Start-Process` 或等价命令打开浏览器可执行文件，不要用「操作电脑」或「附属浏览器」去寻找或启动浏览器，不要为打开网址申请提高权限。CLI 打不开浏览器时，把完整授权链接交给用户，在默认浏览器打开。
5. 返回 `AUTH_PENDING` 或被宿主截断时再执行一次 `muvloom auth login`（或路径 A 的 `--timeout` 等待），它会接着同一次登录、不再打开新页面，直到 `ready`、`AUTH_DENIED` 或 `AUTH_EXPIRED`（授权码 20 分钟有效）。
6. 遇到本地写入失败时，暂停并说明必要权限；不要将其说成授权码过期，也不要循环发码。

认证不使用提权去打开网页，不引导用户开启全局完全访问。凭据仍由 CLI 安全存储管理，Agent 不手动操作凭据文件。

## 4. 验收

技能安装必须验证已启用，且新工作任务的 `/muv`（或 `/` / `@` 搜索）候选中能找到幕芽；只存在技能文件不算验收通过。用户还要求连接账号时，再按安装指南第 5 节确认 `muvloom auth status` 返回 `ready`、`muvloom capabilities` 成功，并用 `muvloom images validate --prompt "setup smoke"` 做一次零花费报价（不要出图）。任何一项未完成，就说明当前状态与剩余操作，不能仅凭浏览器显示已授权就宣告成功。短暂的 `TEMPORARILY_UNAVAILABLE` / `unreachable` 要重试三次（间隔 5 秒、再 15 秒）；仍失败就告诉用户稍后重试，并保留已有连接。
