HEIC decoder
============

The web application distributes the browser bundle from **heic-to 1.6.7**
(LGPL-3.0-or-later), at upstream commit
`78345a3fcdb4a1d70d513fce2646aeff0127f7ba`. The bundle contains a statically
compiled JavaScript (asm.js) build of **libheif 1.23.7** (LGPL-3.0-or-later), which
uses **libde265 1.0.16** for HEVC decoding (LGPL-3.0-or-later). The decoder is
used from the `heic-to/csp` entry point in a lazy web worker.

  Dirk Farin.

Rebuild / replacement instructions
----------------------------------

To replace or rebuild the decoder, obtain the three corresponding source
archives above (or checkout the pinned upstream revisions), install Node.js,
esbuild, CMake, and Emscripten, and follow `esbuild.mjs` in the heic-to source
archive. Build libheif with its HEVC decoder dependency and reproduce the
Emscripten settings used upstream:

    LIBDE265_VERSION=1.0.16 USE_WASM=0 \
      ../build-emscripten.sh ..

For a Content Security Policy compatible build, also set
`USE_UNSAFE_EVAL=0`. The heic-to build script then bundles the generated
libheif module into its `csp` output. The generated replacement must preserve
the corresponding source and license notices above, update the pinned versions,
commit, and archive checksums here, and remain a separately replaceable worker
bundle; do not overwrite this notice with a minified bundle's license header.

The archives include the upstream build scripts and source needed to reproduce
the generated JavaScript. libheif and libde265 also contain sample
applications under MIT terms; those samples are not part of the shipped
decoder, but their notices remain in each complete upstream source archive.
