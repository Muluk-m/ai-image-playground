# 场景替换

> 示例级内容，尚未经过真实产出验证。

一件事：**主体一个像素都不动，背景整个换掉**。所有的写法、所有的验收都围着这句话。

## 直接干活

用户指着一张图说「换个背景」，意图只有一种合理解读，**不要先问一轮**。
直接 `editImage`：

- `imageIds` 第一项是要换背景的那张图。产出会落在它旁边，源图不动。
- `n` 保持 1；用户要「多几个场景挑」时，**不同场景分别调用**，同一个场景的多版才用 `n`。

用户说「每张」「全部」「这几张都」要换背景时，每张照片都是独立目标：逐张调用 `editImage`，每次 `imageIds` 只填当前照片；其它待处理照片不能自动变成参考图。只有用户明确指定另一张图作为场景、材质或构图参考时，才把它放在目标图后面。

用户提到某张素材却没在输入框里引用它，先 `readLibrary` 按名字查到图片 id 再用。

只有目标范围或场景方向确有歧义才问：用户引用了多张图却没说明处理哪一张（明确说「全部」「每张」就已说明），或者「换个好看点的背景」在这件商品上有两种以上差很远的走法（纯色棚拍 vs 真实使用场景）。那就调澄清工具，给 2-4 个**具体的场景方案**让他单选，别问开放式问题。

## prompt 怎么写

按这三段写，顺序不要乱：

1. **新场景**：环境、材质、陈设、景深。一句话写具体——「浅色橡木桌面，背后是虚化的
   落地窗与米色窗帘，清晨侧光」，不要写「好看的背景」。
2. **光线对齐**：新背景的光线方向、色温、强度要与主体身上原有的光影一致。
   这是这类图最容易穿帮的地方，必须显式写出来。
3. **保留清单**：主体的外形、颜色、材质、logo、包装文字、角度、在画面里的位置与大小
   一概不变；不要给主体补画阴影以外的任何新元素。

再加一句：画面里不要出现任何文字、水印或额外商品。

## 用选区精确圈定

用户在图上画了选区，就必须带 `selectionBindings`：逐项把这张图的图片 id 与选区 id 抄进去，
`prompt` 写成简短的任务摘要。**选区是编辑边界**：圈住背景就只改背景，圈里没被覆盖到的
东西不算在内。选区不足以覆盖要换的范围时，先请用户调整选区，不要自己往外扩。

## 常见翻车与对策

| 现象 | 对策 |
| --- | --- |
| 主体被顺手「美化」了（换了颜色、改了 logo、重写了包装字） | 保留清单写得更细，逐项点名；重出而不是在错的那张上继续改 |
| 主体像贴上去的 | prompt 里补一句「主体与新背景共享同一光源方向，地面接触处有自然投影」 |
| 背景抢戏 | 补一句「背景虚化、低对比、不要出现醒目图案与文字」 |
| 主体位置被挪动 | 补一句「主体在画面中的位置、大小与角度完全不变」 |

出来不对时**回到原图重出**，不要在错的产出上接着改——错误会一层层叠下去。

## 换季 / 换节日氛围

同样一次 `editImage`，把新场景那一句换成节令描述（圣诞、春节、夏日海边），
其余两段照旧。**不要让模型往画面里加节日文案与促销字**，写死「不出现任何文字」。

## 交付

生成完说清三件事：换成了什么场景、这一批是几次生图、
要他确认主体有没有被改动（颜色、logo、包装文字是重点）。
再给 1-2 个具体的下一步：换另一个场景出一版 / 按这张做成主图 / 让它动起来。
工具成功只代表出了候选，不代表主体真的没被动过——这一条必须由人眼确认。
