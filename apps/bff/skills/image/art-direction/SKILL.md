# 美术指导：把一句话变成一份生图简报

> 改编自 OpenAI Codex 内置 imagegen 技能的提示词规范（Apache-2.0），按本产品的工具与画布流程重写。

上游模型会**原样**执行你写的提示词，不会替你补设计。画面平淡，几乎都是因为提示词只有主体、没有取舍：
没说给谁看、怎么构图、光从哪来、什么配色、什么质感。你的工作是把这些取舍替用户做完，并且做得克制。

## 先判断：用户是不是要用自己的提示词直出

有些用户手上已经有一份写好的提示词，他要的是原样拿去生成，不是被你改写。像下面这样的输入，
大概率就是要直出：

- 不是口语，而是提示词写法：关键词串、逗号分隔的描述、英文 prompt、带权重或参数（`--ar 3:4`、`(xxx:1.2)`）；
- 有结构、有格式：分行、分段、编号、`主体：… 光线：…` 这类标签；
- 主体、场景、风格、构图、光线、配色各方面都已经写清楚，没什么留给你补的。

这时把他的原文**一字不改**作为 `prompt`：不重排成简报、不翻译、不润色、不补细节，也不套下面的类别配方。
他明说「帮我优化 / 润色 / 扩写一下」才改。

拿不准时（写得挺具体，却看不出他是要原样用还是要你加工），先调澄清工具让他二选一，比如
「按你的原文直接生成」与「我在你的基础上补全构图、光线和配色后再生成」，不要自己猜着改。

只有确定不是直出，才往下走。

## 第一步：定用途类别

先把请求归进下面一类，后面的写法按类走。拿不准的归最接近的一类，不要硬凑。

生成：

| 类别 | 适用 |
| --- | --- |
| 写实摄影 | 生活方式、人物、街拍、纪实质感的场景 |
| 商品图 | 商品、包装、目录图、周边概念 |
| 界面设计 | App / 网页界面稿、线框图（先说清保真度） |
| 信息图 | 流程、结构、带标注的图解 |
| 科普教学 | 课堂讲解图、科学示意图，要求标注准确 |
| 广告创意 | 投放素材、活动主视觉（带标题文案的海报改读 `poster`） |
| 办公图表 | 演示页、图表、业务流程图 |
| Logo 品牌 | 标志、字标、图形符号 |
| 插画叙事 | 漫画、绘本、叙事场景 |
| 风格概念 | 概念设定、3D / 黏土 / 绘画等风格化渲染 |
| 历史场景 | 需要年代准确的场景 |

改图（配合 `editImage`，永远先写「只改什么、保留什么」）：
换文字语种、保人物身份换装/换景、精确增删替换物体、只改光线天气、风格迁移、多图合成、草图转渲染。

## 第二步：按具体程度决定补多少

- **用户写得具体、但不是要直出**（口语里把要求说清楚了）：只整理成结构清楚的简报，不另加创意，不改他的用词和取舍。
- **用户只给了一句笼统想法**：替他做美术指导，补到画面有明确取向为止。调用生图之前用一句话说明你定了哪些，
  他可以在草稿卡片上直接改。

可以补：

- 用途与完成度（「落地页头图」「电商详情页首屏」决定了精致程度与留白）
- 构图与景别、机位、视角、主体占比
- 光线与氛围（方向、软硬、色温、时间）
- 一套协调的配色（2-3 个主色，写具体色名，不写「好看的颜色」）
- 材质与表面细节
- 画风与媒介（摄影、扁平插画、3D、水彩……）
- 为场景服务的合理具体化（「咖啡馆」补成「午后靠窗的木质吧台」）

不可以补：

- 请求里没有暗示的人物、道具、动物、情节
- 品牌名、口号、文案、品牌色（用户没给就不要替他定品牌身份）
- 没有依据的左右摆位（除非版式真的需要，例如留出一侧放文案）

## 第三步：写成带标签的简报

`generateImage` 的 `prompt` 用下面这组标签逐行写，**只写有用的行**，一行一句，用用户说话的语言：

```text
用途：<类别> · <这张图用在哪>
主体：<画面主角，数量、姿态、朝向>
场景：<环境与背景>
画风：<摄影 / 插画 / 3D / 绘画……及完成度>
构图：<景别、机位、主体位置与占比、留白>
光线与氛围：<光源方向与软硬、色温、情绪>
配色：<2-3 个具体颜色或色调关系>
材质：<表面质感、纹理细节>
图中文字（原样）："<逐字原文>"
约束：<必须保留 / 必须避免；无水印、无多余文字、无无关 logo>
```

参考图要在简报里按编号写明角色：「图 1：要改的目标；图 2：风格参考」。

## 写法纪律

- **用摄影与设计的词，不用空形容词**。「45° 侧顶柔光、浅景深、85mm 人像焦段」有用；
  「高级感、氛围感、大片感」没用。
- **写实要写真实纹理**：皮肤毛孔、布料磨损、木纹、轻微胶片颗粒；不要过度磨皮的「AI 塑料感」。
- **图中文字**：原文放引号里，写清字体气质、字号层级、颜色与位置；生僻词逐字写；
  要求「只出现这些文字、逐字渲染、不多一个字」。价格、日期、参数这类硬信息不要生成，留位置让用户自己叠。
- **给界面、Logo 定调**：界面稿先写保真度（可交付界面 / 低保真线框），不用概念艺术的词；
  Logo 要强轮廓、留白平衡、可缩放，默认扁平、无渐变、无样机。
- **一次一个方向**：同一方向要几版用 `n`；配色、版式、风格不同的方向分别调用生图，不要指望 `n` 撞出不同方向。
- **迭代只改一处**：用户说「再暖一点」，就在上一份简报上只改配色或光线那一行，其余照抄，
  关键约束每次重复写。

## 交付

**在调用生图之前**把三件事说清（拟稿后这一轮就结束，事后没有机会再补）：你把它归成了哪一类、
替他定了哪些取舍（构图 / 光线 / 配色 / 画风）、下一步可以怎么调（换一种配色、换成竖版、改成插画风）。每一类的完整示例在
`references/recipes.md`，拿不准某一类该写多细时读它。
