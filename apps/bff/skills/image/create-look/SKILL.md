# 建模板

模板是「给素材就出这样的图」的一份说明书：**它的形态就是一份技能**——分节正文加钉死的模型、尺寸与素材位。
这条技能管的是把用户看中的那种效果变成这样一条模板，不是出一张图交差。

## 流程

### 1. 先读反推那一条

动手之前调 `loadSkill` 读 `reverse-prompt`，按它的六件事拆用户贴的参考图。
**不要凭一眼印象直接写正文**：写出来的会是一段形容词，换个商品就复现不了。

用户没贴参考图，只用嘴描述（「我想要那种冷冷的水泥风」）时，先问他要一张参考图或一张他满意的旧图。
一张都拿不到就照他的描述写，并在保存卡片上说清这一版没有参考图、效果要试过才算数。

### 2. 写出模板正文

按 `reverse-prompt` 的七节写，一节都不许少：一句话目标 / 适用场景 / 需要用户提供的输入 / 工作流程 /
输出要求 / 约束与禁忌 / 示例。

第 3 节是**素材位**：写清这条模板要几条素材、各派什么用场。
参考图里有两个主体（模特 + 商品）就是两个素材位，不要写成一个。

### 3. 让用户改

正文写完先贴给用户看，请他改。他知道这件商品哪里不能动、哪个词是行话，你不知道。
他说「就这样」再往下走。

### 4. 存成模板

调 `saveLook`，一次交出这些：

- `name`：短，用户一眼认得出效果（「岩壁大理石」「暖调琥珀」）。
- `description`：一句话，说清给什么素材出什么图。它会进这个用户每一轮的技能清单，写长了白花 token。
- `purpose`：`hero` 主图 / `poster` 海报 / `scene` 场景图 / `detail` 详情图。
- `body`：七节正文。
- `model` 与 `size`：钉死。模型从这个部署出得了图的清单里挑，挑不在清单里的模型这条模板出不了图。
  拿不准就用这一轮正在用的那个模型与比例。
- `slotCount`：素材位数量，与第 3 节写的一致。
- `referenceImageIds`：用户贴的参考图。
- `coverImageId`：**第一次保存时留空**，用参考图顶着；等试出满意的产物再回来补。

`saveLook` 只是把卡片发给用户，**不是保存**。用户改完名字按下保存才落库，落库之后系统会告诉你。
手上没有存模板这个工具时，别绕路：告诉用户模板要登录并打开同步才存得下，正文先贴给他留着。

### 5. 主动提议试效果

用户保存完，**主动问他要不要拿一条素材试一张**，不要等他想起来。这一步才是模板值不值钱的判据。

试的时候用 `editImage`：`imageIds` 第一项是素材的视角图（优先拼图，没有拼图用正面），
后面跟这条模板的参考图；**一次最多 4 张**，超了就砍掉次要的参考图，别砍素材。
提示词照正文第 4 节写。

出来的图和用户一起看：

- 不满意 → **回到素材与参考图重出**，不要在产物上接着改（在产物上改会越改越远，主体也会被改画）。
  连着两次都不对就回去改正文，改的是哪一句要说出来。
- 满意 → 再调一次 `saveLook`，这次**带上第一次拿到的那个 `id`**，把 `coverImageId` 换成这张产物。
  带 id 是更新同一条模板，不带 id 会多出一条一模一样的。

## 澄清与边界

- **素材数与素材位不符**：用户拿两条素材去试一个素材位的模板，先问他是哪一条上、还是要把模板改成两个素材位。
  不要自己挑一条。
- **参考图不止一种效果**：用户一次贴了四张风格各异的图，先问他要做几条模板。一条模板只讲一种效果。
- **用户要的其实是一张图**：他只想现在出一张，不想存下来，就别走这条技能，直接按普通出图做。
- 不要在模板正文里写死某一件具体商品（「白色鹅蛋形浴缸」）：模板是给素材用的，写死了就只剩这一件能用。
