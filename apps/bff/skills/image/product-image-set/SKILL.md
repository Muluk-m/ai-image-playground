# 产品套图

> 示例级内容，尚未经过真实投放数据验证；与用户提供的平台规范冲突时一律听平台规范。

套图不是「同一张图的十个版本」，而是**一套各有分工的图**：每一张都有自己的类型名和要回答的问题。
交付时必须把类型名写出来，用户才知道哪张放详情页第几屏。

## 第一步：需求模糊时，先给设计方向，不要问开放式问题

用户只说了「做一套详情页」「拓展产品卖点，精致一些」这种话时，他不是不知道要什么，
而是**说不出来**。这时不要反问「你想要什么风格」，而是调澄清工具给 **2-4 套具体的设计方向**，
每套用一句话写清定位与会产出什么，例如：

- 「高端质感路线：深色背景 + 硬光打亮材质，突出做工与用料」
- 「生活场景路线：真实家居环境里的使用瞬间，突出好用」
- 「参数对比路线：白底 + 数据与结构标注，突出硬指标」

推荐项放第一个。界面自带「其他」，不要自己占一个选项写「都不是」。

**需求本来就清楚时跳过这一步**（用户给了参考图、指定了风格、或明说由你定）：直接进第二步，
并在回复里说明你替他定了哪个方向。

## 第二步：把这几件替他定下来

1. **商品本身** —— 用户引用了实拍图吗？没有就 `readLibrary` 按商品名查素材库。
   **有实拍图一律 `editImage`，不要 `generateImage`**：套图里的每一张都必须是同一件真商品。
   **用户本轮请求指向一件真实在售商品时**，素材库也没有才问他要实拍图——这是唯一你补不了的一件。
   主体是虚构或创意形象（吉祥物、插画角色、概念品）就不要问，直接 `generateImage` 画。
2. **平台与语言** —— 淘宝 / 天猫 / 京东 / 拼多多 / 1688 / 小红书 / 抖音 → 中文简体；
   Amazon / Temu / Shopee / TikTok Shop / AliExpress 等跨境平台 → 英文。
   用户明确指定语种就听他的。**他没提平台就按中文简体做，不要为此发问**，回复里说一句即可。
3. **张数与类型** —— 用户说了张数就照他说的；没说就出 6 张。常见的整套规格是 5 / 10 / 15 张。
4. **画幅** —— 用户没说就整套统一用一个比例（详情页常见 4:3 或 3:4，主图位用正方形），
   一套里不要混着来。

## 第三步：一套带类型的图

**每一张单独调一次 `editImage`，`n` 保持 1。** 不同类型是不同的画面，不是同一画面的多版本；
用 `n` 一次出多张只会得到一堆同质的图。用户要「这一张多给我两版挑」时才用 `n`。

类型词表（按需取，不必全上）：

| 类型 | 这张图回答什么 |
| --- | --- |
| 主宣传图 | 这是什么、值不值得往下看 |
| 卖点图 | 最强的那一条卖点，一张一条，不要堆 |
| 细节图 | 做工、材质、接缝、纹理，近摄 |
| 功能展示图 | 某个功能怎么运作 |
| 使用场景图 | 谁在什么场合下用它 |
| 参数图 | 尺寸、容量、规格这类硬数字 |
| 对比图 | 和旧款 / 常规做法的差别 |
| 包装配件图 | 开箱里有什么 |

一套 6 张的默认配比：主宣传图 1、卖点图 2、细节图 1、使用场景图 1、参数图 1。

每张的 `prompt` 各写一句：**主题**（这张要说什么）、**卖点**（要突出的那一条）、
**风格氛围**（整套统一，逐张重复同一句，不然会漂）、**视觉元素**（这张画面里该有什么）。
另外每张都要写死一条：保留商品的颜色、材质、logo、包装文字与型号标识，一个字都不许改。

## 图上的文字

**默认不生成文字。** 模型写的中文字会糊、会错、会写出商品没有的承诺。
用户明确要文案时，每张只放一句短的（不超过 8 个字）放在留白处，交付时提醒他人工核对。
参数图里的数字尤其危险：要么不写，要么让用户把真数字给你。

## 第四步：交付时说清楚，并给下一步

一次说完这四件：

1. 这一套是几张、分别是什么类型（逐张点名）
2. 你替他定了什么：平台、语言、画幅、设计方向
3. 这一批一共是几次生图
4. 哪里要人工核对：商品细节有没有被改动、文字与参数对不对

最后给 **2-3 个具体的下一步建议**，每条是一个他点头就能直接做的动作，例如
「把使用场景图换成夜间氛围再出一版」「按这套风格补 4 张凑满 10 张」
「挑一张做成主图视频」。不要写成开放式的「还需要什么吗」。

## 中途别停也别催

整套跑完再收尾，**不要出了三张就停下来等用户说「继续」**。
用户中途喊停就停，剩下的不要自作主张跑完。
