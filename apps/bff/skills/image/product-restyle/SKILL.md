# 商品换款

> 示例级内容，尚未经过真实产出验证。

一张已经拍好的图，**场景和光影是资产**：布景、机位、打光、投影都不该重来一遍。
要换的只是画面中间那件东西——换成另一件商品，或者换个颜色 / 材质 / 款式。

## 先分清是哪一种

| 用户在说 | 走哪条 |
| --- | --- |
| 「把这里的杯子换成我的保温杯」 | **换主体**：要有目标商品图 |
| 「这款出个黑色的」「换成哑光质感」 | **换颜色 / 材质**：只要原图 |
| 「换成长款的那个版本」 | **换款式**：能给目标图就给，给不了按描述改 |

分不清、或者用户同时说了好几件事时，先按最主要的那件做，在回复里说明你怎么理解的。
只有「换成什么」本身有两种以上差很远的解读时，才调澄清工具给 2-4 个具体选项。

## 换主体

`editImage`：

- `imageIds` 第一项是**原图**（要改的那张，产出落在它旁边）；后面依次放目标商品的图，
  最多再放三张。同一件商品的多角度图一起给，模型还原细节会准得多。
- 用户提到某件商品却没引用它的图，先 `readLibrary` 按名字查图片 id。
- `n` 保持 1。要多版挑再用 `n`；换成不同商品是不同方案，分别调用。

`prompt` 三句：

1. **换什么**：把画面中央的 X 替换为参考图里的 Y。
2. **保留什么**：背景、桌面、道具、构图、机位、光源方向、投影与反光一概不变；
   新商品在画面里的位置、大小、朝向与原商品一致。
3. **还原什么**：新商品的颜色、材质、比例、logo 与包装文字按参考图原样还原，不许美化、不许改写。

第 3 句是这类图最容易翻车的地方：模型很爱把 logo 画成「差不多的样子」、把包装文字重写一遍。

## 换颜色 / 材质

只要原图，`imageIds` 只填它一张。`prompt` 两句：

1. **改什么**：把商品主体改成某某颜色 / 某某材质，写具体（「哑光雾霾蓝」比「蓝色」好）。
2. **不改什么**：逐项点名——金属扣件、logo、包装文字、商标、背景、光影、材质质感里
   不该变的部分。

守则：**只改颜色就不要顺手改材质，只改材质就不要顺手改款式。** 用户想连主体一起换，
那是上一节；想换背景，那是 `scene-swap`。

## 用选区精确圈定

用户在图上圈了要改的部分，就必须带 `selectionBindings`，逐项抄上图片 id 与选区 id，
`prompt` 写成简短的任务摘要。选区是**编辑边界**，圈里没要求改的东西（文字、背景）照样要保留。
选区框不住要改的对象时，先请用户调整选区，不要自己往外扩。
参考图上的选区表示「参考这一块」，不是「改这一块」。

## 出来不对怎么办

- **颜色不对**：改 prompt 里的颜色描述再来一次，`imageIds` 仍从原图出发。
- **细节被改坏了**（logo、文字、扣件）：把保留清单写得更细、逐项点名，**回到原图重出**。
- **连背景一起变了**：prompt 里补一句「背景、构图与光影与原图完全一致」，重出。

**永远从原图重出，不要在错的产出上继续改。** 错误会一层层叠下去，越改越远。

## 交付

说清三件事：换了什么、保留了什么、这一批是几次生图。
然后点名要他人工确认的地方：logo、包装文字、材质质感、投影方向。
再给 1-2 个具体的下一步：再出一个配色 / 换个场景 / 按这张做主图。
