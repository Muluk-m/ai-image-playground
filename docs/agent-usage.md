# 智能体调用用量

每次模型调用保存到 `agent_model_calls`，持久更新成功后累加独立的调用数与 token 计数。一轮对话的结算读取这些标量，不再遍历运行时消息，也不在收尾新增数据库查询。模型工作集被替换、旧消息被移出后，已经记录的调用次数与用量仍然属于原轮。此变更不启用自动换窗或进程恢复。

## 记录边界

- 每次逻辑对话调用先生成调用 ID 并落库，`http_dispatch_count = 0`；最终请求体通过检查、调用底层 fetch 前持久写入派发数与 `request_bytes`。完成时仅允许将 `in_progress` 更新一次。主模型显式关闭 SDK 自动重试，每条记录最多派发一次。transport 收到 HTTP 429/503、错误明确为过载且尚无任何输出时，应用最多退避重试两次，每次先完成失败记录、再创建独立调用记录；上游未报用量仍记为未知，不推断免费。退避中取消或失败不继承已结算尝试的用量。断流、超时或已有文字、推理、工具输出不自动重试；网络异常即使带 overloaded 文案也不重试。旧记录的派发数为 `null`，表示当时没有记录该事实。持久边界记录派发意图，不承诺上游受理；进程在记录与网络调用之间退出仍需核查。
- 记录绑定会话、轮、执行时的用户或设备身份，并随会话生命周期保留。访问控制仍由已有会话接口执行；不新增可凭调用 ID 直接读取记录的接口。
- `conversation` 是对话调用；`compaction` 是平台承担的摘要调用，包含无效 JSON 导致的每一次重试。`handoff` 为后续窗口交接的成本归属预留，本次没有交接调用。
- 对话记录保存实际模型、图片输入块数量、返回的工具调用 ID 与名称、开始/结束时间、状态及用量。不保存提示词、图片字节或回复正文。
- 本地字节检查拒绝保存 `local_rejection`、零派发与明确零用量；不得把它归为上游未知成本。`usage = null` 明确表示上游用量未知。pi 在流式上游缺失用量时提供占位零，因此全零不能证明调用没有消耗。非流式摘要只有在上游明确报告合法的输入/输出 token 数时才保存用量。
- 取消发生在派发记账期间时，底层请求不发送，派发数回退为零并保存明确零用量。SDK 提前结束取消流不代表记账完成：回合结算与 `turnEnd` 必须等待派发及取消回退落库；该等待不包含上游响应体。
- 对话的输入 token 延续现有 pi 口径，缓存读取/写入 token 另存；摘要保存上游报告的 prompt/completion token。不能将缓存计数再次加到摘要的 prompt token 上。

## 结算与运营观测

起轮前的预扣按「估算输入 + 预留输出」定额。估算覆盖这一轮真会发出去的整份输入：系统提示词、历史回放、本轮提示词与视觉证据清单（没有引用就没有清单），以及每次请求都随请求带上的整份工具声明（名称、说明、参数 schema），图片按块的固定值折算，封顶取上下文压缩阈值。压缩过的会话还要算上那份摘要：折进去的原文已经不在历史里，可摘要本身每一轮都发出去，漏掉它会一路少扣。它在 pi 的字符数启发式之上对 CJK 字符做校正：pi 一律按「字符数 / 4」算，而中日韩文字与全角标点在主流词表里约一个字符一个 token，不校正会把中文输入低估约 4 倍。校正后与上游真实分词仍有出入，只保证同量级、略偏保守；上下文压缩量历史用的是同一口径，所以两处不会各说各的。结算仍以上游报告的实际用量为准，预扣多出的部分退回。

出站前还有一道硬闸：把系统提示词、工具声明与每一条消息按同一口径量这一份请求，超过压缩阈值就**拒发**，轮以 `agent_context_overflow` 收场，页脚显示「这一轮的内容太长，没有发出去」。拒发而不是照发，是因为摘要失败的那一刻历史正是最长的那一份，回退成「发完整历史」只会更超——那是一个更贵、更慢、必然被上游拒掉的请求。判「该不该压缩」用的是另一个口径（锚在上游报回来的真实用量上），两者取大的，触发判据永远不会比这道闸松。估算与上游实际用量的偏差每轮记在 `agent.input_estimate_deviation`。

最终出站还有独立字节闸门：主模型在 SDK 序列化后的 fetch 边界计量 UTF-8 请求体，独立摘要在其 transport 边界用同一检查。中文、emoji、base64、工具与供应商包装都计入；无法安全计量的流式或 multipart body 直接拒发。摘要原有重试保留，每次派发重新经过检查；本地拒绝不重试、不降级继续发送主模型。每个逻辑调用独立记录原因，SDK 包装错误不改变 `agent_request_budget_exceeded` 归因，诊断仅包含大小、上限及原因，不保存请求内容或凭证。

字节上限由运营配置 `quotas["agent:request-max-bytes"]` 统一提供，默认 16 MiB 是应用内存与传输保护值，**不是供应商保证**。上线前应核对所用网关的实际限制，必要时收紧；0 或无效值拒发，不能用 0 关闭闸门。token 预算仍独立保留，两者必须同时满足。

用户收费规则保持不变：一轮只结算自己的对话调用，图片和视频工具任务各自预扣、结算或退回。摘要不计入用户轮用量。对话全无已报告用量时沿用预留额结算；混合有报告与缺失报告的调用仍沿用原有已知用量合计，未知部分可从调用记录识别，不能在运营报表中把这个合计称作完整实际成本。

## 对话模式与出图模式

本机没有记下过这个选择时，输入框里的「直接出图」是打开的，起轮会带上 `autoSubmit: true`。
用户在同一台设备上关掉之后，才回到**对话模式**（只存在这台设备，不随账号同步）：图片生成、改图与视频生成先保存完整生成草稿，工具返回 `awaiting_confirmation`
时不创建生成任务、不预扣生成积分，也不预留画布位置。用户在卡片中编辑提示词并点击「确认生成」才
提交；发送消息、拟稿或聊天中的一句同意不能替代该按钮。确认接口使用用户最后提交的提示词，不再交给
模型改写。对话拟稿按本轮模型用量正常结算，不能把「未扣生成积分」解释成对话免费。
服务端仍把缺席的 `autoSubmit` 当成对话模式；默认打开只发生在这个客户端偏好上。

同一张草稿卡重复确认只产生一条任务及一笔生成占用；余额不足等拒绝保留待确认状态，允许修正后再确认。
后续复核与历史回放应使用已确认的提示词，局部编辑的输入图与遮罩范围仍保持拟稿时冻结的材料。
界面另有「全部确认」，逐张调同一个确认接口，一张被拒即停；它不是新的提交路径，幂等与计费不变。

用户可以在输入框上切到**出图模式**（起轮参数 `autoSubmit`，本机偏好，不随账号同步）。这一模式下
生成工具拟好提示词即当场提交，卡片直接是 `submitted`，预扣与结算仍发生在建任务那一处，口径与确认
路径逐字相同；差别只有三件：材料不再落 `agent_generation_drafts`、用户没有逐张编辑提示词的机会、
以及这一轮不因「拟过稿」而收尾，模型可以连着提交多次。

出图模式下一轮最多自动提交 `AGENT_AUTO_SUBMIT_MAX_PER_TURN` 次。额度用尽、余额不足或配额用尽时
该次调用**退回待确认草稿**，不报错、不中断整轮：用户仍然看得见那份稿，处理完照常点确认。
系统提示词里生成流程那一句按模式切换，生成工具自身的说明不重复这条契约——同一条契约写在两处，
出图模式一开就会有一处说错。

### 节点画布：阶段授权

节点画布用阶段授权替代每轮 `autoSubmit` 额度；即使旧客户端仍发送出图模式参数，也不会自动提交或消耗该额度。
`runNodes` 创建待确认提案，记录阶段和明确的节点范围（分组在提案时展开）。预算上限由服务端按节点的模型、数量和倍率报价，模型填写的 `estimatedCredits` 不决定上限；算不出价就拒绝提案，不用 0 代替。有提示词的素材节点按普通出图报价并进入授权；没有提示词、只靠连线输入的素材不进入授权。
对话卡显示这些信息及已用额度；用户确认后，只有发起提案的标签页保有一次性的内存执行凭证，
用户本轮请求里的直接出图偏好决定是否立刻开跑：缺省或 `autoSubmit: true` 时登记授权后由原标签页立即运行，不弹确认卡，也不留 5 秒撤销；只有显式 `autoSubmit: false` 才弹出确认卡，确认后先留 5 秒撤销窗口再运行。模型工具参数不能改这个偏好。刷新、历史重放及其他设备不恢复凭证，也不自动开跑。没有 `direct` 标记的历史 `canvasRun` 只展示。

BFF `GET /api/agent/stage-authorizations/:id` 返回所属会话/项目、范围、预算、已用额度、状态
（`pending` / `active` / `exhausted` / `ended` / `expired`）及按时间追加的审计、节点尝试与实际任务 ID。
确认后超过 30 分钟仍是 `active`、且没有排队或执行中的任务时，读取或定期回收会把它标成 `expired`。定期回收在查询时就排除仍有在途任务的授权，不会先取一批再丢掉，因此空闲授权不会被更老的在途授权饿死。
`confirm` 原子激活且不能重复领取执行凭证。提案时算出的模型、数量和倍率是唯一执行规格，并写进提案快照。确认带上的规格必须与快照一致（数量先做同一次向上取整）；模型或数量已经变了返回 `stage_authorization_stale`，不在确认时改价。节点不能重复，重复的 `nodeId` 会被拒绝。原标签页若发现工作台规格和快照不同，会提示重新提案，而不是拿新规格去确认。之后的 `preflight` 必须与这条报价一致。`preflight` 按服务端单价核算并预留阶段预算，不创建任务、不扣账户积分。图片和视频的报价都走画布执行用的同一套解析：图片用原标签页工作台出图模型，而不是对话模型；不计费且提案时没有可用模型时，不拿空字符串挡预检，第一次预检会写入原标签页实际使用的模型并随后锁住。视频草稿要四项齐全才采用，否则整份退回本轮工作台视频参数。再按节点的视频模式把清晰度封到该模式的上限，并退到模型支持矩阵里的合法档；没有支持矩阵时时长向上取整，未知分辨率的倍率与任务结算相同（没有单独倍率时为 1）。确认、预检、结算记账和任务计价用同一次向上取整。生成参数保留提交时的时长；不在模型支持列表里的时长直接拒绝，不会被改写成向上取整后的档位。结算拒绝负数花费，以及非正的数量或倍率。
实际队列提交再次校验身份、执行凭证、节点、模型、数量、倍率、预算，以及提案时从画布冻结的提示词、输入张数和媒体类型。对不上就拒绝，普通 `/submit` 不能只凭执行凭证跑任意内容。凭证不覆盖图片字节本身。浏览器里尚未写入画布的临时上传不在冻结快照里，阶段提交会在发出请求前拒绝，不会拿令牌去跑这批本地图。图片按节点或 fileId 计数，和实际提交的张数一致；视频按首帧、尾帧和参考图的槽位计数。授权额度与真实任务、计费预扣在同一事务写入；幂等身份包含授权、尝试和节点，同一命令换一套授权不会重放成旧任务。同一提案键若计费规格、节点或快照变了，返回冲突而不是第一次的授权。
已经提交过任务的节点不能在同一授权里再开一次；取消或失败发生在提交之前时，空的预留会被换掉。已经提交过的节点要重跑，就再提一次新的阶段授权。`end` 关闭后续提交，已受理任务照常完成。登出时服务端在一个事务里结束该用户仍待确认或仍活跃的授权；账号已被禁用但会话还没过期也会收回。回收失败仍会撤销这次会话。
预留但尚未提交的额度不计入已用；已用额度是本阶段累计提交占用，失败退费不恢复授权额度，避免借退费无限重复运行，
账户实扣仍以任务结算与私有流水为准。缺单价、范围外、预算不足、已用尽或已结束都必须重新提案。

回复必须以节点名称指代范围：提案只能说「待确认」，查询到授权的真实 `taskIds` 才能说「已提交」；
提交不代表完成，结果仍须读取画布核实。可用 `runNodes` 的 `authorizationId` 查询真实状态，不产生第二次执行；只带授权 id 即可，不必再带 `nodeIds`。

数据库迁移 `0074_agent_stage_authorizations` 的回退脚本只允许清理空表；已有提案（包括已结束的授权）
必须保留范围、预算与花费审计，回退会明确拒绝丢弃这些记录。回退应用版本不要求删除这张兼容表。


运营可以按会话、轮和模型分组查看调用记录，并通过以下既有关系核对工具成本：

- 调用记录中的工具 ID，对应消息中工具结果块的 `toolCallId`。
- 工具结果中的产物带有 `taskId`；任务也通过 `agent_conversation_id`、`agent_turn_id` 归属该轮。
- 图片/视频真实消耗仍来自任务结算与积分流水；不要将生成模型请求的 token 加进对话任务再收费。

图片块数量只表明视觉输入参与了哪次调用，不代表可从上游总 token 中准确拆出视觉 token。当前网关没有提供可靠货币成本时，不将 SDK 的默认零单价换算结果当作真实零成本；保留用量和模型用于对账。读取相关推理可关联 `readLibrary` 等工具调用，未提供独立用量的步骤不虚构成本分摊。

## 持久性与范围

对话调用在派发前已有独立记录。若进程在完成记录前丢失，记录保持 `in_progress`、用量未知；该行是后续恢复核对的依据，不表示可以重发操作。摘要记录在每次请求返回、失败或本地拒绝后保存；尚未返回且进程丢失的摘要调用不承诺恢复用量。当前计数器仅服务本次进程中的一轮；后续恢复须从持久记录重建计数。检查点调度、外部任务去重恢复和费用额度控制属于后续任务。

新增迁移 `0017_agent_model_calls`。发布仍需先执行现有数据库迁移流程；回退脚本仅用于丢弃新建空部署，不用于线上清理用量数据。

## 验证

以现有 HTTP/SSE、计费回调及持久化状态为主接缝。第三方运行时边界的故障注入模拟完成通知重复和工作消息淘汰，模型与工具循环仍经过真实服务入口。另覆盖摘要重试/失败、历史隔离、用户/设备归属、图片输入、无积分部署和正常/失败/取消结算。
