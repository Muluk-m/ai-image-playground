# 服务端日志系统

Admin 侧栏「运维 → 服务端日志」进入独立 `/logs` 页面，内容是部署里每个容器的运行输出（stdout / stderr）：BFF、worker、Admin、发布路由、cloudflared、宿主机采集、备份与迁移，包括用户 API 的请求结果。每条记录带服务、实例、构建版本、级别、事件、消息和结构化字段；请求上下文里的 `requestId` 自动关联，带 `taskId` 的业务事件可以定位到任务。

## 使用

- 默认显示近 24 小时，按服务、日志级别、近 15 分钟 / 1 小时 / 24 小时 / 7 天或自定义时间范围查询。自定义范围最多 7 天，输入和展示统一使用北京时间。
- 关键词按字面匹配消息、事件、请求 ID、任务 ID 和结构化字段；请求、任务、用户、图片、实例、版本采用精确匹配。用户与图片定位分别读取结构化字段 `userId` 和 `mediaId`，旧日志缺少这些字段时可按请求或关键词查询。
- 页面显示整个日志库实际留存的首末时间；查询包含留存起点之前的时段时明确提示此前可能尚未采集或已清理。无匹配记录不能说明此前没有故障。
- 筛选保存在 URL 中；「复制查询链接」冻结当前查询的开始和结束时间，重新打开后恢复相同范围和筛选，仍需 Admin 登录。
- 级别按钮显示当前查询中各级别数量（不受已选级别影响），总量、错误数、警告数、趋势和前 30 个事件组统计整个筛选范围，不只统计已加载的一页。事件组按服务、级别、事件名聚合；没有事件名的消息会归一化数字和 UUID。
- 点击事件组下钻；日志详情的同请求 / 同任务 / 同用户 / 同图片 / 同实例 / 同版本定位会清除其他限制，只保留时间范围和所选关联条件。点击日志在详情抽屉查看消息、错误栈和字段，按需加载同容器前后各 50 行上下文。
- 查询栏支持 `service:worker level:error taskId:xxx`、`container:"容器名"` 与自由文本；`q:"level:error"` 将字段形式的文字作为字面关键词，自动回填的关键词使用同一格式。部署与输出流可筛选；部署只筛当前 Admin 数据库里的记录，不跨部署数据库查询。趋势可拖选时间范围，事件组与留存信息默认折叠。跟随最新每 10 秒刷新，列表滚动或打开详情自动暂停，同一筛选条件刷新时保留上一份记录；刷新失败会提示并继续展示旧记录。加载更早日志会暂停自动刷新，保证翻页使用同一个时间范围。聚合只在首页计算；后续分页只读取日志记录和游标。每页 100 条，按 `(at, id)` 游标查询。
- 列表以终端形式保留完整换行和缩进，横向滚动长行；点击一段日志查看结构化字段和上下文。
- 「导出已加载」导出当前已加载记录为 NDJSON，不会自动下载整个日志库。

## 图片上传诊断

图片接口拒绝业务请求时记录 `media.request_rejected`，包括用户、图片（已知时）、阶段、错误码和 HTTP 状态。图片内容校验失败另记录 `media.validation_failed`，包括格式不符、动画、像素上限、解码或预览失败等原因，以及声明类型、检测格式、字节数和尺寸；不记录图片内容。两条事件沿用请求上下文，点击「同请求」能关联 HTTP 请求结果和具体错误栈。客户端仍收到原有错误码，上传策略保持原有行为。

## 采集和保留

采集不改应用代码，走 Docker 本身的日志转发（ADR 0021）：

1. `deploy/compose.app.yaml` 的 `x-log-forward` 把每个容器的日志驱动设为 `fluentd`，非阻塞异步发往本部署的 `log-collector`；`scripts/rollout-runtime.sh` 用同样的参数创建 BFF、worker、发布路由和迁移容器。Docker 本地缓存轮转上限为 3 × 10 MB，`docker logs` 照常可用；驱动或磁盘失败仍可能丢失缓存。
2. `log-collector`（Fluent Bit 5.1）在 `$XDG_CONFIG_HOME/ai-image-playground/log-forward/<部署>/forward.sock` 上收日志，每 2 秒把一批记录发到 BFF 的 `/internal/logs/ingest`（通过独立的 `bff-logs` 网络别名，内部令牌鉴权）。BFF 写入失败时回 503，采集容器保留这批数据，按退避重试；未送达的数据存在 `log-buffer` 卷，上限 256 MB。
3. Fluent Bit 将同容器、同输出流的 WARN / ERROR 标题及连续堆栈行合并，跨批次缓冲最多等待 1 秒，随后按完整记录转发；Docker 默认 tag 区分容器，采集器只对原始标签追加输出流；重发标签跳过改写，避免重复处理。BFF 以容器、驱动时间戳和原始输出的摘要去重重试批次，解析每条记录：pino 的 JSON 行保留级别、事件、请求 ID、任务 ID 和结构化字段；其他程序的纯文本行按 `ERR` / `WARN` / `INFO` 一类词判断级别，判断不出时 stderr 记为警告、stdout 记为信息。服务名取自容器名，无法识别的记为 `other`。

采集容器停止期间，运行中的容器在内存里暂存日志，恢复后补发（每容器驱动最多缓存 4096 条，超限会丢弃）；运行时间短于停机时间的一次性容器（例如迁移）会丢失这段输出。采集容器自身的输出只留在 `docker logs`，否则会形成回路。初次部署时 `scripts/app-compose.sh` 在其他服务之前启动它，启动失败只打警告，不影响发布。Compose BFF 和动态 BFF 都声明 `bff-logs` 别名。首个兼容 BFF 启动前，HTTP 连接失败由采集器缓冲重试，不向尚未支持接口的旧发布路由发送；后续新旧兼容实例可共同接收并去重。HTTP 400/401/404/413 等不可重试响应会丢弃该批次，不能用 Retry_Limit 声称所有错误都会补发。发布收尾重建 cloudflared，将其切换到日志转发。

迁移 `0060_server_logs` 建表，`0061_server_logs_containers` 放宽服务名约束，`0062_server_logs_instance_at` 支持同容器上下文范围查询；只有 BFF 写入，Admin 用现有只读数据库权限查询。日志界面和接口都要求 Admin 会话。写入使用独立单连接池，连接超时 2 秒、语句超时 1.5 秒，避免挤占业务连接。

每分钟清理过期数据，保留近 7 天、约 20 万条。单次删除最多 5000 条，容量超限会逐步回落。数据库日志隐藏常见密钥字段、认证头、Cookie、原始请求体、响应预览和序列化 JSON 中的用户内容，消息里的 Bearer、常见 API key、URL 密钥参数与 URL 密码也会脱敏。单行消息最多 4000 字符；多行终端记录整体脱敏后最多保留 16000 字符，结构化字段超限会标记截断。应用日志仍应遵守不输出秘密和用户原文的约定。

`LOG_LEVEL` 控制 BFF 与 worker 的输出级别，默认 info。PostgreSQL 属于共享的基础设施栈，暂不转发，用 `docker logs` 查看。数据库不可用时界面报告读取失败，日志在采集容器里排队等待，现场排障仍可用 `docker logs`。

页面的「采集容器状态」打开运维看板，检查 Fluent Bit 容器是否运行和宿主机采样是否新鲜。旧 BFF 内存缓冲的心跳计数已停用，不代表当前 Docker → Fluent Bit 传输状态。Fluent Bit 的重试错误用 `docker logs <部署>-log-collector-1` 查看；当前未接入其缓冲积压、丢弃量指标。

概览只计完整 ERROR / FATAL 记录与浏览器异常；旧采集器误判为 ERROR 的单独 `at ...` 堆栈行按输出流默认级别展示（stderr 为 WARN、stdout 为 INFO），列表筛选、统计和概览使用相同规则，入库原文保留。已入库的旧分行记录缺少精确行顺序，不能还原为原始多行事件；多行合并从新版采集器生效后开始。
