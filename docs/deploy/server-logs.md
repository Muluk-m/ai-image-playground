# 服务端日志系统

Admin 侧栏「运维 → 服务端日志」进入独立 `/logs` 页面，采集 BFF 和 worker 现有的 pino JSON 日志，以及用户 API 的请求结果。每条记录带服务、实例、构建版本、级别、事件、消息和结构化字段；请求上下文里的 `requestId` 自动关联，带 `taskId` 的业务事件可以定位到任务。

## 使用

- 默认显示近 24 小时，按服务、日志级别、近 15 分钟 / 1 小时 / 24 小时 / 7 天或自定义时间范围查询。自定义范围最多 7 天，输入和展示统一使用北京时间。
- 关键词按字面匹配消息、事件、请求 ID、任务 ID 和结构化字段；请求、任务、用户、图片、实例、版本采用精确匹配。用户与图片定位分别读取结构化字段 `userId` 和 `mediaId`，旧日志缺少这些字段时可按请求或关键词查询。
- 页面显示整个日志库实际留存的首末时间；查询包含留存起点之前的时段时明确提示此前可能尚未采集或已清理。无匹配记录不能说明此前没有故障。
- 筛选保存在 URL 中；「复制查询链接」冻结当前查询的开始和结束时间，重新打开后恢复相同范围和筛选，仍需 Admin 登录。
- 总量、错误数、警告数、趋势和前 30 个事件组统计整个筛选范围，不只统计已加载的一页。事件组按服务、级别、事件名聚合；没有事件名的消息会归一化数字和 UUID。
- 点击事件组下钻；日志详情的同请求 / 同任务 / 同用户 / 同图片 / 同实例 / 同版本定位会清除其他限制，只保留时间范围和所选关联条件。展开日志查看消息、错误栈和字段。
- 每 10 秒刷新，同一筛选条件刷新时保留上一份记录；刷新失败会提示并继续展示旧记录。加载更早日志会暂停自动刷新，保证翻页使用同一个时间范围。聚合只在首页计算；后续分页只读取日志记录和游标。每页 100 条，按 `(at, id)` 游标查询。
- 「导出已加载」导出当前已加载记录为 NDJSON，不会自动下载整个日志库。

## 图片上传诊断

图片接口拒绝业务请求时记录 `media.request_rejected`，包括用户、图片（已知时）、阶段、错误码和 HTTP 状态。图片内容校验失败另记录 `media.validation_failed`，包括格式不符、动画、像素上限、解码或预览失败等原因，以及声明类型、检测格式、字节数和尺寸；不记录图片内容。两条事件沿用请求上下文，点击「同请求」能关联 HTTP 请求结果和具体错误栈。客户端仍收到原有错误码，上传策略保持原有行为。

## 采集和保留

无需配置额外日志服务。迁移 `0060_server_logs` 新增表和索引；仅 BFF / worker 写入，Admin 使用现有只读数据库权限查询。日志界面和接口都要求 Admin 会话。

每个进程最多缓存 500 条，每 2 秒开始入库，单批最多 100 条，有积压时连续处理最多 20 批。写入失败时保留批次重试，相同日志 ID 避免重复；队列满后丢弃新来的数据库日志，容器 stdout 仍完整输出。采集积压、累计丢弃数、累计失败次数和最近写入时间放在服务心跳的 `detail.logs` 中。日志使用独立单连接池，连接超时 2 秒、语句超时 1.5 秒，避免挤占业务连接。优雅退出最多等 2 秒写出剩余批次，随后立即关闭日志连接；强制杀进程会丢失尚未落库的缓存。

每分钟清理过期数据，保留近 7 天、约 20 万条。单次删除最多 5000 条，容量超限会逐步回落。数据库日志隐藏常见密钥字段、认证头、Cookie、原始请求体、响应预览和序列化 JSON 中的用户内容，消息里的 Bearer、常见 API key、URL 密钥参数与 URL 密码也会脱敏。消息最多 4000 字符，结构化字段超限会标记截断。应用日志仍应遵守不输出秘密和用户原文的约定。

现有 `LOG_LEVEL` 控制采集级别，默认 info；debug / trace 需要相应配置。此功能从新版本启动后采集，不回填旧容器日志，不采集 Admin 的 console、PostgreSQL、nginx 或宿主机 journal。数据库不可用时界面报告读取失败，可以使用 `docker logs` 排障。
