# 0013 — 保留 Agent 原生模型历史，产品历史继续作为事实源

日期：2026-10-01。状态：采纳。关联：[#973](https://github.com/Muluk-m/ai-image-playground/issues/973)。

## 背景

参照 [Craft harness 调查](../research/craft-harness-audit-2026-10-01.md)，跨轮把产品消息重新拼成纯文字会丢掉原始时间、图片、工具调用与返回，改变下一次模型请求的共同前缀。轮内续调没有这次转换，因此仅修系统提示词的排序不能解决跨轮问题。

## 决策

- 正常用户轮在预扣之前读取 Pi 原生消息缓存；预扣和实发从同一份 `AgentTurnInput` 取消息。当前 UTC 时间继续追加在新用户消息中，旧时间和图片不重新生成。
- PostgreSQL 产品消息仍是事实源。只有会话归属、模型/provider、system、工具清单和完整产品历史的指纹吻合才复用。当前工具授权、图片归属与执行租约照常重新计算。
- 私有对象存储中每会话一个 `agent/<id>/model-context-v1.json`，最多 8 MiB；不在 PostgreSQL 重复保存图片 base64。先检查大小、读取有 1.5 秒上限，解析时检查消息与工具配对；失败退回现有回放。随现有会话前缀清理。
- 只有成功轮可以保存，在释放执行租约前等待写入完成或到达 5 秒期限；到期取消 PUT，缓存故障不拖住成功轮。存储服务在取消后仍提交的旧快照会被历史指纹拒绝，最多损失缓存命中。逐条保留本轮刚写下的消息，对比保存时的产品消息；后台任务、确认卡或插话改变状态就放弃本次保存。写失败不改变结算和成功状态。
- 技能目录的正文参与签名；已读取的技能和附属文件另外按当前正文核验。保存时再次核对新读的正文，修改/删除模板不能把旧工具结果钉成有效缓存。
- 已压缩的会话、唤醒/恢复轮和选区历史沿用既有回放。包括 mask、regions、editAction 和原生工具中的 selection ID；不能把上一轮的请求级选区重新带入下一轮。
- 原生消息超过上下文预算时，该轮永久回到既有压缩路径。每次 transform 都将最初原生前缀替换成产品回放前缀，再进入压缩器，保持持久锚点的位置含义；该轮不保存原生缓存。
- 不引入额外模型调用、自动重试或新的用户计费项。Pi 版本继续钉在 0.85.1；升级 0.87.1 的 transcript API 与 finishTurn 改造另行验证。

## 验证

从对话 HTTP 接口检查最终网关请求：跨轮旧前缀逐字一致，保留图片和完整工具调用/返回。验证历史变动、模型/权限变动、对象故障、选区、失败中止与压缩回退；尤其检查反复 transform 不重复历史或错位锚点，以及预扣估算与实发共用缓存。

上线后用已有首调/续调缓存用量分组观察效果；受控前缀一致不等于上游必然命中，网关路由、保留时间及供应商支持仍影响结果。
