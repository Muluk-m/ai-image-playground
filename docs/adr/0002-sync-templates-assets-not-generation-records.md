# 模板与素材随账号同步，本机数据不上云

登录用户的模板、素材（含图片本体）与用户设置在设备与服务端之间同步；任务记录、商品图任务、画布与草稿只留在当前浏览器。合并规则只在服务端存在一份（记录级最后写入胜出、删除以墓碑传播），客户端无条件接受服务端回传。

这样切是因为两类数据的价值曲线不同：模板与素材是用户反复投入的**资产**，丢了要重做；生成结果是**产出**，量大、一次性、BFF 已按 30 天运行态保留。把产出也上云会让每个用户的对象存储占用按生成量线性增长，配额与成本都无法收敛，而用户要的「换设备还在」主要是前者。

## Considered Options

- **全部上云（含任务记录）。** 用户体验最完整，但存储成本与生成量挂钩，且 30 天运行态 tasks 表要升格为长期档案，两套保留策略并存。
- **只同步用户设置与模板，素材图不上云。** 最便宜，但跨设备套用模板时引用全部降级为「已移除」，用户看到素材名字在、图不在，比没有更困惑。
- **模板 + 素材（含图）+ 用户设置上云，本机数据留本地。** 采纳。素材图有配额兜底，成本可控。
- **客户端做合并。** 每个客户端各实现一套 LWW，规则漂移风险高；服务端合并只有一份实现且在 HTTP 接缝可测。未采纳。

## Consequences

- 换设备看不到历史生成记录，这是刻意的；ZIP 导出仍是本机数据唯一的迁移途径。
- BYOK 密钥永远不在同步集合内，服务端不持有用户密钥。
- 服务端的模板表是 ROADMAP「模板市场」的地基；届时发布 / 复制在它之上做，不另起一套。
