# 模板、素材与项目的同步边界

登录用户的模板、素材（含图片本体）与用户设置在设备与服务端之间同步。经 #422、#433 调整，登录用户的新云端项目增加独立的版本化同步；普通任务记录与商品图任务仍保持本地边界。合并规则只在服务端存在一份（记录级最后写入胜出、删除以墓碑传播），客户端无条件接受服务端回传。

这样切是因为两类数据的价值曲线不同：模板与素材是用户反复投入的**资产**，丢了要重做；生成结果是**产出**，量大、一次性、BFF 已按 30 天运行态保留。把产出也上云会让每个用户的对象存储占用按生成量线性增长，配额与成本都无法收敛，而用户要的「换设备还在」主要是前者。

## Considered Options

- **全部上云（含任务记录）。** 用户体验最完整，但存储成本与生成量挂钩，且 30 天运行态 tasks 表要升格为长期档案，两套保留策略并存。
- **只同步用户设置与模板，素材图不上云。** 最便宜，但跨设备套用模板时引用全部降级为「已移除」，用户看到素材名字在、图不在，比没有更困惑。
- **模板 + 素材（含图）+ 用户设置上云，本机数据留本地。** 采纳。素材图有配额兜底，成本可控。
- **客户端做合并。** 每个客户端各实现一套 LWW，规则漂移风险高；服务端合并只有一份实现且在 HTTP 接缝可测。未采纳。

## Consequences

- 普通历史生成记录仍不自动上云；新云端项目可以跨设备恢复已确认的文字和标注。原有本地项目暂不自动迁移。
- BYOK 密钥永远不在同步集合内，服务端不持有用户密钥。
- 服务端的模板表是 ROADMAP「模板市场」的地基；届时发布 / 复制在它之上做，不另起一套。

## 项目同步的增量交付（#433）

项目结构采用服务端修订号和乐观并发控制，不能复用模板、素材的最后写入覆盖。仅同一部署、同一登录用户可以访问项目；匿名内容不自动认领。媒体及草稿的长期保存按 #422 的后续任务交付，当前含未上传媒体的场景不会提交为残缺文档或显示完整同步成功。

当前结构协议版本为 1，仅接受文字、箭头和画笔。协议上界为 1,000 个元素、512 KiB 结构文档；运营配额可进一步降低，默认每用户 100 个项目。写请求按流读取并限制总字节。每项目只保留最近 128 次提交的确认摘要；过旧请求落在确认窗口外时仍被基础修订校验拒绝，不会重新应用。该记录不是版本历史或操作日志。

界面中的“画布已同步”仅说明当前画布，不承诺云端草稿及会话绑定已完成。回收恢复尚未交付前不开放云端项目删除，避免把本机删除误报为云端删除。持续后台补传、冲突副本操作、图片与视频、迁移分别由后续任务补齐。
