# 界面只认错误码，不渲染服务端的 message

界面支持多语言后，服务端返回的错误需要有人来翻。我们决定由前端按稳定的 `error` 码取译文：BFF 响应里的 `message` 只是给日志与 API 调用方看的说明，不是界面文案；前端没有收录的码回吐机器码本身，而不是服务端的中文。另一条路是 BFF 按 `Accept-Language` 返回翻好的 message，放弃它是因为错误码是有限集合，前端已经持有全部语料和对 key 的编译期检查，服务端再养一份语料会让同一句话有两个来源，而且 BFF 目前并不知道用户的界面语言。

这条只覆盖有限的错误码。智能体回复、工具卡标题、澄清选项、邮件模板这类开放的生成文字没有码可查，只能由服务端按用户的语言生成，前提是 BFF 先知道界面语言；这件事留到正式面向海外前再定，届时无论怎么选，都不改变本条对错误码的约定。
