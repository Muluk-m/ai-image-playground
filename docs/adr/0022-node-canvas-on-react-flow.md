# ADR 0022：节点画布换成 React Flow，Konva 只留给图片编辑

状态：已接受（2026-10-11）。依据：[`video-platform-benchmark-2026-10-10.md`](../research/video-platform-benchmark-2026-10-10.md)。

## 背景

画布要升级为节点画布：图片、视频、文本、素材、分镜表、时间线都是节点，节点之间的有向连线就是引用，选中节点时生成输入框出现在节点正下方，图片与视频工作流共用这一块画布。现有画布是 Konva 一整块 `<canvas>`，与这个形态有三处根本错位：

- 箭头只存两端坐标，不绑定对象，拖动图片时不跟随；
- 工具条等 DOM 叠层靠手算坐标，拖动期间不跟随，doc 要到 dragEnd 才更新；
- 文字是 `Konva.Text` + textarea，不能承载富文本、分镜表这类结构化内容。

## 决定

- 节点画布用 [`@xyflow/react`](https://reactflow.dev)（React Flow v12）：节点是真实 DOM，自带有向边、端口、拖拽跟随、框选、点阵背景与小地图；视口默认无限平移缩放，不改变「无限画布」形态。
- 像素级编辑（局部重绘蒙版、手绘、在图上圈画改图）继续用 Konva，作为选中图片节点后进入的编辑层，不再是画布本身。
- 数据层不换：项目文档、云端同步、项目修订与乐观锁保留；节点、连线、分组作为新类型，前端模型与云端 `project-protocol` 一起扩展。
- 图片与视频节点使用统一 **360 × 240** 展示框，位图按 `contain` 保留原始比例；上传、替换、生成、候选切换与拆图都不按素材像素重算卡片边长，像素尺寸另存 `naturalWidth / naturalHeight`。旧项目的几何只在渲染、避障与定位时投影，不为统一外观在打开时改写共享 Y.Doc。媒体不提供手动缩放，文本与分组保留调整框的能力。
- 缩远时图片与视频封面仍然显示，不再换成只有文件名的空色块；视口外卸载后沿用文件引用 / 云媒体身份重新解析，数据 URL 与缓存不由节点卸载销毁。节点标题按屏幕像素保持字号，选择态只有一条框线。
- 新节点、上传素材、生成结果展开与复制粘贴按展示框避开已有节点及分组，同批新卡也互相避让；只移动新增内容，不移动旧节点。填入已有空卡、替换或重新生成不是新节点，保留原位置与存储宽高。
- 生成输入框固定在视口底部，宽屏位于导航和 Chat 之间，窄屏移到最底部控件行上方；适应画布与节点定位按输入框、工具条和页头的实际占用区域计算，不用固定像素高度猜测输入框尺寸。
- 智能体在节点画布中的图片、视频生成只走目标节点的 `updateNodes` / `runNodes` 路径，通用生图、改图、生视频工具不在该入口开放，队列草稿出口也拒绝绕行。候选和首个主结果复用节点生成器，不新增无主智能体图片节点；授权仍由 `runNodes` 统一处理。
- 画布工具路由以会话 `experience: 'canvas'` 为准，不以可选的 `selectedNodeIds` 字段判断入口。没有选中节点或没有传入客户端画布摘要时仍提供节点工具并读取服务端文档，不退回无主生成路径；项目身份与写权限由服务端继续校验。
- `importCanvasImage({imageNodeId, assetNodeId, viewLabel?})` 将同一云端项目中已同步的真实图片收为素材节点候选并选为主结果，保留来源节点和旧候选，可整体撤销，不提交生成或扣费。空图、视频和非素材目标会被拒绝。素材未有图时显示「待出图」；仅修改提示词或提交运行不能被描述为已挂图或已完成。
- 分镜表制作的纯文档阶段由 `packages/shared/src/canvas-storyboard-flow.ts` 提供：`storyboardMissingAssets` 查询缺图素材，`assertStoryboardAssetsReady` 在执行前阻止缺素材的运行；`prepareStoryboardFrames` 铺宫格或逐镜首帧，`prepareStoryboardVideos` 按镜号绑定首帧、素材、模型支持的时长与时间线。入参为 `Y.Doc`、事务来源与调用方提供的视频模型能力，不读取浏览器、渠道列表或 UI 状态；本地 `fileId` 与云端 `mediaId` 都可作为已有图片。
- **准备占位与允许执行不是同一阶段**：手动铺首帧保留已有行为——提示缺素材但仍允许先铺占位；实际执行方调用素材就绪检查，不因占位已存在而绕过生成门禁。未定稿、首帧缺失或过期、无首帧模型与过长提示词均在文档写入前返回稳定错误码。前端只选择模型、翻译名称/错误、分隔撤销步骤与发起生成确认；裁切宫格图片仍在浏览器完成。
- 时间线沿用每条最多 64 镜、600 秒的片长界限，超限续建下一条而不丢镜；没有视频结果的镜头仍保留位置。展示卡尺寸和避障几何由共享 `canvas-placement.ts` 提供，手动节点与分镜流程使用同一规则。

## 考虑过的方案

- **在 Konva 上扩展**：连线绑定、叠层跟随、富文本与表格都要自建，叠层同步正是现有薄弱点。否决。
- **两套画布并存**：图片与视频会被重新分到两个工作面，与「共用一块画布」冲突。否决。

## 竞品核实（2026-10-10，只读检查各家加载的前端代码，未登录、未生成）

| 平台 | 节点画布 | 像素编辑 | 证据 |
| --- | --- | --- | --- |
| 即梦 | React Flow v12 + Yjs | Konva（智能编辑、视频编辑的涂抹） | 画布子应用 `canvas-view.*.js` 含完整 `@xyflow` 与 `react-flow__*` 类名 |
| LibTV | React Flow v12 | — | CSS 自定义节点 `react-flow__node-image / -video / -audio / -video-clip` |
| TapNow | React Flow + 自研画布包 | Fabric.js | `vendor-pkg-canvas-*.js` 命中 `react-flow__node / __edge / __pane`，`vendor-libs-*.js` 含 React Flow 署名链接 `reactflow.dev?utm_source=attribution` |
| 可灵 | 自研 PixiJS + pixi-viewport（Vue 3） | — | 全部 chunk 无 React Flow |

四家中三家用 React Flow 做节点画布，即梦与 TapNow 也把像素编辑交给另一个库，与本决定的分层一致。

## 后果

- 画布渲染层重写：现有 `KonvaCanvas` 的对象渲染、选择、吸附、叠层改由 React Flow 承担；`rasterizeSelection` 把标注烧进参考图的行为移入图片编辑层。
