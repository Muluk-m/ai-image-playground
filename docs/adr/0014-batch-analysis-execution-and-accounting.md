# 批量分析使用独立执行和计费归属

状态：accepted（规格决定，尚未实施）。2026-10-01；用户确认批次范围、费用展示与暂停恢复语义后，调用 to-spec 将整体方案发布为[规格 #938](https://github.com/Muluk-m/ai-image-playground/issues/938)。

批次可能跨越多轮对话并在原轮结算后继续执行，因此批次是独立的确认与进度归属；生成项复用现有生成任务，视觉分析采用显式 analysis 类别、专属执行路径和逐项计费归属，共用既有 Postgres/worker 与预扣结算 hooks。不会把分析塞进图片队列、追加到已结算对话轮或伪装成平台承担的摘要调用，也不新增外部工作流引擎。

代价是必须扩展任务类型、租约恢复、维护与成本分类，并持久保存计价事实；收益是重启后仍能区分已派发、结果未知与未派发项，保证一次实际调用只有一个计费归属。整批确认不等于整批重复预扣，批次费用由各项账单汇总；沿用已有对话免单能力，生成费用保持独立。详见[技术方案](../design/multi-image-chat.md)。
