# 项目拥有上下文，执行窗口负责有界工作

用户确认执行窗口切换应保持同一段可见对话，并明确后续将引入项目：一个项目对应一张画布和一套独立上下文。项目是未来的创作状态归属边界，执行窗口是在该边界内控制模型输入容量的机制；这些是已确认、待实现的领域方向。

## 决策

- 采用窗口方案 `7A`：内部自动切换执行窗口，用户继续使用原有对话与画布，旧历史仍可查看，不为每个窗口创建独立子会话。
- 后续项目与画布一一对应，每个项目拥有独立上下文。切换项目时不携带上一个项目的目标约束、工作集、摘要、检索结果或工作进度。
- 返回已有项目时恢复该项目自己的目标与进度，按需装入有界执行窗口；新建项目从新的项目上下文开始。恢复不要求把全部历史重新发给模型。
- 用户明确选择个人级长期创作偏好可自动影响所有项目，例如在一个项目中确立的惯用风格可供新项目使用。个人偏好是独立共享默认项，不是复制原项目摘要或开放跨项目历史的依据。
- 用户明确表达“以后”“默认”“记住此偏好”等长期意图时自动保存个人偏好，普通目标要求不自动升格，也不依据多次行为自行推断持久偏好；提供查看、修改和删除入口。
- 修改个人默认偏好影响之后新建的创作目标，进行中的目标保持原有要求。用户在当前目标明确改口时才调整，当前目标的明确要求优先于个人默认项。
- 项目上下文可以包含外部保存的历史与证据，模型仅加载当前执行窗口。窗口切换不把项目全部资料重新塞回模型，也不通过不断追加旧摘要扩大输入。
- 当前 ADR 0005 的会话画布继续描述已实现阶段；引入项目后，ADR 0006 的默认读取归属边界随项目演进，不把项目永久等同于会话 ID。项目界面与迁移未被本次研究自动纳入实现范围。

## 取舍与后果

固定项目归属可让窗口自动轮换和后续对话形式变化不破坏画布与记忆边界，但读取、检查点、证据检索与后台产物必须使用同一归属进行隔离；服务端拥有多个项目资料不意味着可以自动混入当前项目。

窗口容量、用户可见对话长度与项目资料保留量是三个独立维度。既有素材库的访问规则不因项目隔离自动撤销，资料可按需读取，但不能因为可访问就预载其他项目上下文。

后续选择 `8A / 9B` 明确：“切换项目全新”表示项目工作上下文隔离，返回原项目仍恢复其自身进度；个人创作偏好作为独立共享层跨项目提供。两者的来源和作用范围必须分开，不能将项目观察或临时要求自动当作个人偏好。

后续选择 `10A / 11A` 明确个人偏好的显式写入、修改与生效规则。此决策不指定数据库或检索算法；结构化读取和向量检索的取舍在研究文档中作为技术候选说明。未来项目内的会话数量留待项目功能设计，不影响执行窗口保持用户可见对话连续这一约定。
