# ADR 0008：项目图片使用受配额管理的持久媒体

- 状态：实施中
- 关联：[#434](https://github.com/Muluk-m/ai-image-playground/issues/434)、[#422](https://github.com/Muluk-m/ai-image-playground/issues/422)、[#483](https://github.com/Muluk-m/ai-image-playground/issues/483)

## 决定

画布结构保存稳定 `mediaId`、对象顺序、几何、名称、分组及来源；不保存临时下载地址或位图。原图与 1024 像素以内的预览分别存储。列表只返回摘要和封面媒体身份；画布在视口内请求预览，下载、导出或作为生成参考时才取原图。浏览器保存的本地原件不会因为上传而被删除。

`media_objects` 区分预留上传与已确认对象。同一用户、相同 SHA-256 复用身份；服务端同时核对长度与实际图片格式。所有容量写入在用户行锁内串行，旧素材与新媒体共用总容量计量。初始总容量为可配置的 10 GiB，单图沿用既有更严格的上限；预览也计费。预留包括有界预览预算，确认时按实际原件和预览字节结算。20 分钟未确认的预留不再占用可用额度，上传记录保留供重试和回收。

客户端只得到暂存对象的短期 PUT 地址。服务端按申报长度有界读取，验证摘要与解码结果，把已验证的字节写到新的、仅服务端可写的原件键，并确认原件和预览可读后发布。重复使用上传地址只能改暂存对象，不能改已发布原件。单次解码与缓冲有上限，不把原件落到 VPS 系统盘；存储 I/O 在数据库事务外执行。失败候选位于所属媒体身份的目录下，可与数据库发布指针比较后回收。

`media_references` 使用项目、素材、会话、创作记录的统一引用身份；项目保存与引用变更同事务。其他引用生产者随相应后续票接入。删除与回收实现必须检查所有引用，不能仅凭任务过期删除对象。媒体回收和回收站策略由 #440 继续实现。旧素材入口保留先写对象、再短事务重新核验容量并发布账本的顺序；并发抢占剩余额度时，被最终拒绝的写入可能留下未入账对象。目前存活用户的这些对象没有应用级回收，不能把只清理已删除用户的旧清理器视为覆盖；旧前缀仍受上述生命周期限制，#440 必须补充存活用户孤儿对账。

## 存储边界

永久对象使用 `durable/<S3_KEY_PREFIX>/`，暂存与候选也在该隔离空间。现有任务继续使用原来的前缀，不改变临时任务的清理行为。

2026-09-17 实际检查发现，生产桶的 `image-playground/` 与 `image-playground-paid/` 分别有 45 天过期规则，其 `pg/` 子目录另有 14 天规则；全局规则仅终止 7 天未完成的 multipart。部署时必须重新检查实际规则，禁止新增覆盖 `durable/` 的过期规则。存储账号与付费 Pages 账号不同，不能使用 Pages 账号的检查结果代替存储桶检查。

读取前先由 BFF 检查登录归属，再签发有效期 10 分钟的 GET 地址。浏览器直接访问 R2，普通原图不经 BFF 搬运。临时 URL 只存在于请求中；本地场景中的 `aip-media:<id>` 重新获取访问地址。签名过期最多重取一次；R2 的过期响应没有 CORS 头，浏览器也可能只暴露网络错误。

## 发布验收

- 在真实 HTTP 与隔离 PostgreSQL 上验证两设备恢复、跨账号拒绝、并发容量、重复上传、损坏图片与存储失败恢复。
- 使用真实存储适配器和受控时钟模拟已核对的 45 天规则，验证临时任务过期、永久原件仍可读。
- 在 R2 所属账号核对生命周期，并为部署的前端 origin 配置 GET/HEAD/PUT CORS。验证浏览器 PUT、预览读取、原件读取和导出，不能只验证命令行下载。
- 部署 BFF 与迁移，再发布前端。旧本地场景保留原件；云端图片未确认时不得标记完整保存。

参考：[Bun S3 签名地址](https://bun.sh/docs/runtime/s3)、[R2 生命周期](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)、[R2 CORS 与过期签名](https://developers.cloudflare.com/r2/buckets/cors/)。

## 普通会话附件的短期租约（#940）

普通会话上传复用画布无关客户端、媒体 API、摘要去重和统一容量。运营同时开启 `agent:attachments` 与 `accounts:sync`，并把 `sync:attachment-lease-seconds` 设置为正数后生效（例如 1200 秒）；默认关闭且租约为 0。关闭时保留原有受数量和请求体限制的内联入口；启用后上传失败必须重试或显式移除，不能悄悄退回内联。新选入的 PNG/JPEG/WebP 文件先在浏览器预处理，服务端接收处理后的工作图，再生成预览；本地画布与素材已有的原件不改写，遮罩保持与对应画布源图的坐标一致。遮罩/编辑动作的引用协议另由 #941 实施，本票不改变原有数量上限。

仅首次由附件入口新建的媒体标为 `attachment_managed`；复用历史身份不会把旧对象纳入扫描。重复上传续租，所有引用按消息受理事务整体认领。重复客户端消息 ID 复用已受理结果，不为重放里的其他媒体新增引用。失败或队列拒收不持久认领任何附件。

回收只扫描租约和上传预留都到期的受管对象（即使已就绪，也要等旧暂存 PUT 地址失效），并核查项目、素材、会话、创作记录的统一引用。现有任务会复制原件至自己的任务目录；本阶段还保守保护同用户非终态任务和运行中的 Agent 轮。若历史任务长期不结算，该用户的附件回收会延后，须先完成任务状态对账；不可用固定超时跳过保护。后续任务若直接使用持久媒体，必须单独持有任务引用。

确认原件和回收共享 PostgreSQL 会话锁，删除中禁止续租/认领；对象 I/O 不占用事务和用户行锁。删除失败保留 `deleting` 账本与容量，维护循环重试并在对象删除成功后释放一次容量。受管 pending 预留也只在安全回收后释放，不沿用旧媒体 20 分钟后自动腾额度的计量。租约过期但已被任一会话等引用的对象仍保留；删除一个会话不会删除另一个会话使用的原件。

## 附件上传限制与错误反馈

对话附件的像素预算由 `agent:attachment-image-pixels` 控制，硬上限最高支持 1,000,000,000 像素；单图最大 50 MiB。客户端预处理目标与这道原件接收上限独立。单图字节预算仍取 `agent:attachment-image-bytes` 与 `sync:asset-image-bytes` 的较小值，与像素预算分别校验。前端从 `/api/capabilities` 读取当前部署的实际限制，不用生成模型的输入分辨率限制代替原件上传限制。

超过像素预算返回 `media_image_pixels_exceeded`，不能归入 `media_invalid_image`。输入框显示失败原因、当前限制和处理办法；大小或格式超限要求用户调整文件后重新选择，临时网络或服务失败允许重试，失败附件仍阻止整条消息发送。


## 文件附件上传前预处理（2026-10-08）

选图、拖拽、粘贴与兼容内联入口共用 `lib/imagePreprocessing`。文件头校验真实格式、完整容器、动画及解码尺寸，输入最大 100 MiB、6400 万像素、单边 32768；这些是浏览器解码安全边界，与服务器原件接收上限分开。预处理以 2048 最长边、4194304 像素、2 MiB 为工作图目标，并取 capabilities 字节/像素预算的较小值。保持比例，不放大小图；解码自动应用 EXIF 方向。PNG/WebP 检查透明通道，透明图绝不转 JPEG。优先尝试 PNG 和高质量 JPEG/WebP，逐档调质量，再按 75% 缩尺寸；编码仍不能满足预算则保留失败位置并禁发，不回退上传原文件。已经满足预算且比重编码小的有效原图可复用字节。

处理共用单一串行队列，优先 Worker + OffscreenCanvas，完成/取消/超时均终止 Worker 并释放位图；老浏览器复用同一有解码上限的 Canvas 编码器。处理后的字节、实际 MIME、原始字节数和输出尺寸一起持久化，再沿既有摘要上传、租约和草稿恢复链路发送，重试不会反复压缩。已有本地画布/素材 data URL 保留其原件语义，避免改动遮罩与区域坐标。用户磁盘原文件不改动。

实现参考（仅参考策略，未复制代码）：Craft Agents `packages/server-core/src/services/image-utils.ts` 的尺寸/格式/质量预算；Grok Build `xai-grok-shell/src/session/image_normalize.rs` 与 `xai-grok-tools/src/util/image_compress.rs` 的头部解码保护、尺寸与质量降档、不放大、不膨胀和分类失败。附件 UI 使用纯缩略图，处理中在图片位置转圈；文件名保留在可访问名称与提示，失败原因和重试仍直接可见。
