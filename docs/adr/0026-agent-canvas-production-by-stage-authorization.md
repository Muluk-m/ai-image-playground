# ADR 0026：智能体画布制作只经分镜表流程，按阶段授权运行

状态：已接受（2026-10-19）。关联：[ADR 0022](0022-node-canvas-on-react-flow.md)、[ADR 0023](0023-canvas-document-on-yjs.md)、#1363。

## 背景

「山海学徒」会话复盘：智能体用通用建节点工具手工搭首帧与视频节点，结果是首帧生成方式却空帧位、提示词写 15 秒而参数是 5 秒、素材节点没有图、生成结果成了无主图片节点；运行时而要用户逐批确认、时而直接开跑，运行结果与开跑前被拦的原因都不回到对话。19 轮里 25 次工具调用失败，第 1 集一个视频也没出。

画布手动操作早有完整的分镜表流程（定稿 → 铺首帧 → 建视频节点并绑帧位 → 排进时间线），智能体却绕开了它。

## 决定

- 从分镜表派生的首帧与视频节点，用户与智能体都只经分镜表流程铺出。流程与界面无关的部分放进共享包，前端与 BFF 共用一份实现；通用建节点工具只留给分镜以外的零散创作。
- 一集的制作分素材、首帧、视频三个阶段，每阶段由用户做一次**阶段授权**（范围 + 预算上限）。授权内智能体自行运行、同一节点至多自动重试一次；超出范围、预算或重试后仍失败就停下说明。首帧阶段的授权即为分镜表定稿。它取代「逐批运行建议」与「出图模式自动运行」两套语义。
- 画布节点运行仍在浏览器执行；浏览器把一批运行的结果（提交的任务、开跑前被拦的原因、成败）回报 BFF，由 BFF 记账并按唤醒规则唤醒智能体。

## 考虑过的方案

- **给通用建节点工具补齐时长、帧位、分辨率等字段**：智能体仍要自己保证镜号、帧位与时间线一致，等于再写一遍分镜表流程，且与手动流程分叉。否决。
- **每批运行都确认**：整集要跑几十个任务，确认过碎；只设金额阈值又说不清钱花在哪一步。否决。
- **画布节点运行迁到服务端执行**：宫格切图、结果落节点等逻辑都在前端，迁移成本远超本次目标。暂不做，回报通道先把结果接回智能体。

## 后果

- 分镜表流程从前端抽到共享包，前端手动流程行为不变，由现有测试守住。
- BFF 新增阶段授权的持久化与运行回报入口；唤醒从后台任务扩展到画布节点运行。
- 出图模式每轮自动提交额度在画布模式下的去留需在实现阶段明确，不得与阶段授权同时生效导致重复开跑。
