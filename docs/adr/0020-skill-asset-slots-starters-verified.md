# 0020：素材位推广到技能，起手句按场景露出，只露出已验证的技能

日期：2026-10-02。状态：已接受。关联：#995、#997，ADR 0007。

对话创作首屏要按场景引导用户用技能（Lovart 式两层：场景按钮 → 起手句）。为此技能需要声明「要什么图」与「一句话怎么开头」，
而且只能把产出质量验证过的技能摆到首屏。

**素材位从模板专属推广到所有技能，声明写在 `meta.json`。** 新增可选字段 `inputs`（素材位：稳定 key、中英显示名、是否必填、
能否多图）、`starters`（起手句：中英文案，`{key}` 引用素材位，可选示例词）、`scene`（四个固定场景之一）与 `verified`
（验证记录：日期、模型、分数）。沿用 ADR 0007 的旁路文件规则：这些字段只走界面，不进系统提示词、不进技能全文；
写坏只回退该字段，技能照常可用。预置模板没写 `inputs` 时由 `slotCount` 派生 `asset1..N`（显示名「素材」、必填、可多图），
`slotCount` 字段与用户自建模板（`user_looks`、同步 kind `looks`）的存储一律不变，用户模板同样按自己的素材位数量派生。
被否决的做法：把素材位写进 frontmatter（标准不认、loader 读不回来）；让起手句复用快速生成的槽位 `{名称}`（槽位的笛卡尔积展开
只对快速生成有意义，对话里的可改文字就是普通文字）。

**起手句只能引用声明过的素材位。** 引用了未声明位的那一条在加载时丢掉并打 `agent.skill_starter_dropped`，同一技能的其他起手句
与技能本身保留；示例词不在句子里时只丢示例词。随仓库发布的技能由 `shipped-skills.test.ts` 把这些回退一律拦在 CI。

**「已验证」由服务端算，前端不判断。** 技能目录（`GET /api/agent/skills`）给每条技能一个布尔 `verified`：有验证记录，且记录的模型
等于这条技能实际会用的模型。验证记录本身（日期、分数）不发给界面。

- 预置模板：比钉死的 `template.model`。改钉死模型即自动下线，直到重新验证。
- 非模板技能（裁决）：比**部署默认的出图模型**，即智能体在没被指定模型时 `resolveAgentModel('image')` 解析出的那个
  （运营配置的 `AGENT_IMAGE_MODEL`，没有就是 channel 清单里第一个图片模型）。运营换默认模型、或该模型下线退到别的模型，
  非模板技能就全部翻成未验证。否决「只要有记录就算」：验证的是「这条流程在这个模型上出得了图」，换了模型的结果没有被看过。
  也不按访客在输入框里选的模型分别计算：目录是部署级数据、会被缓存，访客选择只影响单轮，首屏不为它拆出多份清单。

**露出规则在前端只做过滤。** 场景引导只渲染 `verified` 且归了场景、有起手句的技能，每个场景最多三条；没有可露出技能的场景不出按钮，
目录拉不到或一条都没有时整块隐藏。点起手句经「输入框填一句话」接缝（`composerFill`）交给输入框结构化内容（技能、句子、示例词），
输入框按自己的存储形态落成开头的 `/技能名` 加句子，示例词选中；素材位本票先以位名作普通文字占位，位胶囊另做（#998）。
已有用户草稿时不覆盖，只提示。本票不写任何随仓库发布的 `verified` 或起手句：生产在验证流程跑完前不露出任何东西。
