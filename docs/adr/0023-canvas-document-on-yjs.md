# ADR 0023：画布文档以 Yjs 为准

状态：已接受（2026-10-11）。关联：[ADR 0022](0022-node-canvas-on-react-flow.md)。

## 背景

现有项目同步是整份文档保存加修订号乐观锁，冲突时只能二选一。节点画布要求 Agent 在服务端直接改画布（浏览器关着也能干活），同时用户在浏览器里拖节点、改文字；再加上离线编辑、多设备，以及工作流调研里「多人分集并行」的真实场景，整份覆盖会让冲突成为常态。

## 决定

- 一个项目画布就是一个 [Yjs](https://yjs.dev) `Y.Doc`（CRDT）。浏览器之间、浏览器与服务端经 WebSocket 同步；本机用 `y-indexeddb` 持久化；服务端把增量写入 PostgreSQL 并定期压缩为快照。
- Agent 在服务端对同一个 `Y.Doc` 施加改动，与用户编辑自动合并。
- 撤销按人：每个人只撤自己的改动；Agent 的一批操作对发起它的用户算一步。
- 数据层按多人协同设计；第一版产品只开放「一个用户加 Agent」，共享编辑与他人光标以后再开。
- 整份保存与修订号乐观锁随节点画布上线退役。

## 考虑过的方案

- **自建操作日志**：服务端定序、客户端重放。合并、离线与按人撤销都要自己实现，等于重写半个 Yjs。否决。
- **保留整份保存，冲突时让用户选**：Agent 与用户并发写是常态，不可接受。否决。

## 后果

- 同步层重写，BFF 新增 WebSocket 通道（Elysia 原生支持）。
- 生成结果不进文档：节点只存生成记录的引用与主结果，避免文档膨胀拖慢同步。

## Dev 实现与兼容边界（#1149）

节点画布始终使用 React Flow。`accounts:sync` 开启时，云项目的文档是 Y.Doc。
`GET /api/projects/:id/canvas` 读取快照，`/canvas/ws` 使用 y-protocols 的同步帧；
服务端另发提交确认帧，客户端收到 PostgreSQL 提交确认后才标记已保存。
每次更新在独立候选文档上校验结构、项目归属及媒体/任务引用，失败不写入，也不广播。

`canvas_documents` 保存快照和迁移时的原始 `legacy_document`；`canvas_updates` 保存增量。
每 128 个增量或 5 分钟后的下一次写入会在同一事务中压缩快照并删除已覆盖增量。
迁移与写入使用项目所属用户的行锁，与原有媒体/Agent 归档事务串行；通知只在提交后送出。
每个 BFF 进程最多占用一条 PostgreSQL LISTEN 连接，普通读写继续使用既有连接池。
发布容量核算必须把这条连接算进总计 100 条的预算，不随画布或 WebSocket 数增加。

旧 `canvas_projects.document` 继续作为 Agent、项目列表与旧读取接口的投影，
它不再接受已迁移项目的整份客户端 PUT（返回 `project_canvas_upgrade_required`）。
Agent 预留与完成产物时同步更新同一份 Y.Doc，保留用户已经移动的位置和其他节点。
迁移原件独立保存在 `legacy_document`，不随投影更新或快照压缩改变；本轮没有清理原件的任务，
至少保留 30 天。浏览器原 IndexedDB 场景也保留，未同步的旧本地编辑另存为恢复副本。

回滚代码时不能恢复旧客户端整份覆盖写入，否则会丢失节点与连线。
数据库 down 文件仅用于空测试库回退；有实际数据的环境应保留新增表，先导出 Y.Doc、
原始旧存档及媒体引用，再设计数据恢复。本轮仅 dev 验证，不开启生产能力或执行发布。

WebSocket 生命周期验证使用 Bun 1.4.3，Docker 构建与运行阶段固定到同一版本。
Bun 1.3.14 在该同步测试中关闭连接后仍保留 pendingWebSockets，导致 stop 挂起；
同一测试在 1.4.3 正常释放。开发 BFF 也应使用 1.4.3 或更新版本。

## 时间线片段（#1154）

时间线按源节点 ID 取当前主结果，源节点被删除或暂时没有视频时保留缺镜位置。
旧 `data.clips` 作为不可变基线保留重复来源与原入出点；新增片段及编辑增量存入
`timelineSlots`，以时间线 ID、旧槽下标或新来源 ID、字段为键。裁剪、顺序、删除标记
独立合并。编辑器打开时捕获槽位身份与基线，保存只写用户实际修改的字段；未见的远端
新增保留，远端删除不会被旧草稿复活。一次保存连同可视连线计为一步撤销。

新增与成片导出上限仍为 64 段。持久化允许最多 1000 段，以容纳离线客户端并发新增后的
暂时超限；所有片段保留并同步，界面提示删减后导出，不静默截断或拒绝整个画布同步。
服务端同时校验旧基线、每个槽字段、合并投影、文档字节数与槽字段总数。此格式仅在 dev
分支使用，上线前必须同时更新支持该根字段的服务端与前端。

## Agent 写入与混合历史（#1160，仅 dev）

`createNodes`、`updateNodes`、`connectNodes`、`deleteNodes`、`arrangeNodes` 在所属项目的
同步事务内修改候选 Y.Doc，经过同一套图结构、媒体和任务归属校验后提交。工具只接收节点
字段，不接收可替换整份文档的快照；创建视频必须显式指定生成方式，不提交生成任务。

`canvas_commands` 用项目、轮次及工具调用 ID 保证幂等，同事务保存调用前状态和增量。
最多保留 64 条完整撤销记录；过期记录清空大字段但保留幂等凭据。撤销重新建立该调用的
Yjs UndoManager，再合并当前文档执行逆操作，避免用旧 JSON 覆盖用户后来编辑。逆操作本身
保存成下一次可反转的记录，revision 防止两个窗口重复反转同一版本。

浏览器将本端 UndoManager 与服务端命令接到同一历史入口。Yjs 编码不包含 `Item.redone`，
所以两端把恢复映射存入独立根字段 `undoLineage`，不纳入用户撤销范围。区间先拆分，再按
最终 Item 建立和校验指针；保留已回收内容的身份与位置，支持文本、节点父项跨两端恢复。
元数据有形状、数量和循环校验，整个文档仍受字节上限约束。浏览器先在临时文档预演本地
逆操作，超过历史预算就保留原内容与历史并提示，不把无法同步的状态写进 IndexedDB。

历史映射暂不清理，因为其他窗口或保留的服务端命令仍可能引用旧身份；达到预算后停止新增
逆操作。历史压缩需在后续规模验收中显式处理跨窗口历史失效。该根字段需要前后端同时升级，
不能先发布新前端给只接受旧根字段的服务端。数据库 rollback 仍仅用于空测试库。
