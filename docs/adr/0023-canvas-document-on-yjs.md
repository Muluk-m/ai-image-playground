# ADR 0023：画布文档以 Yjs 为准

状态：已接受（2026-10-11）。关联：[ADR 0022](0022-node-canvas-on-react-flow.md)。

## 背景

现有项目同步是整份文档保存加修订号乐观锁，冲突时只能二选一。节点画布要求 Agent 在服务端直接改画布（浏览器关着也能干活），同时用户在浏览器里拖节点、改文字；再加上离线编辑、多设备，以及工作流调研里「多人分集并行」的真实场景，整份覆盖会让冲突成为常态。

## 决定

- 一个项目画布就是一个 [Yjs](https://yjs.dev) `Y.Doc`（CRDT）。浏览器之间、浏览器与服务端经 WebSocket 同步；本机用 `y-indexeddb` 持久化；服务端把增量写入 PostgreSQL 并定期压缩为快照。
- Agent 在服务端对同一个 `Y.Doc` 施加改动，与用户编辑自动合并。
- 撤销按人：每个人只撤自己的改动；Agent 的一批操作对发起它的用户算一步。
- 数据层按多人协同设计；第一版产品只开放「一个用户加 Agent」，共享编辑与他人光标以后再开。
- 整份保存与修订号乐观锁随节点画布上线退役。

## 考虑过的方案

- **自建操作日志**：服务端定序、客户端重放。合并、离线与按人撤销都要自己实现，等于重写半个 Yjs。否决。
- **保留整份保存，冲突时让用户选**：Agent 与用户并发写是常态，不可接受。否决。

## 后果

- 同步层重写，BFF 新增 WebSocket 通道（Elysia 原生支持）。
- 生成结果不进文档：节点只存生成记录的引用与主结果，避免文档膨胀拖慢同步。
