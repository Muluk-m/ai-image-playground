**2026-09-19 重订，2026-09-20 复核。** 旧的 Phase 0/1/2 时间轴已失真：主线三项里 2.2 标着已交付却没收口、2.3 被自己的进展注释废掉、0.1 的 token 单元漏勾；同时 50 张 open issue 里有 40 张是四条规格下的 ready-for-agent 切片，在旧结构里一条都没出现。本次改为按**准入标准**分道。旧编号保留在「已交付」「已搁置」「已砍 / 降级」三节里，不删除。

## 排序原则

**瓶颈不在 spec，在执行和验收。** 队列里已经躺着 40 张 spec 好、标 `ready-for-agent` 的切片，继续产 spec 只会加大堆积。

按准入标准分三条道，不按时间分 Phase：

| 道 | 准入标准 | 谁先走 |
| --- | --- | --- |
| **Lane A 收口** | 已经在向用户收钱、但没被验证或没闭环的能力 | 最先。A 没清空之前不往画布上加新能力 |
| **Lane B 地板** | 付费产品的不可失守线（钱、数据、成本上限） | 与 A 并行，但范围严格受限 |
| **Lane C 差异化** | 决定谁付钱的方向 | A 的成本敞口关掉之后 |

两条硬约束：

1. **已上线的能力未验证，就不许铺新能力。** 当前有两处未验证：长画布智能体任务的质量与总成本（#408），以及 `apps/bff/skills/image/` 下三条电商技能正文自己标着「示例级内容，尚未经过真实产出验证」。
2. **Lane C 与视频主线无依赖。** 电商三件套都走已有的 `image` 计费单元与 `editImage` 工具，不等任何视频能力。

## Lane A：收口

### A1 智能体对话不被生成阻塞（#600）

- [ ] 目标：生成进行中对话仍可继续；排队消息、后台任务、唤醒与失败重试各自有明确状态。
- 现状：旗舰模式的阻塞缺陷，规格已就绪。
- 为什么排第一：改动面最小、用户感知最强，且不依赖任何其它项。
- 验收：生成中发送的消息不丢、不乱序；任务失败后对话不卡死。

### A2 智能体画布有界执行与成本验证（#391，优先 #400 / #398 / #396 / #408）

- [ ] 目标：每次请求装入**有界**工作内容；长结果外置；按需读预览与高清局部；跑通一次长画布任务并记录真实总成本。
- **这不是性能优化，是计费正确性问题。** 对话按 token 折算积分（裁决 E2）且已上线（`ModelPriceUnit` 含 `kilo_token`，私有迁移 `0008_chat_token_pricing`）。#400 的存在说明当前没有上下文上界——画布越长，用户为实现缺陷付的钱越多。
- 现状：#408 明写「验证长画布任务的质量、**总成本**和可靠性」，至今未验证。
- 涉及：BFF 智能体轮次输入组装、工具返回外置、画布观察刷新。
- 验收：给定一张超过阈值的画布，单轮输入 token 有上界且可预测；一次完整长任务的总积分消耗被记录下来，与预扣口径对得上。
- **这一项不完成，Lane C 不开工。**

### A3 画布视频第二期收口（#634）

- [ ] 目标：视频入口进画布、多图参考、智能体按镜头出片，以及随之而来的死代码清理。
- 现状：规格已就绪；2.3 分镜的出口已经改到这里（#649），所以它也是 2.3 的收口。
- 验收：视频不再需要独立入口；旧导演台路径无残留。

### A4 电商三条技能的真实产出验证

- [ ] 目标：`scene-swap` / `product-restyle` / `image-remix` 三条技能拿到失败率数字，去掉「示例级内容，尚未经过真实产出验证」这行标注。
- 方法：10 个 SKU（硬表面 5 / 透明高反光 3 / 服装 2）× 3 条技能 × 3 次，统计 logo、型号字、比例、光影方向四项的失败率。
- 产出同时回答 Lane C 的路线裁决（抠图合成 vs 全图重绘）。
- 验收：失败率表进 `docs/research/`；三条技能正文按结论修订。

## Lane B：地板

### B1 存储边界回到模板 + 素材（裁决 G1）

- [x] 已在的：登录用户的**模板、素材（含图片本体）、用户设置**跨设备同步（#176，能力位 `accounts:sync`，配额走 operator-config）。
- [ ] 要做的：**停止扩大云端存储范围**，并把边界写成一条可执行的规则。
- 裁决 G1（2026-09-19）：云端只存资产（模板 / 素材 / 用户设置）与智能体会话；**生成产出不再扩大上云范围**，项目画布、草稿留本机。理由：产出量大、一次性，继续上云会让对象存储占用按生成量线性增长，带宽与存储成本不收敛——这正是 [ADR 0002](adr/0002-sync-templates-assets-not-generation-records.md) 原本的取舍。
- **处置方式已裁决：只停止扩张，不回退删除。** 已上线的云端生成历史（`generation_images` / `media_objects` / `durableMediaStore`，前端 `CloudTaskTile` / `CloudGenerationDetail`）原样保留，不拆链路、不删用户既有数据。
- **会话不变**：裁决 F1「对话历史存服务端」原义保留。智能体运行时在 BFF 进程内（[ADR 0003](adr/0003-agent-runtime-in-bff-process.md)），流式 SSE、工具调用幂等与刷新恢复都依赖服务端会话；且吃存储带宽的是媒体原件而非文本。G1 不触碰会话。
- 本条推翻 [ADR 0007 生成原件长期保留与默认云同步边界](adr/0007-durable-generation-cloud-ownership.md)（accepted 2026-09-17），由 [ADR 0011](adr/0011-cloud-storage-limited-to-assets.md) supersede。
- 三条省成本杠杆（替代回退，按此顺序做）：
  1. **[#440](https://github.com/Muluk-m/ai-image-playground/issues/440) 无引用媒体回收与容量释放** —— #422 六片里唯一省成本的，从「全停」中捞回本道。
  2. **每用户原件配额 + 保留期**：把存储上限从「随生成量线性」变成有天花板，参数走 operator-config。
  3. **预览图分辨率降级**：`projectMedia.ts` 目前每张原件都生成 WebP 预览，这是带宽主项。
- 验收：不新增任何「把产出上云」的路径；存储成本随注册用户数而非生成量增长。

### B2 设备标识安全项（#312）

- [ ] 目标：智能体设备标识是纯 bearer，领养端点把「读」升级成了「永久占有」。
- 现状：`needs-triage`，但这是权限提升，不是体验问题。
- 验收：领养需要显式授权，读权限不隐式升级为占有。

## Lane C：电商图三件套

参考飞象（flyelep.cn）的 AI 工具箱形态，把三件电商高频编辑做成可被智能体稳定路由、且用户能直接点到的一级能力。
竞品逐家做法、字段全表与可抄 / 不抄清单见 [电商图竞品调研](research/ecommerce-image-competitors.md)。

**入口方式（2026-09-19 裁决）：先做交互原型（`/prototype`）对齐功能形态，再进 A4 的真实产出验证，最后才开发。** 不跳过原型直接按竞品结论开发。

**共同现状前提**：三条技能已存在但未验证（见 A4）；遮罩接缝（`MaskEditorModal` 的圈选 / 涂抹、`AgentReference.maskDataUrl`、`selectionBindings`、圈外像素按原图回贴）已落地，[masked-edit-intent.md](research/masked-edit-intent.md) 记录截至 2026-09-17 为未发布。所以这三项**不是从零做能力，是把已有接缝做实、拆清、给出入口**。

**共同待裁决（一次定，三项复用）**：

- **入口形态**：继续纯智能体路由，还是同时给一级入口（飞象 / 美图 / 即梦都有显式入口；即梦的教训是让用户自己判断需求属于哪个工具）。
- **参考图角色是否结构化**：是否引入 Adobe 的两个正交枚举 `Reference to`（Object / Whole image）×`Intent`（Swap / Place）。#669 已明确第一阶段不把 `imageIds` 拆成 `targetImageId` / `referenceImageIds`，动它就是推翻该裁决。
- **候选版本数**：即梦的局部重绘一次出 2–4 版再「应用」；我们现在 `n` 默认 1，改动直接影响每次扣费。
- **像素保真声明**：是否按 Photoroom 的做法，要求每条技能显式写出「这条会不会重画商品像素」。

原「候选方向 · 图片工具箱」（超分放大、抠图、去水印、扩图）并入本道——形状相同，不另起一处记。

### C1 局部重绘

- [ ] 目标：用户在画布上圈一块、说一句，只改这一块，圈外像素不动；出多版候选供选用。
- 现状：遮罩接缝已落地并做过对抗审查（[masked-edit-intent.md](research/masked-edit-intent.md)，含 16 类对抗案例与「圈外逐像素差异为 0」的实测记录），但没有作为一条具名能力对外出现，也没有候选多版对比。
- 涉及：智能体路由规则与新 SKILL、composer 的选区入口、`n` 与候选选用的交互、计费口径（多版 = 多张）。
- 参照：即梦「局部重绘」（矩形框选 + 笔刷双模式，一次 2–4 版再应用）、Canva Magic Edit 与 Lovart Mark/Touch Edit 的「点选即成选区」、飞象 `partial-redrawing` 的范围控制句「当用户目标是"小范围替换"时，提示词应避免写成整张图重做」。
- 验收：圈外像素逐像素不变；同名对象重复出现时只改被圈中的实例；选区不足以完成动作时先澄清而不是擅自扩选；候选未被选用不产生额外扣费。

### C2 场景替换

- [ ] 目标：主体一个像素不动，背景整个换掉；支持文字描述、场景参考图、以及批量逐张。
- 现状：`scene-swap` 技能已在，缺三样——参考图张数上限没写（`product-restyle` 写了「最多再放三张」，两条口径不齐）、失败归因全部指向提示词没有素材侧、没有场景预设。
- 涉及：`scene-swap` 正文补齐、场景预设是否入库（美图铺 40+ 缩略图、Pebblely 40+ 主题、稿定按节点+品类切）、批量逐张提交。
- 待裁决：抠图合成还是全图重绘。Photoroom / Claid / Shopify 走前者并据此给像素保真承诺；Pebblely 2026-03 明确取消抠图（「No more background removal」），理由是珠宝、发饰、透明瓶抠不动。我们现在是全图重绘，改路线要连带决定是否引入抠图能力。**由 A4 的失败率数据裁决。**
- 验收：主体的外形、颜色、材质、logo、包装文字、角度、位置与大小不变；「每张」「全部」时逐张独立调用，其它照片不自动变成参考图。

### C3 商品替换

- [ ] 目标：把画面里的商品换成用户自己的商品，背景、光影、构图、摆放位置全部保留。
- 现状：语义被 `product-restyle` 的「换主体」分支覆盖，但和「换颜色 / 材质」挤在同一条技能里。飞象（`product-replace`）、美图设计室（slug 同为 `/image-workshop/product-replace`）、稿定都把它拆成一级能力。
- 涉及：从 `product-restyle` 拆出独立 SKILL 并重划三条技能的互斥边界、目标商品图张数（飞象 ≤3、Photoroom ≤4、我们 `editImage` 参考上限 3）、多角度参考图一起给的写法。
- 参照：飞象三条示例全部以「保留……」开头，保留项写在替换项前面；美图把输入契约写成三段「替换哪个商品 / 保留的背景构图 / 需要匹配的光影和角度」；飞象的失败归因分「结果不像 → 参考图角度不足」与「背景不协调 → 保留项没写」两栏。
- 验收：新商品的颜色、材质、比例、logo、包装文字按参考图还原；原图的背景、光影方向、构图与摆放位置不变；同一背景批量换 SKU 时逐张独立提交。

## 已交付

- **0.1 计费单元泛化**（原 Phase 0）：模型单价带 `unit`，预扣接缝收 `quantity × unitMultiplier`。图片 `image`、视频 `second`（公开树 c2de35d，私有树迁移 0006）、对话 `kilo_token`（私有迁移 `0008_chat_token_pricing`）三种单元全部落地。`PrivateTaskHooks.reserveTask` 签名里没有 unit 字段，单价由服务端按 model 查表，新增单元不改公开树。
- **1.2 邀请注册奖励**（#414 / #418 / #419）：固定邀请码与邀请链接，双方默认各 200 分进可消费余额。
- **1.3 付费返利与积分提现**（#414 / #417 / #420 / #421）：默认 5%、100 积分/元折算，返利进奖励余额，手动全额提现为消费积分。
- **2.1 视频生成（部分）**：视频模式 composer、feed 与播放器（#189 / #190 / #191）；上游 Grok Imagine（含 `/videos/extensions` 续写与 `/videos/edits` 改视频）、Agnes `agnes-video`、火山方舟 Seedance 2.0（`doubao-seedance-2-0-mini-260615`，最长 15 秒、支持首尾帧，靠 `ARK_BASE_URL` / `ARK_API_KEY` 开关）。按秒计费已落地。
- **2.2 智能体模式**：对话式工作台 + 工具注册表（`generateImage` / `editImage` / `readLibrary` / `generateVideo` / `arrangeTimeline` / `loadSkill`）+ 服务端会话（裁决 F1）+ token 折算积分（裁决 E2）。**收口项见 Lane A。**
- **2.3 视频分镜（形态已变更）**：独立导演台与 `POST /api/storyboard/plan` 随画布视频二期（#634）下线；分镜改由画布上的智能体按镜头出片并排进时间线（#649）。**原 2.3 作为独立模式不再存在**，剩余工作并入 A3。
- **账户同步**（#176，2026-09-08）：登录用户的模板、素材（含图片本体）与用户设置跨设备同步。能力位 `accounts:sync`，两项素材配额走 operator-config。素材生命周期缺口见 #222。
- **活跃热力图**（#177，2026-09-08）：按天消耗的一年一屏热力图，账户面板、Admin 用户详情与概览各一张；数据只来自积分流水，私有树实现。
- **国际化**（#470）：工作台界面中英文，服务端错误按错误码在前端翻译（[ADR 0006](adr/0006-ui-trusts-error-codes-not-server-messages.md)）。
- **商品图工作流下线**（#643）：前端页面、状态机、执行工作流、端侧分割模型及 BFF 的 remix-analysis / remix-listing / matte 路由全部移除；旧任务在作品中按组只读展示。

- **1.4 拉新风控**：#414 已确认沿用现有注册资格并接受刷号风险，**不设排期**。规则起步（同设备 / 同 IP 段注册上限、一次性邮箱黑名单、奖励延迟 24h 可撤销、单邀请人日奖励封顶、异常账号冻结回收）留作日后独立规划。

## 候选方向（未排期）

- **作品分享页**：单张 / 单条作品公开链接，带邀请码，是拉新的天然入口。
- **每日签到 / 低余额提醒 / 套餐到期提醒**：留存三件套，邮件与站内通知复用 0.2。
- **提示词与模板市场**：把「模板」从个人 IndexedDB 升到可发布、可复制，付费模板抽成。地基已就位（#176），且服务端模板表本就是这条的地基（ADR 0002）。
- **付费用户队列优先级**：套餐用户任务排队优先，免费用户限并发。
- **开发者 API Key**：按积分计费的 HTTP API，面向小 B。
- **Admin 报表**：邀请漏斗、返利对账、积分流水导出、模型成本与毛利。
- **面向海外的三项**（界面已支持中英文，以下留到正式出海前）：
  - **货币与支付**：价格展示、充值档位与支付渠道目前只有人民币。
  - **灵感库内容**：案例的标题、说明与提示词只有中文。
  - **服务端生成文字与邮件模板**：智能体回复、工具卡标题、澄清选项和邮件没有错误码可查，要由服务端按用户语言生成，前提是 BFF 先知道界面语言。

## 已裁决

2026-09-07 确立；邀请规则 2026-09-16 更新；D1 与存储边界 2026-09-19 修订。

- **A2** 邀请人与受邀人默认各得 200 分，自动进入消费积分余额，双方额度独立可调；取代原双方各 500 分。
- **B1** 充值返利以积分计入奖励余额，用户手动提现为消费积分；注册奖励不经过奖励余额。
- **C2** 每笔符合条件的实付均参与返利，不设额外邀请关系期限；取代原绑定后 6 个月限制。最新规格为 #414。
- **D1** ~~视频首发顺序 Grok Imagine → Agnes → Veo，之后接 Seedance~~ → **2026-09-19 修订**：Grok Imagine → Agnes → Seedance 已落地；Veo 无限期推迟。
- **E2** 智能体对话按 token 折算积分。
- **F1** 对话历史存服务端。**与 G1 不冲突**：智能体运行时在 BFF 进程内（ADR 0003），会话必须在服务端；G1 约束的是产出媒体，不是会话。
- **G1（2026-09-19，新）** 云端只存资产（模板、素材含图片本体、用户设置）与智能体会话；生成产出停止扩大上云范围，项目画布与草稿留本机。理由是存储与带宽成本不能随生成量线性增长。**处置为只停止扩张、不回退删除**；已上线的云端生成历史原样保留，靠配额、保留期与无引用回收（#440）压平成本曲线。本条由 [ADR 0011](adr/0011-cloud-storage-limited-to-assets.md) 记录并 supersede ADR 0007。
