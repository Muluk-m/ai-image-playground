## 排序原则

**瓶颈不在 spec，在执行和验收。** 本文件的处置已在 tracker 上执行完（2026-09-20）：26 张票关闭，open 从 50 降到 24，其中实现切片只剩 #391 的 15 片、#634 与 #440。继续产 spec 只会加大堆积。

按准入标准分三条道，不按时间分 Phase：

| 道 | 准入标准 | 谁先走 |
| --- | --- | --- |
| **Lane A 收口** | 已经在向用户收钱、但没被验证或没闭环的能力 | 最先。A 没清空之前不往画布上加新能力 |
| **Lane B 地板** | 付费产品的不可失守线（钱、数据、成本上限） | 与 A 并行，但范围严格受限 |
| **Lane C 差异化** | 决定谁付钱的方向 | A 的成本敞口关掉之后 |

两条硬约束：

1. **已上线的能力未验证，就不许铺新能力。** 当前有两处未验证：长画布智能体任务的质量与总成本（#408），以及 `apps/bff/skills/image/` 下三条电商技能正文自己标着「示例级内容，尚未经过真实产出验证」。
2. **Lane C 与视频主线无依赖。** 电商三件套都走已有的 `image` 计费单元与 `editImage` 工具，不等任何视频能力。

## Lane B：地板

### B1 存储边界回到模板 + 素材（裁决 G1）

- [x] 已在的：登录用户的**模板、素材（含图片本体）、用户设置**跨设备同步（#176，能力位 `accounts:sync`，配额走 operator-config）。
- [ ] 要做的：**停止扩大云端存储范围**，并把边界写成一条可执行的规则。
- 裁决 G1（2026-09-19）：云端只存资产（模板 / 素材 / 用户设置）与智能体会话；**生成产出不再扩大上云范围**，项目画布、草稿留本机。理由：产出量大、一次性，继续上云会让对象存储占用按生成量线性增长，带宽与存储成本不收敛——这正是 [ADR 0002](adr/0002-sync-templates-assets-not-generation-records.md) 原本的取舍。

## Lane C：电商图三件套

参考飞象（flyelep.cn）的 AI 工具箱形态，把三件电商高频编辑做成可被智能体稳定路由、且用户能直接点到的一级能力。
竞品逐家做法、字段全表与可抄 / 不抄清单见 [电商图竞品调研](research/ecommerce-image-competitors.md)。

**入口方式（2026-09-19 裁决）：先做交互原型（`/prototype`）对齐功能形态，再进 A4 的真实产出验证，最后才开发。** 不跳过原型直接按竞品结论开发。

**共同现状前提**：三条技能已存在但未验证（见 A4）；遮罩接缝（`MaskEditorModal` 的圈选 / 涂抹、`AgentReference.maskDataUrl`、`selectionBindings`、圈外像素按原图回贴）已落地，[masked-edit-intent.md](research/masked-edit-intent.md) 记录截至 2026-09-17 为未发布。所以这三项**不是从零做能力，是把已有接缝做实、拆清、给出入口**。

**共同待裁决（一次定，三项复用）**：

- **入口形态**：继续纯智能体路由，还是同时给一级入口（飞象 / 美图 / 即梦都有显式入口；即梦的教训是让用户自己判断需求属于哪个工具）。
- **参考图角色是否结构化**：是否引入 Adobe 的两个正交枚举 `Reference to`（Object / Whole image）×`Intent`（Swap / Place）。#669 已明确第一阶段不把 `imageIds` 拆成 `targetImageId` / `referenceImageIds`，动它就是推翻该裁决。
- **候选版本数**：即梦的局部重绘一次出 2–4 版再「应用」；我们现在 `n` 默认 1，改动直接影响每次扣费。
- **像素保真声明**：是否按 Photoroom 的做法，要求每条技能显式写出「这条会不会重画商品像素」。

原「候选方向 · 图片工具箱」（超分放大、抠图、去水印、扩图）并入本道——形状相同，不另起一处记。

- [ ] 目标：用户在画布上圈一块、说一句，只改这一块，圈外像素不动；出多版候选供选用。
- 现状：遮罩接缝已落地并做过对抗审查（[masked-edit-intent.md](research/masked-edit-intent.md)，含 16 类对抗案例与「圈外逐像素差异为 0」的实测记录），但没有作为一条具名能力对外出现，也没有候选多版对比。
- 涉及：智能体路由规则与新 SKILL、composer 的选区入口、`n` 与候选选用的交互、计费口径（多版 = 多张）。
- 参照：即梦「局部重绘」（矩形框选 + 笔刷双模式，一次 2–4 版再应用）、Canva Magic Edit 与 Lovart Mark/Touch Edit 的「点选即成选区」、飞象 `partial-redrawing` 的范围控制句「当用户目标是"小范围替换"时，提示词应避免写成整张图重做」。
- 验收：圈外像素逐像素不变；同名对象重复出现时只改被圈中的实例；选区不足以完成动作时先澄清而不是擅自扩选；候选未被选用不产生额外扣费。

### C2 场景替换

- [ ] 目标：主体一个像素不动，背景整个换掉；支持文字描述、场景参考图、以及批量逐张。
- 现状：`scene-swap` 技能已在，缺三样——参考图张数上限没写（`product-restyle` 写了「最多再放三张」，两条口径不齐）、失败归因全部指向提示词没有素材侧、没有场景预设。
- 涉及：`scene-swap` 正文补齐、场景预设是否入库（美图铺 40+ 缩略图、Pebblely 40+ 主题、稿定按节点+品类切）、批量逐张提交。
- 待裁决：抠图合成还是全图重绘。Photoroom / Claid / Shopify 走前者并据此给像素保真承诺；Pebblely 2026-03 明确取消抠图（「No more background removal」），理由是珠宝、发饰、透明瓶抠不动。我们现在是全图重绘，改路线要连带决定是否引入抠图能力。**由 A4 的失败率数据裁决。**
- 验收：主体的外形、颜色、材质、logo、包装文字、角度、位置与大小不变；「每张」「全部」时逐张独立调用，其它照片不自动变成参考图。

### C3 商品替换

- [ ] 目标：把画面里的商品换成用户自己的商品，背景、光影、构图、摆放位置全部保留。
- 现状：语义被 `product-restyle` 的「换主体」分支覆盖，但和「换颜色 / 材质」挤在同一条技能里。飞象（`product-replace`）、美图设计室（slug 同为 `/image-workshop/product-replace`）、稿定都把它拆成一级能力。
- 涉及：从 `product-restyle` 拆出独立 SKILL 并重划三条技能的互斥边界、目标商品图张数（飞象 ≤3、Photoroom ≤4、我们 `editImage` 参考上限 3）、多角度参考图一起给的写法。
- 参照：飞象三条示例全部以「保留……」开头，保留项写在替换项前面；美图把输入契约写成三段「替换哪个商品 / 保留的背景构图 / 需要匹配的光影和角度」；飞象的失败归因分「结果不像 → 参考图角度不足」与「背景不协调 → 保留项没写」两栏。
- 验收：新商品的颜色、材质、比例、logo、包装文字按参考图还原；原图的背景、光影方向、构图与摆放位置不变；同一背景批量换 SKU 时逐张独立提交。

### C4 灵感库运营（已交付 2026-09-23）

- [x] 后台维护 showcase / template / skill 三类条目，带分类、封面、参考图、模型与发布状态；存量 563 条 / 22 分类已提供幂等导入。
- [x] 主站从 BFF 动态清单读取已发布内容，支持参考图、模板槽位与技能示例的「玩同款」。
- [x] 发布版本与操作审计写进 PostgreSQL；整份清单先维持现状，条目超过 1000 再分页或按分类分片。
- 定位：获客内容运营，不新增模型能力；不改变 Lane A 的收口优先级。

## 已裁决

2026-09-07 确立；邀请规则 2026-09-16 更新；D1 与存储边界 2026-09-19 修订。

- **A2** 邀请人与受邀人默认各得 200 分，自动进入消费积分余额，双方额度独立可调；取代原双方各 500 分。
- **B1** 充值返利以积分计入奖励余额，用户手动提现为消费积分；注册奖励不经过奖励余额。
- **C2** 每笔符合条件的实付均参与返利，不设额外邀请关系期限；取代原绑定后 6 个月限制。最新规格为 #414。

- **E2** 智能体对话按 token 折算积分。
- **F1** 对话历史存服务端。**与 G1 不冲突**：智能体运行时在 BFF 进程内（ADR 0003），会话必须在服务端；G1 约束的是产出媒体，不是会话。
- **G1（2026-09-19，新）** 云端只存资产（模板、素材含图片本体、用户设置）与智能体会话；生成产出停止扩大上云范围，项目画布与草稿留本机。理由是存储与带宽成本不能随生成量线性增长。**处置为只停止扩张、不回退删除**；已上线的云端生成历史原样保留，靠配额、保留期与无引用回收（#440）压平成本曲线。本条由 [ADR 0011](adr/0011-cloud-storage-limited-to-assets.md) 记录并 supersede ADR 0007。
