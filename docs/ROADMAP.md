# Roadmap

产品方向与排期的唯一记录。每项写清「目标 / 现状 / 涉及层 / 待裁决 / 验收」，动工前先按 openspec 流程出 proposal，
这里只登记方向与依赖，不写设计细节。进度勾选在本文件，追踪 issue 见 GitHub `roadmap` 标签。

## 排序原则

按依赖排，不按想到的顺序排。三条硬依赖：

1. **邀请奖励与返现必须先有邮箱验证**，否则 500 分注册礼就是刷号提款机。
2. **智能体、分镜、视频都要扣积分，而现有计费只认「张 × 模型单价」**。计费单元不泛化，三个新模式一个都接不进去。
3. **分镜的产出是视频提示词**，视频生成不先能用，分镜模式没有出口。

推荐顺序：底座（0.x）→ 账号与增长（1.x）→ 视频生成（2.1）→ 智能体（2.2）→ 分镜（2.3）。

## Phase 0：底座

### 0.1 计费单元泛化

- [ ] 目标：积分预扣 / 结算从「按张」扩成「按计费单元」，一个任务可以是 N 张图、N 秒视频、一轮对话或若干 token。
- 现状：`PrivateTaskHooks.reserveTask` 只收 `model + quantity`，模型单价定义是「每张图积分数」（见 `CONTEXT.md` 积分与套餐）。
- 涉及：公开树接缝 `apps/bff/src/lib/private-overlay.ts`、`packages/shared` 的任务协议；私有树 hold / settle / 模型单价表。
- 待裁决：单价表按 `model × unitKind` 维护，还是每个模式一张价目表。
- 验收：图片任务行为与流水不变；新增单元种类不改公开树。

### 0.2 邮件基础设施

- [ ] 目标：BFF 能发事务邮件（验证码、密码找回、返利到账、余额不足）。
- 现状：零发信能力；`users` 表只有 `username`（注册时拿邮箱当用户名），没有 `email` / `email_verified_at` 字段。
- 涉及：`packages/db` 迁移、BFF 发信 adapter（服务商经 env 配置，不硬编码）、模板、按邮箱与 IP 的发送限流、能力位 `accounts:email`。
- 待裁决：发信服务商（Resend / SES / SMTP 中转）。
- 验收：没配发信服务商的部署照常跑，只是邮箱相关能力关闭。

## Phase 1：账号与增长

### 1.1 邮箱验证码注册

- [ ] 目标：自助注册必须验证邮箱，验证码 6 位、10 分钟有效、单邮箱单 IP 限频。
- 依赖：0.2。
- 涉及：注册流程改两步（发码 → 验证 + 建号）；`accounts:self-register` 开启时强制；Google OAuth 注册视为已验证。
- 顺带：密码找回走同一套验证码，成本几乎为零，一起做。
- 验收：未验证邮箱不能建号、不发新人积分；一次性邮箱域名黑名单可由运营配置。

### 1.2 邀请注册奖励

- [ ] 目标：每个用户一个邀请码 / 邀请链接，被邀请人完成邮箱验证注册后，邀请人得 500 分。
- 依赖：1.1（奖励发放点是「邮箱验证通过」，不是「提交注册表单」）。
- 涉及：私有树 `referrals` 表（邀请人、被邀请人、绑定时间、奖励流水 id）、注册接口收 `ref` 参数、前端邀请页与分享链接、Admin 邀请漏斗。
- 待裁决：500 分给谁（见文末裁决项 A）；每人邀请奖励是否封顶。
- 验收：奖励走积分流水且可追溯到 `referral_id`；同一被邀请人只能绑定一次；自己邀请自己无效。

### 1.3 充值返现 5%

- [ ] 目标：被邀请人每次充值，邀请人得充值积分数的 5%。
- 依赖：1.2；充值成功事件（私有树已有充值流水）。
- 涉及：充值结算事务内追加返利流水；退款时对应返利撤销；Admin 返利对账视图。
- 待裁决：返积分还是返现金（裁决项 B）；返现有效期（裁决项 C）。
- 验收：返利与充值在同一事务内落账；退款可逆；报表能按邀请人汇总。

### 1.4 拉新风控

- [ ] 目标：让 1.2 / 1.3 不被薅。
- 规则起步：同设备 / 同 IP 段注册上限、一次性邮箱域名黑名单、奖励延迟 24h 发放并可撤销、单邀请人日奖励封顶、异常账号一键冻结并回收奖励。
- 涉及：注册与奖励发放路径、Admin 风控面板。
- 验收：每条规则可由运营配置开关与阈值，不硬编码。

## Phase 2：新模式

### 2.1 视频生成

- [ ] 目标：工作台新增视频模式：文生视频、图生视频，结果可预览、下载、进历史。
- 现状：整条上游链路只认图片（`extractImages` / `imageArchive` / 任务结果只有图片）；BFF 队列模式天然适合分钟级任务，直连 BYOK 路径不适合。
- 服务商分两批：
  - 首发：Grok Imagine 视频、Agnes `agnes-video`、Gemini API 的 Veo 3.x（Google 生视频走 Veo，异步 operation 轮询，需核实当前模型 id 与价格）。
  - 验证效果后接入：火山方舟 Seedance 2.x（字节，C 端即梦同源）。
- 涉及：BFF 上游 style 新增视频协议族、对象存储存视频与封面、任务结果类型扩成 `image | video`、前端 TaskCard / Lightbox 播放、计费按秒或按片（依赖 0.1）。
- 待裁决：首发服务商顺序（裁决项 D）；视频先只走 BFF 队列不开 BYOK 直连。
- 验收：一条视频任务在三家任一上游跑通并扣费结算；失败按原桶退回。

### 2.2 智能体模式

- [ ] 目标：对话式工作台，智能体能调工具（生图、改图、查素材库、套模板、以后生视频），每轮对话扣积分。
- 依赖：0.1（对话计费单元）。
- 涉及：BFF 新增对话任务类型（流式 SSE）、工具注册表、会话与消息存储、前端会话 UI；LLM 服务商经 channel 配置。
- 待裁决：扣费口径（裁决项 E）；对话历史存服务端还是继续存浏览器 IndexedDB。
- 验收：一轮对话 = 一条任务占用，工具调用内的生图按现有模型单价计入同一任务；余额不足在发送前拦截。

### 2.3 视频分镜与提示词模式

- [ ] 目标：输入一句创意或一段脚本，产出分镜表（镜号、画面、运镜、时长、台词）与每镜可直接投喂视频模型的提示词，一键送 2.1 生成。
- 依赖：2.1（出口）、2.2（它就是智能体的一个专业形态，结构化输出）。
- 涉及：分镜结构化 schema、分镜编辑器（表格 + 参考图）、按目标模型（Seedance / Veo / Grok）的提示词方言、批量送生成。
- 验收：分镜可编辑后逐镜或整体生成；提示词按目标模型切换方言。

## 候选方向（未排期）

有邮件与积分体系之后成本很低、或对增长有直接帮助的：

- **作品分享页**：单张 / 单条作品公开链接，带邀请码，是拉新的天然入口。
- **每日签到 / 低余额提醒 / 套餐到期提醒**：留存三件套，邮件与站内通知复用 0.2。
- **提示词与模板市场**：把现有「模板」从个人 IndexedDB 升到可发布、可复制，付费模板抽成。
- **图片工具箱**：超分放大、抠图、去水印、扩图，作为智能体工具与独立入口，按次计费。
- **付费用户队列优先级**：套餐用户任务排队优先，免费用户限并发。
- **开发者 API Key**：按积分计费的 HTTP API，面向小 B。
- **Admin 报表**：邀请漏斗、返利对账、积分流水导出、模型成本与毛利。
- **国际化**：拉新面向海外时前端多语言与邮件模板多语言。

## 待裁决项

回复编号即裁决。

- **A. 500 分给谁**：A1 仅邀请人 / A2 邀请人 500 + 被邀请人额外新人礼 / A3 邀请人 500 + 被邀请人首充翻倍。
- **B. 返现形式**：B1 返积分（推荐：闭环、无提现合规问题） / B2 返可提现现金。
- **C. 返现期限**：C1 永久 5% / C2 首年 / C3 仅首充。
- **D. 视频首发顺序**：D1 Grok → Agnes → Veo / D2 Veo 先（质量最稳）/ D3 三家同时接、按 channel 开关放量。
- **E. 智能体扣费**：E1 每轮固定分 / E2 按 token 折算 / E3 每轮基础分 + 工具调用按各自单价（推荐）。
- **F. 对话历史**：F1 服务端存（可跨设备、可审计）/ F2 浏览器 IndexedDB（沿用现状）。
