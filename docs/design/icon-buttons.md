# 图标按钮与提示规则

本规则是 Web（`apps/web`）、Admin（`apps/admin`）及其私有 overlay 的共享规范。
新增或修改图标按钮、工具栏、导航操作、tooltip 和相关组合件时必须遵守；两端的设计文档与组件文档引用本文件，不维护另一套提示策略。

## 显示规则

**用途一眼就能看懂的图标按钮只显示图标，不加 tooltip，也不为解释用途补可见文字。**
无障碍名称与可见提示分开处理：所有纯图标按钮仍保留简短、可本地化、随当前动作更新的 `aria-label`。
有 `aria-label` 不等于需要弹出同名提示。

| 情况 | 呈现要求 |
| --- | --- |
| 常见图标执行约定动作 | 保持纯图标，悬停与键盘聚焦均不重复提示动作名称 |
| 已有可见文字且含义清楚的按钮、菜单项、标签 | 不再弹出同名 tooltip |
| 图标不足以说明业务用途 | 悬停与键盘聚焦显示简短动作名称，例如「复用配置」「送入画布」「交换首尾帧」 |
| 需要说明禁用原因、上传限制、操作范围或快捷键 | 只提示控件上看不到的必要信息，动作名称与说明分开 |
| 文字实际溢出，或业务名称／参数值在窄屏被收成图标而无法判断 | 显示被隐藏的完整文字；常见图标动作仍遵守第一行 |

常见动作包括关闭 X、返回、搜索、新增、更多、复制、编辑、删除、下载／上传、附件、收藏、刷新、
撤销／重做、缩放、全屏、播放／暂停／停止、发送、音量、侧栏展开／收起、设置、筛选、排序、上下移动、
锁定／解锁和翻页。这是示例，不是仅限关闭按钮的白名单；判断依据是**实际用途与图形在当前上下文中是否直观**。
例如刷新图标表达刷新时无需提示；交换首尾帧应选对应语义图标并说明业务用途，不能借熟悉的图形隐藏不同含义。

收起导航后，无法从图标判断的业务目的地保留名称提示；普通侧栏开关不因位于导航中而恢复 tooltip。
禁用态需要解释时仍可查看说明，但不得因此恢复点击。按钮用途提示不额外附加无关的模型 ID、任务 ID、技能 slug 等内部标识；
Admin 业务字段已展示但被截断的 ID、容器或镜像标识仍可提示完整值，供排障使用。

## 组件接入

- 复用现有 `Button`、`Hint`、`TooltipIconButton` 及业务组合件。自动提示、显式包裹、原生 `title` 和自绘浮层都适用同一规则；不得换一种包装把重复提示加回来。
- 动作名称放在 `aria-label`，必要说明放在 `aria-description` 并通过现有提示接口展示；`aria-description` 本身不负责生成可见提示。`title` 仅用于必要说明，不填写与常见动作同义的文案来绕过抑制。具体接口见[组件用法](../../apps/web/docs/design-system/components.md)。
- 组合件透传无障碍名称与必要说明。对于确实需要可见提示的非直观图标，仅有 `sr-only` 文本不足以替代提示。
- 共用原语的判断由两端同名的 `icon-action-tooltip.ts` 与 `Button` / `Hint` 承担，保持字节一致。新图标或封装若未被识别，应修正共用判断或调用方式，不能把组件当前的默认表现当成设计例外。

## 评审与防回退验收

涉及图标按钮或提示的变更，评审时逐项说明新增 tooltip 提供了什么额外信息；只复述明显动作名称的提示应移除。
按影响范围验证以下行为，不把「每个图标都能弹出标签」作为通过条件：

1. 常见动作在鼠标悬停和键盘聚焦时均无重复 tooltip，保留可访问名称、焦点与原操作行为。
2. 非直观业务操作与必要说明仍可查看；响应式收起文字后按上述显示规则判断，不一律添加提示。
3. 修改共享行为时覆盖 Web 与 Admin 调用方式、自动提示与显式包裹，保持两端一致；沿用现有[图标提示回归](../../apps/web/src/__tests__/components/ui/iconActionTooltip.test.tsx)与[共享原语一致性检查](../../apps/web/src/__tests__/components/ui/parity.test.ts)。`icon-button-label` 门禁检查的是无障碍名称，不是要求可见 tooltip。
