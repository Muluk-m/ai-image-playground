## Problem Statement

用户经常需要在一次会话中提交几十至上百张图片，统一编辑、逐图检查或跨图比较。目前任意聊天附件和遮罩未必先转换为持久媒体引用；大量内联图片和同轮不断累积的视觉工具结果可能撑大请求体、上下文及内存，使发送或执行失败。

用户也缺少完整的批次交互：无法围绕一份固定范围统一确认、查看逐项进度、暂停后续派发、刷新后恢复，或区分明确失败和上游结果未知。简单放宽图片数量或把 base64 换成 URL，不能解决执行完整性、重复收费与恢复问题。

现有系统已经具备媒体上传与引用、视觉 token 估算、跨轮纯文字回放、按需看图、生成草稿、后台任务及恢复基础。本规格扩展这些能力，不假设每轮都会重新发送全部历史图片，也不从零建设通用任务平台。

## Solution

一次添加 100 张图片作为验收目标。先有界上传并校验，消息携带稳定引用；按用户任务读取必要视觉证据，同时限制视觉 token、最终模型请求字节与运行期内存。

用户进行批量处理时，系统固定完整范围和逐项计划，展示预估费用，支持一次确认、逐项执行、独立失败处理及持久进度。暂停停止后续派发，已提交工作继续跟踪；结果未知先核查，不能盲目重发。任何减少范围、丢失必要细节或近似比较都必须由用户明确选择。

分两阶段交付：第一阶段解决多图上传与请求可靠性；第二阶段交付完整批量执行、独立分析、暂停恢复及汇总。第一阶段的 100 张入口不宣称已经具备第二阶段的自动执行能力。

## User Stories

1. As an 已登录用户, I want 一次添加 100 张图片, so that 常见批量任务不需要手动拆成许多会话。
2. As an 用户, I want 从本地文件、画布、素材视角和批注结果添加图片, so that 不同输入来源使用一致的发送流程。
3. As an 独立会话用户, I want 上传附件不依赖云画布, so that 不建立项目也能可靠处理图片。
4. As an 用户, I want 看到每张附件的排队、上传、校验、就绪和失败状态, so that 我能知道发送前还缺什么。
5. As an 用户, I want 仅重试失败上传并复用已成功结果, so that 不必重复传输整批文件。
6. As an 用户, I want 全部附件就绪或由我明确移除失败项后才能发送, so that 系统不会偷偷遗漏图片。
7. As an 用户, I want 发送使用点击发送时固定的图片与参数, so that 上传期间继续编辑画布不会改变这次任务。
8. As an 编辑图片的用户, I want 原图、遮罩、编辑动作和区域信息保持配对, so that 系统处理的范围与我的选择一致。
9. As an 用户, I want 模型预览压缩不改变执行所用原件, so that 节省请求体积不会损害编辑身份和像素精度。
10. As an 用户, I want 大图、非法格式或校验失败得到明确反馈, so that 我能采取操作而不是遭遇无解释的失败。
11. As an 用户, I want 已发送上传附件随会话保留并计入统一容量, so that 回到旧会话仍能查看和处理输入。
12. As an 用户, I want 未发送附件只暂存且不自动加入素材库, so that 一次误拖入不会永久占用容量或污染素材。
13. As an 用户, I want 删除会话不误删仍被其他用途引用的图片, so that 其他项目和素材保持可用。
14. As an 用户, I want 多次看图时请求保持在预算内, so that 一轮对话不会越聊越容易超限。
15. As an 用户, I want 超限时获得具体原因和可选操作, so that 我可以决定缩小范围或改变目标。
16. As an 用户, I want 系统明确哪些图片已检查、哪些失败或尚未检查, so that 我不会把上传完成误认为分析完成。
17. As an 批量编辑用户, I want 对固定图片集合应用统一规则, so that 不需要逐张重复描述。
18. As an 用户, I want 确认前查看完整范围、统一规则、逐项提示词及预估总消耗, so that 我清楚授权了什么。
19. As an 用户, I want 一次确认整批生成计划, so that 不需要为 100 个独立目标重复点击确认。
20. As an 用户, I want 新增图片或修改规则后重新确认, so that 后续对话不能悄悄扩大已授权范围。
21. As an 用户, I want 重复点击和刷新后确认不产生重复任务, so that 不会重复生成或扣费。
22. As an 逐图检查用户, I want 每张必要图片有真实读取证据和结论, so that 汇总完整覆盖我的要求。
23. As an 跨图比较用户, I want 系统保留比较需要的联合证据, so that 分批处理不会悄悄变成近似结论。
24. As an 用户, I want 系统无法保证比较质量时先让我选择, so that 必要细节和范围不会被擅自降低。
25. As an 先分析再生成的用户, I want 分析前知道预估费用、生成前确认已经形成的逐项提示词, so that 每阶段的授权都有可审查内容。
26. As an 用户, I want 临时新增的付费补看进入新版本确认, so that 分析不会无限追加费用。
27. As an 用户, I want 查看批次和逐项进度, so that 我能区分排队、在途、成功、失败、阻塞及结果未知。
28. As an 用户, I want 刷新或断网后恢复批次进度, so that 不需要重新提交已接受的任务。
29. As an 用户, I want 一项明确失败时其他独立项继续, so that 局部问题不会拖停整批工作。
30. As an 用户, I want 余额不足、权限失效或通道不可用时暂停后续派发, so that 公共故障不会扩散为大量失败请求。
31. As an 用户, I want 只重试我选择的明确失败项并看到当前价格, so that 失败恢复范围和费用可控。
32. As an 用户, I want 上游结果未知时先查原请求, so that 网络中断不会导致重复生成和扣费。
33. As an 用户, I want 暂停批次后不再提交新项并看到已提交数量, so that 我知道哪些工作仍会继续。
34. As an 用户, I want 恢复仅继续未提交范围, so that 已有任务不会被重新创建。
35. As an 用户, I want 停止对话与暂停批次有独立入口, so that 我能分别控制回复和后台工作。
36. As an 用户, I want 明确看到分析、生成和对话复核的费用, so that 同一次调用不会在不同归属重复计费。
37. As an 用户, I want 涨价或预扣超出已展示预算时暂停并重新展示, so that 执行期间费用不会被静默扩大。
38. As an 享有对话免单能力的用户, I want 批量分析继续遵守既有豁免, so that 改为后台执行不会意外收费。
39. As an 用户, I want 结果进入发起时的会话体验和目标画布, so that 切换界面不会改变结果归属。
40. As an 用户, I want 汇总注明缺项和未知项且不把跳过算成功, so that 我能判断任务是否真正完成。
41. As an 运营人员, I want 按批次、处理项、尝试和上游请求核查状态与费用, so that 我能处理不确定结果而不盲目重发。
42. As an 运营人员, I want 删除会话后在途任务仍有必要结算证据, so that 系统能够正确收尾。
43. As an 部署维护者, I want 新能力受服务端能力门控并兼容旧消息和客户端, so that 可以分阶段发布与安全回滚。
44. As an 用户, I want 登录、生成权限和生成产物保留规则维持原有边界, so that 本次改造不会隐式改变账号与存储政策。

## Implementation Decisions

### 附件与视觉输入

1. 复用媒体上传预留、二进制 PUT、完成校验、摘要去重、访问授权及统一容量账本。提取不依赖画布的上传客户端；发话准备基于不可变发话快照，不在上传结束后重新读取当前画布。
2. 上传及完成确认分别限并发，同时限制解码像素和缓冲区。只有服务端 ready 才算完成；全部就绪后发送，或用户显式移除失败项。上传重试与付费生成重试分开。
3. 扩展媒体引用携带原件、遮罩身份、编辑动作与区域，保留旧内联归档读取。校验属主、ready、尺寸、方向及遮罩合法性；全部引用校验、认领与消息受理原子完成，发送命令幂等。
4. 100 张按逻辑参考图计数，与媒体对象数、视觉块数、处理项数、单任务产物数分别治理。原图加遮罩不止一个对象，局部查看可能产生多块视觉证据；不得按逻辑图数代替实际出站预算。
5. 已发送上传输入随会话保留、计容量，不自动成为素材；未发送附件使用显式短期租约。会话、素材、项目、在途任务或其他有效引用共同决定能否回收；仅清理新流程明确管理的对象，不能直接扫描删除旧历史“无引用”媒体。
6. 媒体认领与回收互斥。回收先锁定并检查引用/租约，标记删除中，再可重试地删除对象，完成后释放容量；不能先释放容量或允许删除中对象重新被认领。删除会话只解除自己的引用。
7. 新增统一视觉输入准备器，覆盖首轮、插话、看图、外部图片获取、商品图片获取、结果复核以及未来所有返回图片块的工具。证据记录来源、表示、尺寸及字节；模型视图与原件身份分开。
8. 工作集优先保留当前目标必要证据、活动选区与联合比较依赖；已用完的像素可以退出后续请求，保留身份和真实所得结论。占位符不能冒充视觉理解。跨轮已有纯文字回放继续使用。
9. 请求同时满足模型 token 安全预算和最终 UTF-8 HTTP body 字节预算。准备期保守估算，主模型在已有 fetch 注入边界检查供应商适配后的序列化 body；摘要独立 transport 和分析执行器也受同一硬闸。不能用字符串字符数或原文件字节数替代最终计量。
10. 本地拒绝必须阻止底层 HTTP 派发。每个逻辑调用单独记录拒绝原因，穿过 SDK 错误包装后仍输出本地预算错误；分离逻辑调用创建与真实 HTTP 派发计数，不能制造未知上游用量。主模型和新增付费分析调用显式关闭隐式重试；其他既有路径保留独立的重试政策，但每次派发都受计量。未支持的流式 body 表示不能绕过检查。
11. 超限先选择合适预览/局部、移出不必要视觉块，再使用已启用且语义等价的分批能力；仍不满足则返回结构化限制和选择。预览失败不能无界回退原件。第一阶段不依赖尚未交付的持久分析执行器。
12. 阈值由既有运营配置统一求值，前端读取能力与配额。除 100 张验收目标外，单图像素、字节预算、并发、派发窗口和附件租约时长在启用前按当前通道与资源验证，不把示例数值当供应商保证。

### 批次计划与执行

13. 批次是固定范围、确认和进度的稳定归属，处理项是可独立追踪的工作；批次可以跨轮。生成项复用现有后台任务，不把同一输入的产物数量参数改成 100 来代替不同图片的批量处理。
14. 新增持久批次、处理项、执行尝试、分析调用事实和分析结果结构。保存属主、发起会话/轮、体验及项目快照、计划版本/摘要、输入、提示词、参数、依赖、顺序、控制状态、派发代次、任务关联、调用事实及费用归属。批次确认命令、项内尝试序号和任务提交命令均有唯一约束。
15. 一次确认展示规则、完整范围、逐项提示词、模型参数与预计费用，固定计划版本及摘要。重复确认返回同一批次，旧版本确认返回冲突；修改范围、规则、像素或提示词产生新版本。已派发计划保持不可变。
16. 统一编辑按固定输入与规则分派；逐图检查必须覆盖每张必要图片；跨图比较保留目标所需联合证据。只有不会损失必要关系的任务才允许分解，不能把逐图摘要宣称为任何联合比较的等价物。
17. 先分析再生成分阶段授权：分析前展示分析预估，分析后基于真实逐项提示词确认生成。分析每项对应一次有界调用；临时补看进入新计划版本重新确认。汇总需模型调用时也作为明确分析项计量，确定性汇总优先使用代码。
18. 新增显式 analysis 任务类别，复用 Postgres、worker 进程和现有预扣/结算接缝，但使用专属 claim、租约、恢复、取消及终结路径。普通生成 claim 显式只接受生成类别，不能依赖调度查询恰好过滤；对话任务不改作异步分析队列。
19. 分析结果保存结构化结论、实际覆盖范围与媒体/区域/表示出处。分析终结不触发生图产物发布；任务查询、维护、成本分类及运营展示显式认识新类别。
20. 分开保存批次控制状态与执行进度：草稿、待确认、运行、暂停、关闭；逐项区分待处理、可派发、派发中、在途、成功、明确失败、结果未知和依赖阻塞。只有所有项均有确定结局才关闭；区分全部成功、部分失败、全部失败，显式放弃记跳过。
21. 派发与暂停使用同一批次行锁及派发代次。校验运行状态、版本、依赖、能力、预算后，同一事务创建实际任务、预扣并写幂等及批次关联；事务提交即已派发。暂停成功响应后无新项提交，此前已提交到队列的任务继续跟踪。
22. 派发窗口有界，不能预先把 100 项全部选出后在事务外继续提交。恢复重新检查能力、价格及输入，只处理未提交项；已经关联任务的项直接跟踪，不重新创建。
23. 记录 HTTP 派发意图及可用上游请求标识；提交后崩溃从关联恢复。发送与上游接收无法原子化，租约只防止旧执行者覆盖状态，不承诺上游 exactly-once。
24. 明确失败只由用户选定后创建新尝试，保留旧失败和账单。独立项失败不阻塞其他项；依赖失败阻塞下游；余额不足、鉴权失效和通道不可用等公共故障暂停后续派发。
25. 结果未知的处理项映射新增任务非终态 reconciling，保留预扣并先查询，禁止直接失败释放、自动重排或盲目重发。维护、取消、会话删除与租约回收均须认识该状态。查明后仅结算一次；无法查询时提供有依据、操作者和幂等命令的人工核查入口，不能因超时自动判失败。
26. 停止对话维持原语义，批次有独立暂停入口。删除会话原子停止新派发，并按既有取消语义处理已提交项，但保留在途核查与结算责任。
27. 批次解除已删会话的展示关联，未结算任务、尝试、调用、报价事实及必要输入引用不能随会话级联删除。结算后遵守既有审计和清理规则，只保留必要执行内容，不永久保存全部已删会话文字。

### 计费、接口与兼容

28. 整批确认不新增整批扣费；实际按任务逐项预扣、结算，批次只汇总账单。普通对话、独立分析、生成和结果复核的费用分别可追溯，每次真实调用只有一个计费归属。
29. 独立分析不能追加到已结算对话轮，也不能伪装成平台承担的摘要调用。复用 token 计价原语，建立独立调用账本；既有对话调用账本继续服务原轮，统一指标聚合但不重复生成可结算记录。
30. 分析沿用既有对话计费能力及免单豁免，生成费用保持独立。显示预计用量、预计实扣及实际费用；不以免费/付费版枚举代替服务端能力与登录门禁。
31. 持久保存基础单价、输出/缓存倍率、输入估算、输出预留、豁免及价格版本；取价和预扣受同一版本约束。重启不能按当前价格替换旧快照。未执行项涨价或所需预扣超出展示预算时暂停并重新展示；重试使用当前价格。
32. 沿用现有终态与用量结算合同，区分真实零用量和未知用量；不能按批次成功百分比结算，也不承诺缺失 usage 时能精确按实际收费。单生成任务内部多产物的部分成功不自动改成按张结算。本地拒绝不得冒充已派发未知用量。
33. 扩展现有媒体与发话接口；新增批次草稿、版本确认、汇总读取、稳定游标分页、暂停、恢复及明确失败重试契约。所有入口复用属主鉴权、能力与请求防护；命令幂等，冲突明确返回。
34. 复用持久事件/收件箱通道，补充批次、处理项标识及事件版本；断线可补读或重新读取状态。按批次聚合唤醒并复用现有预算，不能为 100 项各起一次付费复核；确定性进度更新不调用模型。
35. 结果跟随发起时 chat/canvas 体验与目标归属。批次卡展示上传、确认、执行、暂停、需处理及最终明细，不因当前切换画布而改投结果。
36. 先部署扩展协议、引用保护、预算计量及消费者兼容，再开启新入口；analysis/reconciling 的数据库约束、worker、维护、统计及计费接缝先完成兼容，生产者后启用。回滚关闭入口但保留新数据读取和结算，只能退到认识在途新类别/状态的版本。
37. 私有扩展按宿主面先扩展、扩展包再使用、验证锁定组合后启用的顺序交付，同时验证扩展包存在与缺席。沿用现有自动部署流程，不绕过发布门禁。
38. 遵守现有持久媒体、生成产物存储与后台任务架构 ADR：不新增外部工作流引擎，不扩大生成产物长期保留；本次明确新增的是上传会话输入随会话保留的规则。

## Testing Decisions

1. **主验收接缝是现有 BFF HTTP API → 真实测试数据库 → 真实任务认领/收尾 → mock 外部 transport。** 从用户发话、上传、确认、暂停、重试和查询观察结果；不 mock 批次服务内部方法来证明它调用了自身。对象存储使用已有内存替身，上游模型/生成服务使用可记录请求及编排响应的 transport 替身。
2. **优先复用现有测试先例。** 媒体接口集成测试已有用户会话、上传完成与不可变原件覆盖；Agent 请求预算测试已有从路由发话并记录实际出站的模式；生成确认测试已有重复确认、提示词和计费 hook 记录；后台任务辅助设施已经走真实 claim、lease、finish 来验证结算、事件及结果归属。扩展这些高层模式，不额外发明独立测试专用业务入口。
3. **测试外部行为，不固定实现细节。** 断言输入完整性、请求实际字节/次数、可见状态、产物归属、账单变化和重启恢复；不依赖内部函数调用顺序、私有集合形状或当前模块拆分。竞态通过可控响应与屏障触发，不依赖随意 sleep。
4. **少量浏览器验收补齐交互。** 覆盖 100 张上传进度、99 成功 1 失败禁止静默发送、失败重试/移除、展开逐项提示词、一次确认、暂停已提交数、刷新恢复及 chat/canvas 结果归属；不把所有服务端状态组合重复成浏览器用例。
5. **附件生命周期。** 覆盖不同来源、用户隔离、摘要去重、非法格式/超大像素、遮罩配对、上传后再次编辑、清理与认领并发、删除会话时在途引用、对象删除重试和容量仅释放一次。既有内联历史和旧客户端继续可读。
6. **请求与视觉预算。** 覆盖首轮、插话、看图、外部图片工具、商品图片工具、复核和摘要；使用中文、emoji、base64 及 SDK 包装错误验证 UTF-8 实际字节。超限底层 fetch 和真实派发计数均为零，保留本地诊断，不能虚增未知用量；必要联合证据与编辑身份不丢失。
7. **批次执行与并发。** 覆盖不同输入的 100 项、重复确认、过期版本、暂停与派发竞态、恢复、明确失败重试、依赖阻塞、公共故障暂停、创建任务后崩溃和上游接收后超时。任务、预扣、关联原子，结果未知不生成第二个请求。
8. **结算与核查。** 覆盖分析/原轮不重复计费、已有免单与非计费部署、零与未知 usage、持久价格快照、涨价阻塞、重复核查结算、reconciling 的取消/维护行为及会话删除后仍可核账。公开测试使用既有记录 hooks，真实收费扩展组合需其自身集成验证。
9. **完整覆盖与汇总。** 上传不等于看过；逐图分析每张都有真实证据，失败/未知/跳过不得算成功。精细联合比较超预算时返回限制和选择，不输出伪装完整的近似结果。新增付费补看必须形成新版本授权。
10. **迁移与发布。** 测试新旧引用、任务类别/状态、消费者先兼容、迁移回滚、扩展包存在/缺席和关闭新入口后在途收尾。数据库测试沿用独立数据库及每文件独立进程，BFF 使用 Bun、前端使用 Vitest；全量检查按项目 CI/远端资源规定执行。
11. **小范围低层测试仅补高层难以稳定触达的边界。** 例如字节编码、遮罩坐标和 token 算式，不镜像实现。并发内存与有效通道限制需受控测量，不能仅凭模型 mock 证明生产吞吐。
12. **上线证据。** 核验实际部署版本、登录、上传、历史读取与受控 provider 兼容；压力与故障矩阵用 mock 上游，不拿 100 次生产付费生成当自动验收。记录引用/视觉块数、最终 body 字节、真实派发数、覆盖与未知项、暂停原因和费用归属，诊断不得记录 base64、签名参数或鉴权信息。

## Out of Scope

- 新增匿名生图权限，或按前端版本名称重建权限系统。
- 把 100 张原图强行装进一次模型请求，或承诺任何精细联合比较都能自动完成。
- 静默漏图、降低必要细节、缩小范围或把近似比较说成完整比较。
- 本次扩展纯静态 BYOK 的批次执行能力；该形态继续沿用已有路径。
- 自动把会话附件纳入素材库，或扩大生成产物云端长期保存承诺。
- 强制所有供应商都使用文件 ID/URL，彻底禁止受控 base64，或声称改传输形式必然减少视觉 token。
- 引入新的外部队列/工作流引擎或用通用多 Agent 平台代替现有任务体系。
- 暂停批次保证取消上游已接受工作，或仅凭本地租约承诺上游 exactly-once。
- 自动重试结果未知的付费请求、在确认计划外自由扩张付费分析，或新增通用部分结算协议。
- 大规模迁移全部旧内联历史，或清理引用信息不完整的旧媒体对象。
- 本规格发布即开始实现、拆票、修改生产配置或执行付费压力测试。

## Further Notes

- 本规格源于已确认的十项产品决定：两阶段交付、按目标读取、100 张接收规模、既有权限、附件随会话保留、完整发送、质量底线、整批确认、独立失败与公共暂停、暂停仅停止后续派发。源码核查基线为公开提交 `3282d7c4`；源码证据不代表已完成生产复现或吞吐测试。
- 第一阶段依次闭合：通用附件上传与租约/遮罩引用 → 统一视觉准备 → 出站字节硬闸及诊断 → 100 张入口与旧历史兼容。第二阶段依次闭合：固定批次计划与逐项生成 → 独立分析与计费 → 完整恢复交互 → 联合任务与完整性汇总。批次初次开放前必须已有幂等、暂停和未知结果底座，不能推迟到后续阶段再补。
- 后续拆票应按可验收用户链路形成纵向切片，并显式表达依赖。该 Issue 是整体规格，不把内部实施顺序当作已经创建的 tickets。
- 已调研 13 个开源项目，除 Open WebUI、LibreChat，也覆盖 Cherry Studio、Jan、Chatbox、ChatALL、SillyTavern、AstrBot、AionUi、CoPaw、big-AGI、AIChat 和 Page Assist。借鉴的是媒体身份、预处理、视觉预算及供应商适配边界，不宣称这些项目普遍具备本规格的可靠批处理，也不推断闭源 ChatGPT 的内部实现。
- 当前规格未规定未测量的通道字节数、解码像素预算、并发窗口或租约时长。它们是实施前必须验证并写入运营配置的工程参数；功能准入要求所有出站路径受预算、拒绝时零派发，以及并发/幂等/计费/恢复验收通过。
