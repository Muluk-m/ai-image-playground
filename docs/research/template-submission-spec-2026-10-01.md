## Problem Statement

生成模式使用模板时，用户已经选齐素材，却可能在不知道的情况下少送图片并继续付费生成：模板允许最多 8 个素材位，组装器却另设 4 张输入上限并静默截断；参考图下载失败或缓存缺字节时也会被跳过，造成效果偏离和引用序号错位。

准备图片需要等待网络。在这期间继续输入、切换模板或修改模型，旧操作可能覆盖新草稿，或者把旧模板与新的模型配置混在一起。准备阶段连点发送还可能重复建立任务。用户需要完整、可解释且不破坏继续编辑的模板提交过程。

## Solution

模板沿用普通图片提交的统一输入准入，取消独有的 4 张限制。素材图与模板参考图必须完整；超限、缺失或加载失败时停止并说明原因，不静默减少输入。

点击发送时冻结这一次提交，之后的编辑属于下一份草稿。交互与现有 chat 的准备/发送体验保持一致：可以继续编辑，交接期间防再次发送，交接后不等待生成结束即可再次发送；保留生成模式原来的成功处理和清空设置语义。

离开生成页面取消准备中的操作，已经建立的任务继续执行。保留现有登录后自动续发，取消登录或主动离开则撤销本次待发送意图。

## User Stories

1. 作为使用模板的用户，我希望 5–8 个素材位的模板在完整输入符合统一准入时可以提交，以便不受模板专有 4 张限制影响。
2. 作为使用模板的用户，我希望填入的素材数量与素材位一致，以便每个素材位都有明确对应对象。
3. 作为使用模板的用户，我希望所有素材图都被发送，以便不会为残缺输入生成的结果付费。
4. 作为使用模板的用户，我希望模板配置的参考图全部保留，以便复现调好的效果。
5. 作为使用模板的用户，我希望完整输入超过上限时收到所需数量与上限说明，以便调整模板或输入后再提交。
6. 作为使用模板的用户，我希望输入恰好达到上限时仍可正常提交，以便充分使用现有能力。
7. 作为使用模板的用户，我希望同一图片作为素材和参考时沿用已有身份去重，以便不重复占用输入名额且不丢失引用含义。
8. 作为使用模板的用户，我希望不支持参考图的模型在生成前被拦截，以便避免无效提交。
9. 作为使用模板的用户，我希望模板钉住的模型不可用时明确失败，以便不会不知情地改用另一模型。
10. 作为使用预置模板的用户，我希望参考图下载失败时明确停止，以便不会得到悄悄缺参考的结果。
11. 作为使用自建模板的用户，我希望本地缓存缺失图片字节时明确停止，以便不会把残缺输入交给模型。
12. 作为使用模板的用户，我希望缺图、超时或损坏输入的错误指出相关图片，以便有针对性地修复后再次提交。
13. 作为使用模板的用户，我希望提示词引用序号与真正发出的图片一一对应，以便模型不会把参考图误认成素材。
14. 作为使用模板的用户，我希望每个素材仍按既有视角选择规则提供图片，以便本次修复不改变已熟悉的模板行为。
15. 作为使用模板的用户，我希望点击发送后固定本次文字、模板、素材、参数及模型配置，以便后续编辑不改变已发起的意图。
16. 作为继续编辑的用户，我希望准备图片期间可以输入下一份内容或调整附件，以便无需等图片加载完才能工作。
17. 作为继续编辑的用户，我希望旧操作结束或失败时不覆盖新文字和新模板，以便下一份草稿安全保留。
18. 作为使用模板的用户，我希望准备和交接期间连点按钮或重复按回车不会重复建任务，以便避免意外重复生成。
19. 作为使用模板的用户，我希望交接完成后恢复发送能力，以便生成进行中仍能主动发起另一笔生成。
20. 作为使用模板的用户，我希望主动再次发送是一次新操作，以便有意生成相似结果不会被长期按内容去重。
21. 作为使用模板的用户，我希望空输入时沿用发送/停止按钮取消准备，以便交互与现有 chat 一致。
22. 作为离开生成页面的用户，我希望准备中的提交被取消且草稿保留，以便离开后不会迟到建立生成任务。
23. 作为已建立生成任务的用户，我希望离开页面不取消该任务，以便它继续按现有生命周期完成。
24. 作为切换账号的用户，我希望旧准备操作不能借用新账号意外提交，以便账号边界保持清晰。
25. 作为未登录的用户，我希望完成此次登录后自动续发点击时的请求，以便不必重新填写内容。
26. 作为取消登录的用户，我希望本次待发送意图被撤销且草稿保留，以便以后登录不会突然提交旧请求。
27. 作为登录期间主动离开生成页面的用户，我希望不再自动续发，以便离页取消规则有效。
28. 作为发起了新操作的用户，我希望旧操作的完成或取消不解除新锁、不删除新的待发送意图，以便异步回调不会互相干扰。
29. 作为使用模板的用户，我希望成功后保留原有文字处理、模板移除及清空设置语义，以便修复不改变既有习惯。
30. 作为使用模板的用户，我希望组装后的长提示词不会作为中转覆盖输入框，以便始终编辑自己的原始内容。
31. 作为一次生成多张图片的用户，我希望数量和提示词槽位展开继续工作，以便无需退回单张生成来规避问题。
32. 作为使用提示词槽位的用户，我希望原有未填槽位、展开后总生成量与计费门禁仍生效，以便切换提交入口不会绕过校验。
33. 作为使用局部编辑的用户，我希望既有遮罩和目标图片校验保持有效，以便模板提交修复不会误用编辑材料。
34. 作为使用模板的用户，我希望图片准备失败时不建立生成任务或调用生成接口，以便失败在付费执行前结束。
35. 作为使用模板的用户，我希望失败后保留可修改重试的草稿，并保护已输入的新内容，以便不必重新组织素材与文字。

## Implementation Decisions

- 范围是工程路线图 B3 的 PR 1：生成模式的模板提交正确性。当前面谈结论直接进入本规格，不重新设计整个可靠性队列。
- 共享模板组装器删除独有 4 张策略，复用普通提交的统一准入。当前平台协议上限为 16 张，不把它宣称为所有上游模型的真实能力；沿用现有模型是否接受参考图的判断。
- 模板素材位数量上限保持原协议，不因修复删改已保存模板。完整素材和参考按已有稳定身份去重后做总量校验，不通过切片或容量循环舍弃必需输入；保留每素材的既有视角选择规则。
- 完整参考集合属于模板契约。本轮不新增可选参考字段、不自动降级为部分参考。不以临时 URL 文本相同或图片观感相似代替稳定身份判断。
- 解析函数只能返回完整材料或结构化错误。能在加载前完成的数量/能力校验提前做；媒体加载完成后再核对身份和最终输入顺序，生成引用与提示词。
- 模板提交协调层在首次异步操作前冻结文字、模板内容、素材视角、数量和槽位值、参数、遮罩及目标、实际使用的模型配置、账号/页面归属与本次操作身份。仅保存配置 ID 而随后读取当前可变配置不足以形成冻结。
- 复用既有显式提交入口和生成任务生命周期。补齐普通输入框入口已有的槽位完整性、展开后总生成量、遮罩/目标、模型可用性、账号与计费门禁，不复制另一套生成框架。
- 冻结业务意图不冻结授权。执行前仍检查当前身份与能力；失效时明确拒绝，不回退到新的活动模型或账号。登录后的自动续发仅通过已有待发送接缝完成。
- 不再通过先修改全局输入框再调用无参提交来传递请求。生成模式清空设置和模板提交原有成功行为继续保留，但旧操作仅能清理仍属于自己的草稿状态。
- 用有操作身份的准备/交接锁防重复点击与回车，旧操作的 finally 只释放自己的锁。期间输入与附件仍可编辑；交接给生成任务生命周期后释放门禁，允许另一笔主动生成。
- 对齐 chat 的交互规则，不复制其会话 inbox、乐观消息清空或整个草稿存储模型。空输入时沿用发送/停止按钮取消准备；取消生成任务与取消准备是不同动作。
- 准备取消的最后检查点在建立生成任务前，覆盖素材持久化等 await 之后。任务已经建立后，网络是否出站不再作为准备取消的依据；离页不撤销已建立任务。
- 登录后自动续发是离页取消规则的明确例外：完成本次登录恢复原请求；取消登录或主动导航离开则撤销相应待发送意图。恢复沿用完整性校验，消费待发送意图一次；旧取消不得清除后来另一笔意图。
- 保留既有多图和槽位展开。准备阶段只交接一次，正常扇出可建立多条任务；不能用“全局仅一条任务”作为防重复断言。单任务命令幂等不被扩张解释为所有多任务重试安全。
- 错误使用结构化原因，由前端按现有语言机制显示素材身份、数量和处理建议，遵守“界面只认错误码”的既有 ADR。
- 不改数据库、不扩大云端存储范围、不持久化新的凭据副本；原有任务、私有计费接缝、平台与 BYOK 运行路径继续复用。

## Testing Decisions

- 用户已确认包含行为测试的三张实施票拆分；各票以真实模板提交及现有认证恢复接缝验收。
- 主要测试从生成模式的模板发送交互开始，贯穿真实模板解析/组装、显式提交和任务建立，观察实际出站请求、创建的任务与用户可见草稿/按钮状态。尽量只在外部网络和媒体持久化边界使用替身，不 mock 掉被验证的组装器或显式提交入口。
- 正确性以外部行为衡量：缺图或超限时生成请求与任务数为零；成功时图片和提示词对应；准备期重复点击只产生预期的一次扇出；新草稿不变。不断言内部 helper 调用顺序、token 数值或复制实现逻辑的快照。
- 在既有共享模板组装器测试中补边界矩阵：5–8 个素材位、总输入低于/等于/超过统一上限、较小的显式上限、素材与参考身份去重、素材条数不符、素材无视角。把原有“超限仍截断成功”的测试改为完整性契约。
- 在主流程中注入首张/中间图片 404、超时、缓存缺字节和图片加载失败；断言无生成出站、错误可定位且不覆盖新草稿。成功样本检查图片真实顺序和提示词序号，而不只比较图片数量。
- 用可控 Promise/事件屏障固定异步竞态：解析期间打字、换模板、改模型；持久化完成前离页或取消；旧操作完成时新操作已开始。避免固定 sleep 和随机时序。
- 按真实交互验证准备时输入可编辑、发送受门禁、空输入时停止可用；交接后可再次发起，已有任务不因导航取消。覆盖清空设置分支和模板原有成功处理。
- 沿用现有认证启动恢复测试入口，验证登录自动续发一次、取消登录/主动离页不续发、旧取消不清除新意图。涉及登录重新挂载的测试使用已有 IndexedDB 替身与恢复入口，不新造认证模型。
- 沿用现有生成生命周期测试的网络队列替身和任务观察方式，覆盖原生多图、拆分多任务、槽位展开、总生成量上限、计费门禁及 BYOK 路径；只补本次改动触及的回归。
- 现有先例包括共享模板组装器测试、模板列表/提交前检查测试、普通生成 store 测试、generationJob 的真实队列出站测试、chat 草稿新旧状态保护测试及认证启动恢复测试。主流程当前缺少完整模板异步提交覆盖，新增在现有前端测试组织内，不引入新框架。
- 前端使用现有 Vitest，共享组装器沿用现有 Bun 测试。外部上游全部模拟；本机仅相关指定测试、单 worker，全量验证按仓库约定交远端/CI。测试计划不代表本次已执行或通过。

## Out of Scope

- 下线闲置批量端点、批量命令协议、批次表或跨刷新恢复尚未交接完的整批意图。
- Agent 画布读取与编辑来源统一、对象冲突检测和执行回执。
- 请求编译器、可选参考图选择界面、文字排版导出或成套任务产品能力。
- HTTP 请求已经发出但回执未知后的恢复，以及现有“重试”新建任务语义的改造；不承诺本规格解决网络重试重复生成或扣费。
- 通用模型能力矩阵建设、后台自动重试、调用尝试账本、归档/取消结算状态机改造。
- 给普通生成引入 chat 服务端排队、未发送消息列表或新的云端草稿存储。
- 改变用户模板模型自动回退策略、模板素材位协议上限、已建立任务的取消规则。
