## 登录重设计范围

基线代码的主要入口是 `apps/web/src/auth/LoginDialog.tsx`，当前有作品拼贴、利益点介绍、表单双栏；本次检索未发现独立 LoginPage 或 `/login` 路由，因此独立登录页作为新官网配套承载面规划，不将其描述为已经存在的独立路由。

设计提案：同一套表单在完整登录页与弹框中复用；独立页可以有作品展示，弹框优先保持紧凑。覆盖登录、注册、邮箱验证、可选邀请码、第三方登录、等待、错误及注册关闭状态；登录方式和能力开关沿用当前后端，不凭视觉稿增加短信、Apple 或其他未配置方式。官网登录成功进入现有首页；工作台内被账号门禁拦截的操作仍沿用原有恢复语义，不因官网的无 prompt 流程而删除已有待发请求机制。

本轮制作三套可点击首屏与登录原型，比较完整页、弹框和窄屏效果。原型不连接认证或生成 API，素材使用仓库现有静态图片，仅演示构图与轻量转场，不将其当作已准备好的视频成片。

## 指南迁移澄清

用户问“为啥保留 guide 这些纯 html”。这里的建议是保留已有 URL 与有价值的内容，指南的页面组件、布局和渲染实现迁入 TanStack Start，与官网统一设计，不保留旧手写 HTML 渲染器。SSG 构建结果仍会是 HTML，这是交付形式，和保留旧实现是两回事。保留原路径或提供重定向的具体迁移映射仍待页面规划确定。

## 本仓库事实（只读，基线 54e17380）

- guide 已是构建期整页静态渲染，包含双语独立章节、搜索索引、canonical、hreflang、OG/Twitter、JSON-LD；见 `apps/web/src/seo/vitePlugin.ts` 和 `apps/web/src/features/guide/render.ts`。
- 工作台首页仍依赖客户端渲染，静态入口的正文主要是空 root；新官网的收益是可直接抓取的产品内容与清晰转化路径，不是“首次采用 SSG”。
- `/`、`/image` 当前共用创作入口，OAuth 回调返回 `/`。根路径归属改变后必须一起梳理回调、待发恢复、guide CTA 和 canonical。
- `pendingSubmission.ts` 已通过 IndexedDB 保存待发请求，sessionStorage 标定发起标签页；现有消费采用取出与删除的同一事务。可复用，但不等价于跨网络端到端 exactly-once。
- 当前默认 `createTarget` 为 `generate`；对话和画布另走 Agent 项目创建。按最新官网方案，登录后进入现有首页，不改变其默认创作模式。
- 当前 `CONTEXT.md` 的入口段落与部分代码存在漂移：文档写两模式，代码已有对话/生成/画布；本记录不把历史描述当作新增方案约束。

## 技术与 SEO 核验

- [TanStack Start 官方静态预渲染文档](https://tanstack.com/start/latest/docs/framework/react/guide/static-prerendering)支持构建时输出 HTML，符合静态托管方向。SPA shell 本身不等于含正文的 SSG 页面。
- 本次直接读取 [npm latest 元数据](https://registry.npmjs.org/@tanstack/react-start/latest)：版本 `1.169.2`，Node `>=22.12.0`，Vite peer `>=8.0.0`；实施时须重新核验并锁定依赖。尚未做兼容性构建，不能把文档支持等同于本仓库已集成可用。
- 不预渲染账号、项目或私有业务数据；官网静态内容与浏览器登录态分开处理。官网与工作台同源可以继续使用同源待发存储；不同子域需要额外交接协议。
- SEO 提案：有正文的 HTML、可抓取内链、每页独立 title/description/canonical、语言互指、sitemap、真实 404、旧地址保留或明确重定向。依据 [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) 与 [多语言页面指南](https://developers.google.com/search/docs/specialty/international/localized-versions)。
- 动效不能挡住正文或创作按钮，移动端与减少动态效果设置需有退化方案。SEO 排名与转化改善需上线后测量，不能由框架名称保证。

### 设计判断与下一版草案（尚未由用户确认）

- 当前叶片山水过于直接地把品牌的芽绿解释成植物，容易偏向自然景观品牌；同图裁切、缩放及灰度对比没有表达图片/视频创作的能力。应重新选作品主题与构图，而非继续补装饰动画。
- 首屏：墨绿与芽绿主导的超现实创作画面，明确主体和视觉冲突；主标题控制在一行短句，保留一个创作 CTA 与少量作品缩略图。品牌色主导封面、界面和光线，不要求每个案例整体染绿。
- 滚动第一段：首屏作品缩入作品带，其他独立案例进入视野；用户可以选中作品放大。此为本项目拟议动效，不声称是竞品已经验证的滚动实现。
- 滚动第二段：一个案例从参考素材展开为不同构图，再进入成片；拖动对比、切换方案需要呈现真实不同的画面。未准备好视频时明确标注静态分镜预览，不把静态缩放当作成片。
- 收尾与认证：创作 CTA 打开紧凑登录浮层；独立登录页使用同一表单和统一品牌视觉。延续已确认的登录后进入现有首页语义。
- SEO 正文由场景页、指南及有意义的下屏短说明承接；核心标题和链接仍在 HTML 中，不藏到动画、Canvas 或视频像素里。
