# 遮罩编辑：最小可执行约束契约与对抗审查

> 初始独立研究/审查记录。后续实现和实际验证状态见 [主报告](../masked-edit-intent.md#7-实现与当前证据)，本附件不代表最终代码或验收结果。

## 结论

现方案是“视觉提示 + 自由改写 + 上游单张目标 mask”。它能改善理解，不能保证不篡改用户意图、参考区域被遵守或圈外像素不变。更强的思考模型同样不能替代约束。最小闭环应为：不可变请求快照 → 结构化编辑计划 → 服务端校验 → 一次生成 → 输出检查 → 候选结果。语义不明确时澄清；不因检查失败自行再花钱生成。

只读依据：`apps/bff/src/lib/agent/selection-preview.ts`、`turn.ts`、`tools/editImage.ts`、`tools/queueTask.ts`、`upstream.ts`。未执行测试，未调用付费生成，以下为待实现契约。

## 1. 不可变请求快照

由服务端保存，不接受 LLM 修改：

- `editRequestId`、用户原文 `userText`、原消息 ID、请求版本；插话产生新版本，不覆盖旧意图。
- 当前引用的图片 ID、实际输入字节 hash、方向规范化后的尺寸；名称与展示编号只作标签。
- 每个选区的 ID、所属图片 ID、原始 mask hash、坐标尺寸、alpha 语义与选区版本。
- 一轮已确定的模型/参数、允许生成数量与计费授权范围。

工具参数引用这些 ID，不可提交任意图片替换绑定。文字哈希只能证明原文未变，不能证明派生提示词忠实；不得用“原文保留了”替代语义检查。

## 2. 编辑计划最小结构

`targetImageId`、`targetSelectionIds[]`、`operations[]`、`references[]`、`boundaryPolicy`。

每个 operation 至少记录：目标选区、对象说明、动作（移动/替换/调整属性/删除等）、用户指定属性与值、原文依据。参考项至少记录：图片 ID、参考选区 ID、使用属性（造型/位置/颜色等）。不得把“参考此物体”自动扩为“复制整张参考图的布局与风格”。

选区是允许编辑的最大范围，不是必须全部修改的命令。具体对象与属性服从用户原文；未要求变化的文字、背景、其他对象即使在选区内也应保持。多个选区既不意味着所有同名部件全局替换，也不意味着只改最显眼一个。

计划可以由 LLM 生成，但 ID、版本、mask 绑定由程序校验；对象与文字意图的对应关系无法仅靠 schema/关键词确定。明确歧义才询问，不把每次编辑都变成确认表单。

## 3. 硬边界与软边界必须区别

**硬边界模式（用户说圈内修改/其他不变时默认）：**

- 提交原图和目标 mask；仅此不构成保证。
- 若产品要承诺圈外像素不变，输出应按批准的编辑区域与原图合成，圈外复用原像素。羽化只能在已授权区域内部。
- 无合成保障时只能声明“要求保持圈外内容”，不能宣称技术上锁定。
- 合成仅保证边界，不保证圈内其他内容或对象改对。圈内背景仍需语义检查。

**软边界模式（仅在用户明确允许时）：**

- 可为阴影、遮挡、反射、背景修补批准一个额外影响区域，具体区域/边距可视化并入新版本。
- 不能因模型说“为了自然”自行扩大 mask，也不能默认扩张到全图。

移动对象通常需要旧位置修补区 + 新位置区 + 过渡影响区。用户只圈了旧物体而要求移出选区时，应先澄清/扩选；硬裁切会造成截断、残影或重复对象，不能把这种失败包装成严格保留成功。

## 4. 参考区域必须成为实际输入

当前蓝色 overlay 只给思考 LLM 看，`editImage` 实际生成仍接收完整参考原图、单个目标 mask。参考选区仍依赖 LLM 的文字转述，复杂产品细节容易损失。

最小改进：生成输入包含服务端按参考选区制作的 ROI 图，保留少量明确上下文，并以稳定顺序/编号说明各图作用；需要空间关系时保留完整参考图作辅助。原图、ROI、目标 mask 都不能混用。不要把蓝色覆盖图直接当产品素材，否则可能复制蓝色。

不规则选区的矩形裁切仍包含圈外内容；孤立透明抠图又会失去尺度、支架与安装关系。ROI 提供事实定位，不等于语义保证。重复部件、多视角含糊时仍需澄清。

## 5. 服务端确定性检查

生成前：引用必须属于请求快照且可访问；目标不由数组偶然顺序决定；mask 可解码、方向/尺寸一致、alpha 语义正确、非空、大小在资源限制内；全图选区允许但不能由模型偷换生成。目标与参考角色必须显式；不支持 mask 的上游直接拒绝，不静默丢弃。

操作范围只能引用用户提交/批准的 selection；LLM 不得生成新 selection 或扩大边界。未知对象/动作字段进入澄清。LLM 提示词由服务端从原文与计划组装，减少自由文本重写权限，但不得声称程序能证明自然语言等价。

提交前按请求版本检查插话/取消状态；已提交的在途任务保持原版本，新意图不得串入旧任务或导致重复收费。幂等键绑定一次明确生成操作，不以内容相同阻止用户主动重做。上游结果未知时先恢复查询，不盲目重提。

## 6. 何时澄清

仅在阻碍正确执行时：目标/参考角色不明；一个 mask 覆盖多个候选对象而原文无法区分；参考位置/角度无法从图片确定；文字要求与硬边界冲突；要同步哪些视角不明确；mask 无法读取或选区不见。

禁止以猜测替代澄清：例如把“参考头枕位置”自行写成“降低至椅背上沿”。不应为无关风格、所有参数逐项追问。

## 7. 输出验证与费用边界

先做无额外生成费用的检查：解码/尺寸、与目标完全相同的输出、圈内外差异统计。完全相同可明确标记未改；差异显著只说明像素变了，不能证明对象改对。损失压缩、重采样会导致全图微差，阈值应区分解码像素与文件 hash，不能以一个通用差异阈值判语义成功。

硬合成前记录原始候选圈外变化，合成后检查边界；不让合成掩盖上游失控或裁切失败。保留原图与候选，不自动覆盖源图。

若增加独立视觉验证，分别判定每个明确操作、保留项与参考匹配，输出通过/失败/不确定；它仍是概率判断，也有费用与延迟，需纳入预先声明的预算，不默认为“免费”。未验证统一称候选图；失败/不确定如实显示，不宣告已准确完成。

验证失败不自动调用编辑工具再次付费生成。用户主动重试、或事先明确授权了有限重试预算，才允许新生成；不得通过换 tool call ID 绕过。每次生成的请求版本、费用、结果必须可追溯。

## 8. 过度约束的代价与选择

- 完全复制原文但不解析指代，会把 @14 等展示编号误送上游；应保留原文，同时补显式 ID/角色映射，补充不等于改写设计意图。
- 硬圈外锁定牺牲阴影融合和大位移自然度；允许用户扩选/批准影响区，比静默软化边界可靠。
- 禁止所有推断会让正常替换不可用：透视、光照与接缝适配可作为目标范围内的必要实现细节，但不能改变产品属性或越过边界。
- 同一产品多视角替换通常需要统一几何/外观，在多个已授权区域共同生成；逐区独立生成可能造成款式不一致。不能为“一致性”自动修改未圈中的真人场景头枕。
- 单个 mask 可表示多个不连通区域，但没有区域级操作绑定；计划需要一对多映射，不能简单把连通区域数量等同对象数量。

## 最小落地顺序

1. 不可变请求/引用绑定 + 计划结构 + 禁止自动付费重试，保留当前提示词改进。
2. 参考 ROI 实际输入与 mask 能力校验；当前头枕案例作为固定人工验收样例。
3. 候选差异检查、明确未验收状态；评估硬合成在位移/阴影用例的失效后再开放边界模式。

验收必须覆盖：圈内两个示意头枕都改、真人后头枕不改；圈内无关文字保留；移动出界触发澄清；多个参考选区不串；插话不串版本；失败不追加收费。仅检查 prompt 含某句话不能证明以上行为成立。
