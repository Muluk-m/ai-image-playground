## 结论

当前改动解决了“LLM 完全看不到圈选”和一部分错误指令，但没有建立可执行的编辑契约。唯一蓝色覆盖图是有损定位通道，参考圈选仍经 LLM 自由描述，最终工具只有 prompt + imageIds + 第一张 mask。提示词不能保证不越界、不漏对象、未改部分不漂移。应将它视为第一层语义改进，而非已完成精确局部编辑。

特别要区分三个概念：用户想修改的对象；允许发生像素变化的范围；期望参考的属性。三者不能由一个 mask 隐式等同。

## 结构攻击点与改进优先级

### P0：执行前必须有可检查的不变量

1. `mask` 绑定 `imageId + imageRevision/hash + dimensions + alphaConvention`，绝不能仅靠同尺寸判断可复用。
2. 解码后校验选区面积、通道、尺寸；错误应为可恢复输入错误，而不是整轮通用失败。全选允许但与“全部修改”分开。
3. 明确 edit target 和 reference roles。考虑新增结构化 `EditIntent`：用户原话、目标图版本、选区ID、操作、参考来源/区域、转移属性、保留要求、未解歧义。用户原话不可被生成摘要覆盖。
4. 程序检查只能验证 ID/几何/字段一致性；不能把结构化输出当语义已正确。模型仍能填写一份自洽但错的契约，必须保留语义评估。

### P1：让“参考选区”成为真实数据

- 当前只传给LLM的蓝色图不应替代原图。定位图与原图（或局部原图裁片）分工：前者说明哪里，后者说明长什么样。
- 裁片传输需稳定映射与显式角色，不能随意追加图导致编号和目标第一张发生变化。
- 多不连通mask不能一律取总bbox后就说“已隔离”：总bbox可能包进大量未选内容。可先按语义邻近分组，保留mask或背景淡化定位。
- 不建议将蓝色叠层直接作为生图参考，这会把人工标记颜色带到结果。

### P1：结果契约与可观测性

- 记录目标/参考版本、mask覆盖率、region边界、模型档位、原话与工具最终prompt，避免记录图片base64进日志。
- 输出验收分开：修改是否完成、保留是否满足、范围是否越界。外区像素diff是报警指标，不是普适失败判据（压缩/色彩变化会误报）；几何对齐后评估，OCR辅助文字，关键对象仍需视觉评估。
- 不能为了“外区必须相同”无条件硬贴回原像素：位移、阴影、遮挡连续性可能被切断。若产品承诺严格局部像素编辑，须单独定义允许的边缘融合带并说明限制。
- 验收失败不可无限自动重试收费。先明确最多重试次数与计费策略；当前可先保守称候选结果、让用户指出差异。

## 验收设计

- 程序层：所有上述 P 断言以合成确定性mask/图像完成；覆盖初次、插话、历史恢复、新产物迭代四条路径。
- 语义层：每例保留固定原图/参考图/真实圈选/用户原话，记录结构化意图与最终prompt。对快速/中等/深度各档做重复评估，不只看一次成功。
- 视觉层：评审不看模型自述，只看源图/选区/指令/输出，分别标“目标正确、动作正确、参考正确、保持正确”；有一个严重改错对象即失败。
- 合成单元测试与scriptedAgentFetch只能证明线路/参数，不证明真实LLM会遵循提示。
- 原始头枕案例必须作为必过回归：左侧两处都更新，右侧真人头枕、文本、箭头保持要求，参考ROI正确；同时增加“只改左一处”反例，防止针对案例硬编码成改两个。
