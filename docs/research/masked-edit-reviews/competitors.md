# 局部遮罩编辑竞品调研：约束意图，而不是替用户补意图

> 初始独立研究/审查记录。后续实现和实际验证状态见 [主报告](../masked-edit-intent.md#7-实现与当前证据)，本附件不代表最终代码或验收结果。

调研日期：2026-09-17。范围：仅官方文档与官方产品设计访谈；未试用生图，未读取任何竞品私有系统提示词。以下“建议”是本项目设计推论，不是竞品实现事实。

## 一、五项一手证据

### 1. Lovart：先标记具体实例，再描述动作

来源：[Advanced AI Editing](https://www.lovart.ai/docs/edit-your-design/advanced-ai-editing)，页面未列更新日期，访问 2026-09-17。

- 官方交互：Mark / Touch Edit 识别、标记点击的具体元素，标记进入输入框；同一次请求可有多个标记，最多 10 个。
- Edit Elements 则将画面拆成可独立移动、缩放、旋转的部分；官方把它与自然语言局部编辑区分。
- 证据性质：产品工作流与数量限制；不构成像素保持保证，也未公开目标定位算法或系统 prompt。
- 对本项目启发：同一个“头枕”在画面出现三次时，名词不是唯一标识。目标应是“图 14 的选区 A、B”，而不是由模型重新选择最显眼的一处头枕。精确移动也不能擅自退化成外观替换。

### 2. Adobe Photoshop：引用什么，与怎样使用，分开表达

来源：[Use reference images for consistent results](https://helpx.adobe.com/photoshop/desktop/create-open-import-images/create-images/use-reference-images-for-consistent-results.html)，更新 2026-08-18，访问 2026-09-17。

- Firefly 工作流先有目标选区，再上传参考；Reference to 区分 Object / Whole image，Intent 区分 Swap / Place。Place 明确保持背景。
- 合作模型是另一个流程：输入详细提示词后上传参考；该页记载 Flux 最多 3 张、Gemini 最多 8 张。
- 证据性质：特定产品、特定模型的 UI 能力，不是通用 API 协议。不能认为所有底层模型都支持相同控制。
- 对本项目启发：目标图、目标区域、参考图、参考区域、用途必须分开。“参考图有遮罩”不能等价为“这也是待编辑图片”。“参考位置”也不能自动扩为“参考整张图的风格和结构”。

### 3. Adobe 设计研究：参考强度滑杆不能代替意图澄清

来源：[Behind the design: Adobe Photoshop Reference Image](https://adobe.design/ideas/behind-the-design-adobe-photoshop-reference-image)，页面未列发布日期，访问 2026-09-17。

- 官方团队披露四轮研究：用户对文字与参考图如何共同影响结果持续困惑；仅调整“Strength”等控制不足以解决问题。
- 最终简化为上传参考、选取参考中的具体部分、决定替换还是放置；团队也承认精确选区与生成结果曾有明显落差，需要改进模型对选区的敏感性。
- 证据性质：官方研究结论；不是当前质量基准或内部提示词公开。
- 对本项目启发：思考深度是模型配置，不能替代编辑契约。先固定用户授权的改动，再让推理服务于执行。不要让“更深思考”变成更自由的美术指导。

### 4. Recraft Studio：选区定义作用域，小选区可能导致变化不明显

来源：[Inpainting](https://www.recraft.ai/docs/recraft-studio/frames/inpainting)，页面未列更新日期，访问 2026-09-17。

- 官方流程为选图、Edit area、圈定区域、描述更新、生成；宣称替换选区并保持其余画面。
- 文档同时指出：选区过小可能导致变化细微；大图会缩小后编辑，连续多次编辑可能降低质量；该页工作流目前标为旧界面功能。
- 证据性质：产品承诺与已公开限制。不能用该描述担保我们当前模型严格保持选区外像素。
- 对本项目启发：无变化除了 prompt 之外，也可能是有效区域、坐标或缩放错误。不能通过未经授权扩大遮罩“修复”。区域不足以完成移动时，说明所需范围并请求用户调整。

### 5. Recraft API：遮罩语义是明确的协议，参考语义不能脑补

来源：[Endpoints — Image inpainting](https://www.recraft.ai/docs/api-reference/endpoints#image-inpainting)，页面未列更新日期，访问 2026-09-17。

- 官方规定白色像素为重绘区域，黑色为保留；请求以 image 与 mask 配合 prompt；当前文档将该操作限定于 V3 / V3 Vector。
- 这属于 API 输入契约；它不证明其它模型的 mask 也使用相同黑白/透明度语义。
- 对本项目启发：每个上游适配器应明确 mask 的表示、尺寸与关联目标。一个通用 MASK 标签无法表达目标可改区与参考提取区两个不同概念。
- 局限：本页不能作为“多参考区域均被上游支持”的证据；缺少对应参数时，必须在我们自己的适配层实现参考裁切/标注等能力并验证。

## 二、本项目可采用的内置提示词约束（设计建议）

1. **以用户原话为改动边界。** 可把代词绑定为稳定图 ID 和区域 ID；不得新增移动方向、幅度、结构、风格、对象替换等用户未授权的变更。
2. **遮罩限制的是实例和区域，不是泛指类别。** 同部件重复出现时，只改目标图里被选中的实例；“头枕”不能匹配到右侧人物身后那个未选实例。
3. **分别解释目标遮罩与参考选区。** 目标遮罩表示允许改变的位置；参考选区表示从哪里提取用户指定属性。不得把后者当作第二个待编辑目标，或静默丢弃。
4. **把保留约束限定为未授权内容。** 不能写“两个参数卡片不变”，因为卡片内就是目标；应写“卡片中的文字、箭头、背景保持；圈定的头枕按要求修改”。没有看清这些元素时，不得编造这份清单。
5. **参考属性最小化。** 用户只说位置，就不自行替换材质、款式或整张图风格。若“位置”实际可能指款式/部位，而图和选区不足以判定，问一个窄问题；不要用“更低、更贴近”猜测。
6. **视觉证据不足时不得假装看过。** 必须实际给 LLM 目标区域与参考区域的可见表示；仅“用户画了遮罩”这一句无法支撑“左边两个头枕”的推断。
7. **生成成功与编辑成功分开。** 未检查输出时只报告结果已生成，不声称目标已正确移动、圈外完全没变。对抗验收必须包含改错实例、遗漏一个区域、参考区漏传、圈外变化、无变化。

## 三、可机器校验的最小编辑契约（建议，不要求额外用户表单）

```text
originalUserText: 原样留存
editTarget: imageId + targetMaskId
referenceSources: [{imageId, referenceRegionId?, allowedAttributes}]
requestedOperation: 用户实际要求的操作；不确定就保留原话
scope: selectedInstancesOnly
preserve: outsideTargetMask + 未获授权的属性
unsupportedCapabilities: 当前上游不能实现的语义
```

原话与契约一起进入工具层；不得完全以 LLM 自由重写 prompt 替代。工具层验证目标存在、mask 绑定、输入图片序号映射和参考区域可用性。多个不相连选区允许同时编辑，但不能据此自动泛化到所有同类物体。

## 四、对抗结论

- 仅加“严格遵守用户意图”很容易失效：模型可能先错认对象，再严格执行错误对象。必须让目标实例可见、可定位。
- 仅加“保持其它不变”可能更糟：若模型把整个参数卡片列为保留区，会直接与遮罩冲突。
- 仅换更强 LLM 无法修复参考选区被丢弃、mask 反转或上游不支持；更强模型也可能更流畅地合理化错误。
- 仅做圈外像素回贴不能证明任务完成：会隐藏越界生成，但目标仍可能没改；头枕移动还需给新旧位置足够区域。
- 三家公开资料支持“显式作用域、参考角色、动作类型”的设计方向；没有资料能证明照搬某段提示词可保证这个案例成功。
