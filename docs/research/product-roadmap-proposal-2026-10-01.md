# Muvloom 产品迭代路线图草案

> 用户已要求改为工程与技术方案视角。后续审阅以 [工程改进路线图](./engineering-roadmap-2026-10-01.md) 为准；本文保留为产品目标背景，不作为实施排期。

日期：2026-10-01。代码核对基线：`168b5107`。状态：**供审阅的优先级建议，不是已批准的排期**。

依据：[竞品研究](./competitive-landscape-2026-10-01.md)、当前实现及现行 [ROADMAP](../ROADMAP.md)。本文件不覆盖现行路线图、不改变 ADR、不创建实施票；方向确认后再把接受的项目归并到唯一正式路线图，避免两份排期长期并存。

## 1. 产品目标与排序依据

**先让用户更容易得到想要的结果，再让结果容易改、能交付、下次能复用。**

近期核心应是对话式视觉创作的质量与完成体验。商业验证先选“小型品牌/电商运营的商品视觉”作为样本场景，因为已有素材、模板、套图和批量实现；这只是优先验证的客群假设，不将全产品提前锁死为电商工具。前两轮的改进同样服务海报、社媒和普通图片任务。

排序按四项判断：用户任务被阻断的程度、发生频率、现有实现可复用程度、证据确定性。没有使用缺少用户数据的精确 RICE 分数。P0 先做，P1 随主流程推进，P2 满足触发条件后做；同级按编号排序。

北极星指标建议：**用户一周内实际采用的完整创作任务数**。必须记录用户明确采用/使用的反馈；下载只能作代理指标，不能直接算真实采用。配套看整套合格率、人工修改时间、每套可用成本、第二次任务复用情况，生成次数只作过程量。

## 2. 当前不足：已有部分和真正缺口分开

| 问题 | 当前已经有 | 真正不足/证据缺口 | 用户后果 |
|---|---|---|---|
| 意图到画面的落差 | 设计意图字段、澄清、art-direction 和领域技能 | 缺少同题验证证明“表达/焦点/风格”确实进入产物；方案和最终效果缺少可检查的对应 | 反复解释“不是这个意思”，多次重做 |
| 局部修改可信度 | 选区绑定、输出对齐、保护区、预览精修 | 各路径/分辨率下保护范围、错误应用与恢复的完整实证不足 | 改一处时担心损坏已满意部分 |
| 精确文字与版式 | 画布标注、图片对象属性编辑、海报技能 | 生成图中的标题、价格、Logo 缺少已证实的独立设计结构；套图技能默认不生成文字 | 视觉有了，仍需到另一工具排字、改规格 |
| 成套任务完成感 | 多次生成、批量端点、任务状态与 ZIP 导出 | 缺少已证实的“图的角色—商品—采用版本—最终文件”统一交付体验 | 散图需要人工整理，局部失败难判断是否整套完成 |
| 复用质量 | 多视角素材、用户模板、预置模板、模型绑定 | 复现质量未量化；品牌事实/规范与某次提示词、效果模板的边界不够明确 | 下次换商品仍要重新调，重复说明品牌规则 |
| 首次价值不明确 | 创作、探索、项目、资产和工具箱 | 定位很宽，尚缺任务式引导有效性的用户证据 | 新用户看到很多能力，却不知道第一件该做什么 |
| 交付信任 | 消耗、后台任务、失败恢复及部分云记录 | 保存范围的文档口径不一致，实际完成/计费/取回的一致性需继续验证 | 不确定花了多少钱、任务是否完成、作品是否还在 |

上表中的“缺少证据”不等于已查明线上故障，也不自动要求重构。先验收已有实现，仅修复观察到的缺口。

## 3. 总路线图

| 顺序 | 优先级 | 迭代主题 | 最小交付 | 依赖 | 工作量判断 |
|---|---|---|---|---|---|
| R0 | P0 | 建立质量与用户基线 | 固定任务集、现有流程对照、失败分类、初步用户观察 | 无；立即开始 | S，数据准备决定耗时 |
| R1 | P0 | 让 Agent 理解目标并落实到画面 | 需求到创作约束的闭环；有歧义时给具体方向，产物按目标复核 | R0 首批失败样本 | M |
| R2 | P0 | 连续改稿可信 | 目标/保护范围清楚、候选可对比和回退、商品事实核对 | R0；可与 R1 分阶段推进 | M–L，受失败原因影响 |
| R3 | P1 | 精确文字和最小版式编辑 | 新创作的背景、商品、Logo、文字分开；直接改字和位置并导出 | R1/R2 第一批验收；先原型验证 | L，先做技术/交互探针 |
| R4 | P1 | 完整套图交付 | 图的角色清单、采用版本、局部补做、尺寸/命名/打包 | R1/R2；带文案版本依赖 R3 | M |
| R5 | P1 | 下一次任务真正复用 | 商品事实、轻量品牌资料、经验证效果、换 SKU 复用与结果回归 | R4 样本；排版规则依赖 R3 | M |
| R6 | P1 | 首次成功与第二次使用 | 少数任务入口、真实案例、直接带入素材、成本说明与复用引导 | 随 R1–R5 逐项落地 | S–M，持续工作 |
| R7 | P2 | 外部审阅与小团队 | 经授权的审阅链接/意见/采用确认，随后才考虑角色与权限 | 重复出现客户交接需求；存储/访问边界裁决 | M–L |
| R8 | P2 | 从合格图片延伸短视频 | 从已确认商品/风格出短视频，保持事实并完成简单成片 | 图片任务复用和质量成立；真实视频需求 | M–L，仅指增量探索 |

S/M/L 是相对工作量，不是工期承诺。没有确定投入人数与数据准备情况，所以按完成标准安排迭代轮，不给虚假的发布日期。已有视频修复与验收继续按现行计划执行；R8 控制的是新增扩张。

**可靠性并行线**：钱、作品和状态方面的已确认故障立即优先；维护任务追踪、费用核对和既定存储治理。不新造一套运行时，也不以“完善基础设施”为由无限阻塞质量与用户验证。

## 4. R0：先知道问题出在哪里

**范围**：收集 10 个真实商品样本，覆盖包装/硬表面、透明反光、服装难例；每个做意图表达、局部改稿、成套任务，共 30 个任务。任务可复用现有 A4 素材，别再维护第二套互不相通的评测。先跑一次找问题，对变化较大的案例再重复验证。

同时观察约 5 位目标用户完成自己的任务，记录现用工具、需要的交付格式、卡点和返工。用户数是探索规模，不能据此宣称统计显著或已证明市场需求。未取得合适授权的客户图片不作为共享测试资产。

**输出**：每题的输入、预期表达、不能变化的事实、实际输出、人工修改分钟数、模型/版本、所有尝试费用。失败分为理解、审美/构图、商品事实、编辑破坏、执行/交付、排版六类。

**验收**：形成能复跑的基线和按影响排序的前三类失败；每条结论可追到样本。不强制等所有竞品采购完再改本项目：先用我方现状与用户旧流程，随后加入 Lovart、美图、Photoroom/飞象等相关对照。

## 5. R1：先解决“懂了话，没做对图”

当前 `design-intent.ts` 已把表达信息、焦点、视线、氛围加入提示词；要验证和改进的是整条路径，不是再加一段很长的系统提示词。

**最小范围**：

- 对明确任务，识别用途、画面表达、主体、必须保留项、参考图角色，直接继续创作；不增加每次必填的表单或确认墙。
- 对真正存在分歧的任务，给 2–3 个具体方向，明确构图和视觉重点。可用既有案例辅助理解；额外生成方向预览涉及费用时先说明，不默认自动多出几张。
- 用户选定方向后，后续图和改稿沿用同一组约束；插话能更新相关约束，不清空所有已确认内容。
- 首轮结果按目标检查，区分“生成成功”“表达达标”“待用户确认”。模型复核只作辅助，不自证质量。

**验收**：同题对比当前基线，用户判定的目标表达达标率上升，达到可用结果的澄清/重做次数下降；商品事实错误率和总费用不能被隐藏。若瓶颈是素材或模型能力，应明确归因，不无限调提示词。

**停止条件**：两轮针对性修改仍不能改善主要失败，先调整素材要求/模型路由/任务边界，不继续堆技能文案。

## 6. R2：让每次改稿保住已完成的工作

**最小范围**：

- 用户当前选中的图和区域明确成为修改目标；参考图不会被当成待改对象。复用现有选区绑定和发话快照。
- 区分“只改背景/局部”和“允许重绘商品”两种任务语义；仍由 Agent 理解，必要时给用户一个简短选择，不要求用户理解算法。
- 保留原版，能比较和采用候选、撤销采用；不把“候选未采用”自动解释为免费生成。
- 增加合适的原图对照与事实检查入口：Logo、字标、颜色、比例、件数。先人工确认，不先开发通用品质评分大系统。
- 对保护失败、生成失败、交付失败给不同恢复动作；恢复沿用既有任务和计费链路。

**验收**：覆盖重复同名对象、缩放、透明边缘、错误选区、刷新与切项目。确定性合成路径在约定工作像素坐标中保护区差异为零；不能将其宣传成任意原图分辨率/所有编辑路径像素不变。用户取消/拒绝应用后原图仍可用；费用与任务对应，重复操作不重复提交。

**取舍**：保真合成和生成式重绘可并存，由任务和样本选择。不能先承诺“主体像素完全不变”，再用全图重绘实现。自动付费重试暂不扩张，必须先具备每次上游尝试、结算与预算的完整记录。

## 7. R3：让确定的信息可以直接改

**用户故事**：一张活动图已满意，只把“¥199”改成“¥169”，背景、商品和其他文字不变化，不必再调用生图。

**先验证**：用真实任务做小原型，确认用户是否需要在产品内完成这些操作，以及现有画布对象能否承载。复用已有文本/图片对象，检查字体、缩放和导出的限制，再决定新增结构。

**最小范围**：从新创作开始，将背景、商品/Logo 和标题/价格保留为独立对象；支持文字内容、字号、颜色、位置、基本对齐和锁定；指定尺寸导出合成图片，并在当前保存策略允许范围内保留编辑结构。

**验收**：中文、英文、长标题、价格与多尺寸样本均不溢出/缺字；改文字不产生生图费用；导出与预览一致；锁定对象不被其他编辑修改。字体来源和可使用范围清楚，不能随意打包未知授权字体。

**首期不做**：任意历史位图完美拆层、完整矢量绘图、专业印刷、PSD 全兼容、自动把所有生成图转成可编辑稿。这些会显著扩大工期，且不属于第一个用户故事。

## 8. R4：把散图变成一套明确交付

当前已有 `/api/looks/batch`、独立任务与 ZIP。要补的是用户能管理和确认的“整套结果”，不是另建批量引擎。

**最小范围**：一套任务显示主图、卖点、细节、场景等角色；每项对应商品、当前状态与采用版本；只补失败/未达标项，不重跑已满意图片；按用途命名并打包，导出前核对数量、尺寸和需人工确认的商品事实/文字。

**验收**：例如要求 6 张时，界面明确区分已生成、已采用、失败、待做；全部采用且导出成功才算交付完成。刷新和部分失败不丢关联；打包数量和清单一致。依赖平台规则的规格仅采用已核实规则，用户自定义尺寸不冒称平台认证。

**不做**：自动上架、全平台规格数据库、投放效果承诺。先完成可取走的交付包。

## 9. R5：把首次满意转化为下次更快

**最小范围**：沿用现有素材和模板，补足三个层次：商品事实（型号、实际文案、不能变的要素）、品牌基础资料（Logo、色值、字体、禁用表达）、效果配方（已认可样本、构图/图的角色、模型与参数）。用户可看到继承项并覆盖本次例外。

模板更新要能辨别版本；模型失效不悄悄替换，升级后用已认可样本回归。先提供少量经过验证的任务配方，不以模板数量为目标。

**验收**：同一用户第二个 SKU 无需重新输入相同品牌信息；保留新商品真实差异；减少操作和返工。建议初步门槛是第二次同类任务的中位人工时间比第一次下降 30%，同时事实错误不增加；这是待校准的产品试验目标，不是行业标准。

新字段涉及资产存储和配额时，遵守现有接缝及云存储范围；不借此恢复已否决的全量产物云同步。

## 10. R6：让用户一开始就知道能完成什么

**最小范围**：围绕已经通过验证的任务展示少数入口，例如“给这件商品换场景”“做一套商品图”“修改现有海报”；案例展示输入、完整输出和后续修改，不只展示最好看的一张。选模板/案例后直接带入创作，复用已给的素材。

不重做全部导航。生成、对话、预览和画布继续承担各自工作；用户不应为了完成第一次任务先学习模型、技能和模板的区别。

在当前任务里说明预计消耗与追加费用条件，完成后引导保存素材/效果供下次使用。真实支付是否阻碍完成要观察，不根据购买页面代码直接启动支付重构。

**验收**：观察首次到达可用结果所花时间、在哪一步退出、第二次是否自行找到并复用资料。暂不以注册量、页面点击或生成次数替代任务完成。

## 11. 迭代轮次与准入条件

| 轮次 | 主交付 | 并行的必要工作 | 下一轮准入 |
|---|---|---|---|
| 第 1 轮 | R0 基线 + R1/R2 各修一个最主要失败 | 观察首批用户；核对已确认的计费/交付问题 | 有可复跑样本，知道主要瓶颈，修复有结果证据 |
| 第 2 轮 | R1/R2 收口为少数可信任务；R3 小原型 | R6 让用户直接进入这些任务 | 连续改稿可用，用户确实需要精确排版 |
| 第 3 轮 | R3 最小编辑 + R4 套图交付 | 对照用户原工作流 | 用户可交付完整任务，文件与采用状态一致 |
| 第 4 轮 | R5 复用 + R6 首次/再次使用 | 重复任务陪跑与单位成本核算 | 有主动重复使用，复用节省人工且成本可接受 |
| 第 5 轮以后 | 根据真实需求选择 R7 或 R8 | 继续质量回归和成本治理 | 外部交接或视频需求反复出现，而非仅因竞品已有 |

小原型可以提前探索，较大的正式开发需等前置问题收敛。每轮根据样本重新排序；例如排版已成为第一阻断点，R3 可在 R1/R2 达到基本可用后提前。

## 12. 与现行 ROADMAP 的衔接

| 现行项目 | 本草案如何处理 |
|---|---|
| A1 对话/后台任务 | 复用已实现能力，发现回归再修，不从头重做 |
| A2 成本与上下文 | 保留必要成本实证与保护；不扩为无边界的 Agent 平台工程 |
| A4 电商真实验证 | 提升为 R0 入口，与 R1/R2 的失败回归共用样本 |
| C0 素材与模板 | 已有实现不能按旧勾选重复建设；转向 R5 的效果验证与复用收益 |
| C1/C2/C3 局部编辑、场景、商品替换 | 归入 R2 的任务语义与验收，复用既有入口；多候选计费单独明确 |
| B1 存储与回收 | 保留已定边界和必要治理；先核验现状，不因文档未勾选判定没做 |
| B2 身份安全 | 现行文件内部存在旧状态残留，实施前核验代码和 issue，不直接重复排入“未完成漏洞” |
| A3/A5 视频 | 已承诺修复和验收不取消；新增视频扩张按 R8 准入 |
| C4 灵感、C5 工具箱 | 维护已有成果；扩展需要证明能带来目标用户的创作采用，优先级低于主流程 |

现行文档还有两项需要在正式归并时澄清：场景替换“主体像素不变”与全图重绘的能力边界；候选生成费用与“未采用不额外扣费”的准确含义。不能让草案默认改变既有计费或质量承诺。

## 13. 暂不扩张的方向

- 没有具体任务缺口驱动的模型接入和通用技能扩容。
- 全套设计软件、任意位图自动拆层、完整 PSD/印刷系统。
- 模板交易市场、社区、签到等尚未证明支持核心复用的增长功能。
- 企业实时协作和复杂审批；先验证客户审阅需求。
- 自动投放、ROAS 优化与全渠道上架；当前缺少业务数据闭环。
- 长剧/全能剪辑生产线；先完成已承诺视频能力，再看明确需求。

维护和修复不受此限制。优先级调整的依据是用户重复出现的任务和可验证收益。

## 14. 第一批应形成的三个可审阅成果

1. **失败样本与诊断报告**：说明 Agent 误解、模型能力、素材、编辑或交付分别造成了什么问题。
2. **一条连续改稿样例**：同一商品/海报连续改三次，正确内容可保留，每次可回退，费用与结果可核对。
3. **一个精确文字编辑原型**：改价格/标题不重新生图，确认用户需要和可行范围后，再进入正式排版开发。

以上是后续实施产出，不是本次已经完成的功能或实验。正式开工仍按项目约定先把适用的产品决策、原型和规格收敛。
