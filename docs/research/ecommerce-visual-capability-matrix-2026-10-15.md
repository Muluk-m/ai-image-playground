# Muvloom 电商视觉能力矩阵与补齐优先级

调研日期：2026-10-15（Asia/Taipei）。我方代码基线：`2bcbd06126e79792c025ad84da1b025d473dda8c`。本轮只读调研，交付研究文档；没有修改产品代码、运营配置或路线图，没有运行生成或部署。

## 1. 结论与阅读方式

**先补齐电商日常交付的基线，再完善成套生产和细分场景。当前重点不是再建一个通用 Agent、画布或批量系统，而是把已有能力补成可预测的商品图交付流程。**

本报告沿用本次讨论确定的方法：完整盘点垂类能力 → 对照现有实现 → 区分基础缺口与深入能力 → 排补齐顺序；不把此前的“套图复用”假设当成已经确定的产品定位。

关键结论：

1. **日常图片处理并非空白。** 我方已有本地批量压缩、格式、尺寸、裁剪、拼图、长图拼接与切图，以及画布局部修改和下载。应复用现有实现，重点补一致性和产品入口。
2. **透明抠图是“不一致”，不能简单记成有或无。** 部分可达流程有生成绿幕后转 alpha 的实现，单图快捷入口则交给 Agent。需要统一输出契约，验证真实透明、主体细节、修边和失败反馈。
3. **精确文字与合成导出是确定的结构缺口。** 现有文字节点/标注不能直接等同于可交付海报中的文字层；画布图片导出取各图片原文件，并不合成画布上的文字。价格、规格、Logo 与商品图组合后可准确修改和导出，应先补。
4. **AI 批量计划已有较完整实现。** 审稿、报价、依赖、暂停/续跑、局部重试和导出已在代码中；实际开放受能力配置控制。下一步应复用它承接套图/多商品任务，不另起一套批量基础设施。
5. **套图、模板、品牌库、改稿、批量都已有竞品覆盖。** 它们是应研究与选择的能力，不能仅凭名称宣称独有。可竞争的地方是达到同等交付要求时更省操作、更少返工、更可靠，仍需同题实测。

阅读顺序：先看第2节范围与证据口径，再看竞品矩阵；我方44项对照表用于补齐排期，末尾的优先级与验收用于决定下一步。细粒度来源和代码行号放在同目录附件中；另附44行CSV，便于筛选优先级。

## 2. 范围、证据与比较规则

覆盖17个重点产品/产品组：国内5个（美图设计室、稿定、绘蛙、飞象、万相营造），海外商品视觉5个（Photoroom、Pixelcut、Flair、Pebblely、Claid），相邻设计工具5个（Lovart、Canva国际版、Adobe Express/Photoshop产品组、Figma Buzz、Recraft），平台内替代2个（Shopify、Amazon Ads）。千牛/京东等若公开信息不足，只列补充观察，不凑覆盖率。

“完整”指覆盖商品视觉的输入、清理、生成、修改、成套、复用、批量、交付和业务连接全过程；不宣称穷尽全市场，也不把每家所有非电商功能纳入。

证据等级：

- **D：官方操作文档/API。** 可以确认特定功能的输入、操作和限制，不等于输出效果已测。
- **P：官方产品页/目录。** 证明厂商公开提供或宣传此入口；参数、质量与账户可用性可能未知。
- **U：本次公开界面观察。** 只证明入口可见，不证明生成成功或付费能力可用。
- **C：我方当前代码与调用链。** 区分用户入口、Agent技能、底层实现及运行配置；不是生产部署和质量验收。
- **?：未取得足够证据。** 不代表不支持。未查证的项保留未知，不据此宣称独占。

本轮未购买竞品、未做同题出图，未读取实际用户订单、收入、使用频次或上线率；因此不排名画质、速度、每套实际成本和转化率。已写的优先级是基于任务依赖、明确缺口和目前已知用户用途的产品建议。

套餐、地区、Beta、API与Web的边界分开写。Adobe多个应用不合并成一份套餐；Canva国际版能力不外推给可画中国版。动态页面以本次读取可见为准，未据此推断上线日期。

基线分层：

| 分类 | 定义 | 处理原则 |
|---|---|---|
| 通用交付基线 | 清晰、准确、可修改、可下载；多种工具有明确供给，而且实际作图需要 | 优先补完整闭环 |
| 电商核心基线 | 真实商品参考、场景/主图/卖点/套图、商品事实、常规批量与复用 | 在现有能力上产品化 |
| 条件基线 | 服饰穿戴、跨境翻译、平台详情格式、印花样机等 | 确认目标人群后提升优先级 |
| 深入能力 | 品牌硬约束、自动质量检查、表格套版、审批、平台连接 | 选有实际收益的，避免全部并行 |

## 5. 补齐顺序：先把商品图交付做完整

排序依据是用户当前已提到的白底图、封面、海报和套图用途，以及能力之间的依赖；目前没有真实使用频次、付费意愿和实现估时，所以不虚构加权得分或承诺开发天数。下表是一组可独立讨论和验收的工作包。

| 顺序 | 工作包 | 为什么排在这里 | 复用/依赖 | 完成应当看到什么 |
|---|---|---|---|---|
| P0-A | 可靠抠图、白底与修边 | 现有用户已在用；商品被重画、PNG不透明会直接阻断交付 | 复用现有入口与导出；评估专用分割/alpha修边，保留主体合成 | 单图/批量/参数入口结果一致；下载有真实alpha；可恢复误删边缘；Logo/文字/结构检查通过；失败不伪装成功 |
| P0-B | 精确文字/Logo与最小版式合成 | 价格、规格、日期是海报/卖点图的确定信息；现有文字节点未进入图片导出 | 复用图片、画布和字体能力；建立明确画板/层/导出语义 | 不重新生成商品即可修改价格和日期；商品/Logo不漂移；编辑结果与PNG/JPG一致；中文换行、溢出可处理 |
| P0-C | 现有图片处理的交付闭环与质量基准 | 普通裁剪/压缩/ZIP已有，应先证明实际流程可用 | 复用工具箱、导出、局部保护、技能验证机制 | 原图→处理→改稿→尺寸/体积→下载完整走通；图不漏、文件可读、命名可识别；记录现有场景/套图质量 |
| P1-A | 专用清晰度增强与可控阴影 | 属于多家已供给的常用处理；我方专用超分未找到，阴影主要靠指令 | 接专用处理并沿用预览/导出；与重采样区分 | 放大后小字、纹理、边缘无明显伪造；阴影可控；用户能比较原图并回退。若用户日常大量低清素材，提前到P0后紧接 |
| P1-B | 商品事实卡与套图清单 | 让每次生成、审稿、返工共享同一份事实；已有套图技能可承接 | 扩展现有素材多视图；复用AI批次计划/依赖/重试 | 同一SKU的名称、规格、包装字确认一次；每图有用途/比例/状态；只重做一张；整套缺项与待确认项可见 |
| P1-C | 多SKU套效果与轻量品牌/详情模块 | 将已经存在的Look、批次和素材转成可重复生产 | 依赖P0-B、P1-B；核对旧批量接口生命周期，选正式支持路径 | 可选择商品清单和参考、预览映射/费用；失败项续做；Logo/字体/配色可复用；导出按SKU和用途命名 |
| P2 | 跨境本地化/A+、服饰试穿、表格套版、自动QA | 都有明确竞品；价值依赖用户平台/品类/数量 | 依赖事实、文字层和可审阅结果；条件满足可升P1 | 各有独立样本与验收：翻译不改型号价格、试穿保印花版型、字段不串SKU、QA误报漏报可统计 |
| P3 | 团队审批、店铺同步/发布、重型视频、POD/印刷 | 当前3位用户的需求尚不能支持这些投入顺序 | 依赖稳定交付与明确工作量/协作规模 | 先有持续需求和搬运/审核成本数据，再定义专项范围 |

P0-A、P0-B可以分别设计；P0-C贯穿两者，先得到现有质量基线。P1-B可在P0-B期间定义数据和流程，详情模块及字段批量导出需要等确定排版成立。专用超分不必等待完整商品资料系统。

### 5.1 值得借鉴的不是功能名，而是这些具体操作

1. **美图：先选图种/模块，再逐张改。** 用户明确这一套要主图、场景、细节还是规格；只重做有问题的模块。可承接我方现有套图技能和批次卡，不需要从零另建生成器。[套图教程](https://www.designkit.cn/help/147)、[详情模块](https://www.designkit.cn/help/149)
2. **Photoroom：设计层可以修改并应用到整批。** 独立文字、图形、层序与批量应用，让价格或Logo修改有明确作用范围。借鉴时先做小范围可控布局。[批量图层](https://help.photoroom.com/en/articles/17060080-add-graphics-text-and-shapes-to-a-batch-of-images-web-app)
3. **Pebblely：输入阶段核对包装文字。** 商品资料与OCR校正为后续生成提供确认过的事实。我们可先让用户人工确认，随后才加自动核对。[商品创建流程](https://www.pebblely.com/how-to/)
4. **Canva/Adobe/Figma：表格字段绑定版式对象。** 这是精确生产几十款价格图的能力，与AI生成几十张图分开建设；现阶段先做少量字段和模板。[Canva](https://www.canva.com/help/bulk-create/)、[Adobe](https://helpx.adobe.com/express/web/bulk-create-and-automate/bulk-create.html)、[Figma](https://help.figma.com/hc/en-us/articles/31271824185623-Bulk-create-assets-in-Figma-Buzz)
5. **绘蛙：把服饰失败拆为可修的问题。** 印花、手脚、商品局部都有明确入口。若选择服饰，就围绕这些失败做专项，不能拿通用生图提示词当完成。[功能目录](https://www.ihuiwa.com/?catId=all)
6. **Claid：输入和输出规格明确。** 尺寸、留白、背景、格式与异步状态让交付更可预测；同样的契约也适合我们已有导出和任务系统。[批量API](https://docs.claid.ai/image-editing-api/batch-api-reference)

### 5.2 此阶段应控制的投入范围

- 画布、Agent、素材库、批次编排、下载、裁剪、压缩已有基础，先接通并验收。
- 任意AI图片自动拆层可研究，但价格/Logo精确编辑可以先用原生文字和图层完成。
- 品牌先做到个人常用Logo、字体、色和固定区域；审批与组织权限属于另一个工作包。
- 商品真值先可查看、可确认；自动评分和自动重试必须先测出误报漏报，避免用AI自评代替正确性。
- 专项服饰、跨境、POD按可触达人群升级优先级。竞品有该功能，可以证明值得研究，尚不足以证明我们应立即实现。

## 6. 完整调研之后，还需要补哪一层证据

本次已经覆盖公开功能供给和我方实现差距；**还不能据此确定谁的出图效果最好，以及哪类商家最愿意付费。** 接下来建议用现有3位用户的真实任务做一轮同题验证，完成后再决定垂类深度。以下为验证方案，未在本轮执行，也未消耗生成额度。

| 样本/任务 | 建议最小范围 | 核验重点 |
|---|---|---|
| 商品样本 | 约12个已获授权SKU；优先覆盖用户真实商品，兼顾包装字、反光/透明、小细节、复杂边缘；服饰仅在用户实际涉及时纳入 | 原图、规格、颜色、包装文字作为人工确认的真值；不能让模型编造未提供的角度/参数 |
| 基础处理 | 每SKU透明/白底、尺寸与压缩，难例局部修边 | 真alpha、商品结构/文字/Logo、文件规格、处理耗时 |
| 场景与海报 | 每SKU一个场景、一张带固定价格日期的营销图 | 商品保留、光影、文字准确、后续改价是否需要重生成 |
| 套图 | 选择4个SKU，各做同样的6种职责，并提出一次相同改稿 | 整套完成、各图用途、风格与事实一致、单张返工是否影响其他图 |
| 小批量 | 5个SKU共用一套参考或版式 | 映射不串款、共享修改范围、失败续做、文件命名与完整打包 |

候选对照先选我方、美图、Photoroom；如现有用户有服饰或跨境主业，再加入绘蛙或飞象/稿定。按同一输入、目标尺寸、可接受编辑步骤和成本口径运行，记录实际套餐与模型；不要拿精选展示图代替同题结果。

| 指标 | 定义/记录方式 | 用途 |
|---|---|---|
| 首轮可采用率 | 初次结果中，无需返工且通过任务检查的张数/初次输出张数 | 判断基本可用性 |
| 整套可交付率 | 所需图种齐全且每张通过检查的套数/计划套数 | 避免只看其中最漂亮的一张 |
| 事实错误 | 逐项记包装字/Logo/规格/数量/颜色/结构错误，保留原图对照 | 决定专用能力优先补哪里 |
| 改稿损伤率 | 一次指定修改后，原已通过区域/事实被破坏的次数/修改次数 | 衡量可控修改 |
| 人工时间与操作 | 从导入到下载的人工分钟、工具切换、手动校正和选择次数；另记等待时间 | 判断工作流是否省事 |
| 每张/每套交付成本 | 包含失败、重试、后处理的实际生成消费；订阅分摊单独列出假设 | 不能以单次最低生成价格替代 |
| 实际使用与复用 | 用户是否把图用于真实交付；下一SKU是否重用资料/模板 | 判断定位与付费价值，不能由画质分数推断 |

事实项先设硬门槛：用户确认的价格/型号/规格/Logo不能错；视觉审美与自然度另行评分。首轮不预设虚构的“95%成功”承诺，用基线实测和用户验收确定下一阶段目标。

## 7. 对定位的阶段性含义

基于当前用户用途，适合先验证的服务范围是：**帮助电商作图人员和小商家，把真实商品素材加工成可修改、可成套交付的上新与营销图片。** 通用个人创作能力继续作为底座；对外电商任务需要明确输入、输出和可修改范围。

这是研究后的验证方向，还不是已经确定的服饰/跨境/某平台定位。下一步应从真实订单里找出最频繁的任务和返工原因，再选择品类深入。可能形成优势的衡量标准是“相同商品要求下更少事实错误、更少人工步骤、更低整套返工成本”；目前没有同题实测，不能宣传已优于竞品。

**本轮交付边界：** 17个产品/产品组，覆盖商品视觉全过程的竞品矩阵、44项我方代码对照、补齐工作包与验收方案。没有改产品代码，没有把建议写成正式路线图，没有生成测试图片，也没有验证生产开关。公开文档不能确认的透明格式、图层深度、具体套餐、地区或接口能力，均保留未知或条件说明。
