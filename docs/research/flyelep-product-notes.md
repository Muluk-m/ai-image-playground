# 飞象（flyelep.cn）产品实测笔记与开源技能仓库借鉴边界

> 一手来源：owner 的登录态浏览器实测，2026-09-17，**只读观察、未触发任何生成**。
> 二手来源：该产品公开的技能仓库 [`FlyelepAI/agent-skills`](https://github.com/FlyelepAI/agent-skills)（Agent Skills 形态的 HTTP API 说明书，共 16 条）。
> **2026-09-19 补充**：四条目标技能（`partial-redrawing` / `scene-replace` / `product-replace` / `product-color-change`）的字段全表、图片角色划分、提示词原文与失败归因，见 [电商图竞品调研](ecommerce-image-competitors.md#三飞象四条技能的字段全表主要参考对象)。
> 本文脱敏：不写具体账号、项目名与商品名，以「一个已有的 A+ 详情项目」这类说法指代。

## 一、这是个什么产品

自称「超级卖家首选 AI 内容神器」，同时做跨境与国内电商的图文与视频内容。
货币单位是「算力」，按次计价，价格直接写在生成按钮上。

它与我们的相关性在于：**它是目前能找到的、离我们形态最近的一个电商向 Agent 生图/生视频工作台**——
左对话右画布、一个输入框起手、场景即技能。所以它的分流方式与参数词表值得看，
但它的交互策略（尤其是「问不问」）与我们相反，见 §五。

## 二、入口：一个输入框 + 两级分流

首页只有一个输入框，上方两级分流：

- 一级：`电商图文` | `电商视频`
- 二级（场景）：
  - 视频：主图视频 / 种草视频 / 品牌 TVC / 自由创作
  - 图文：A+ 详情 / 产品套图 / 主副图 / 白底图 / 单图 / 营销物料 / 自由创作

输入框 placeholder 明写可用触发：「上传 1–6 个参考素材、输入文字或 @ 主体…」；
右上角有「示例」一键填样例。灵感流按 口播 / 种草 / 品牌 / 剧情 分类。

底部参数 chip 在场景模式下多一个 **平台·语言**：

- 跨境：Amazon / Temu / Shopee / TikTok Shop / AliExpress / 阿里国际 / OZON / Lazada / DHgate / Coupang …
- 中文电商：淘宝 / 京东 / 拼多多 / 1688 / 小红书 / 抖音 / 唯品会 …

视频侧还有 `模型选择`（多个档位 + 生成方式「全能参考 | 首尾帧」）、
`视频参数`（时长滑杆 4–60s、480P|720P、字幕有/无、比例含「智能比例」）、`人脸素材`。
图文侧是 `生成配置`、`图片参数`、`参考风格`、`上传文件`。两侧的生成按钮都带价。

**结论**：入口分流是「类型 → 场景」，**场景就是技能**。进去之后是同一块「对话 + 画布」，
类型与场景仍可在输入框 chip 上切。

## 三、工作台：左对话 + 右画布（与我们同构）

- 左：项目名 + ID；新会话 / 历史 / 收起；对话流；底部同一个输入框，chip 变成
  `电商视频▾`（类型）`品牌TVC▾`（场景）`平台·语言` `模型选择` `视频参数` `人脸素材`。
- **每轮用户消息上方有一行本轮配置摘要**，例如
  `视频（自由创作）| 720p | 智能比例`、`A+详情 | 特惠通道 | 中文简体 | 淘宝 | 智能比例`。
- 右：画布，底部工具条 选择/抓手/图片/文字/撤销/重做/图层/全选；右上 队列任务 / 历史版本 / 导出图片。
- 选中图片后浮出的工具条每项都带单价：裁剪、图层分离、AI 抠图、局部重绘、智能延展、
  无损放大、图片翻译、AI 超清、编辑文字、爆款图片复刻、重新生成。
- 首页下方另有「AI 工具箱」：爆款图片复刻、爆款视频复刻、局部重绘、场景替换…

**值得抄的一条**：每轮消息上方那行配置摘要。用户能一眼看到这一轮 Agent 用了什么参数，
这正好对应我们「替他定了什么要在回复里说清楚」那条裁决——只是他们做在了 UI 上。

## 四、一条完整的图文流程（在一个已有的 A+ 详情项目里只读观察）

1. 用户发了一句很模糊的话：「拓展产品卖点，有产品解析，精致一些」。
2. Agent 标「询问」，给 **4 套设计方向**，每套一句话定位，单选 + `确定`；
   并注明「不符合也可以直接输入具体特征」。
3. 选择结果回写成一条用户消息：`【设计方向选择】…`。
4. Agent「生成图片」：一次产出 **一套 10 张带类型的图**——
   产品主宣传图 / 卖点图 / 细节图 ×2 / 功能展示图 / 使用场景图 ×4 / 参数图，各标了比例。
   下方是 `重新生成（带价）` 与 `设计方案`（看这一套的方案）。
5. 末尾一张「为您推荐」卡：「以下是该品类在某平台 Top10 都在用的风格，尝试一下？」
   给 4 个下一步选项 + `确定`。

关于钱：**没有生成前的价格确认**，价格只写在生成按钮上；确认只发生在「意图不清」那一刻
（问方向）。余额不足时 Agent 直接回一句「您的算力不足」。

## 五、对我们的三条含义

1. **场景型技能的产物是「一套带类型的交付物」**，不是一张图。
   图文侧是 10 张带类型名的套图，视频侧对应分镜/多镜。类型名必须写出来，
   用户才知道哪张放详情页第几屏。
2. **「问不问」取决于对意图的掌握程度，不取决于价格。**
   他们在意图模糊时问，在意图清楚时直接花钱做——这一条与我们 owner 的裁决一致。
3. **问的形式是给方向选项，不是开放式提问。** 2–4 套具体方向，每套一句话写清会产出什么，
   并留一个「也可以直接输入」的出口。这正是我们澄清工具的形状（2–4 个互斥选项 + 界面自带的「其他」）。

顺带一条反例来自另一家（即梦）的同期实测：它的 Agent **一次澄清都不问**，
直接扣费跑完，然后事后告知「当前模型比例自动适配为 16:9，你可以导出时裁剪为 9:16」——
用户明说的 9:16 被静默丢弃了。这是我们技能正文里「用户明说的约束不许静默丢掉、
做不到的先说」那一条的直接来源。

## 六、飞象开源技能仓库能借什么、不能借什么

那个仓库把它自己的 HTTP API 写成了 Agent Skills 目录：
`generate-poster` / `generate-video` / `scene-replace` / `product-replace` /
`product-color-change` / `image-translate` / `gen-hot-image` / `gen-hot-video` 等十余条。

### 不能借

- **不能借流程。** 每条技能的正文都是「填这些字段 → POST 这个 URL → 轮询任务 → 展示结果」。
  我们的技能是给一个已经握着 `generateImage` / `editImage` / `generateVideo` / `readLibrary`
  的模型看的创作指引，不是接口说明书。照搬会让技能正文引用一堆我们没有的东西。
- **不能借它的提问策略。** 它每条技能都写着「以下必传参数必须通过询问用户获取，
  agent 不可自行填写」「调用前应先向用户列出必传参数与可选参数表格」。
  这与我们的裁决**正好相反**：我们按对意图的掌握程度决定问不问，
  意图清楚就直接做并说明替用户定了什么。
- **不能借它的接口、字段名与品牌名。** 我们的技能正文里不出现它的任何一项。

### 能借（只这三样）

1. **能力分类。** 「电商图文 / 电商视频」两级分流下的场景清单，
   给了我们第一批技能该覆盖哪些场景一个现成的参照：
   主图视频 / 种草视频 / 品牌 TVC；白底图 / 主副图 / 产品套图 / 营销物料。
2. **参数词表与默认值推导。**
   - **平台决定语言**：淘宝 / 天猫 / 京东 / 拼多多 / 1688 / 小红书 / 抖音 → 中文简体；
     Amazon / Temu / Shopee / TikTok Shop / AliExpress / eBay / Lazada / OZON 等跨境 → 英文。
     用户显式指定语种时以用户为准。**这条推导的价值在于「不要反过来问用户」**。
     （我们再加一条他们没有的：用户连平台都没提时，按中文简体做并说明，同样不问。）
   - **视频业务类型**只有三类：主图视频 / 种草视频 / 品牌宣传。
     这正好是我们三条视频场景技能的边界线。
   - **配音与字幕是两个独立的开关**（`needVoice` / `needText`），不是一件事。
     我们两样都做不到，所以两样都要在技能里分别说清楚，而不是笼统说「不支持声音」。
   - 时长、比例、分辨率这类枚举**不借**：我们有自己的档位表
     （`packages/shared/src/video-presets.ts`），两边的取值并不一样。
3. **素材约束与提示词写法。**
   - 素材侧：参考图最多 6 张、同一商品的多角度图一起给有助于还原细节、
     商品替换的目标图最多 3 张、颜色/场景参考图各只收 1 张。
     这些数字我们不照抄（我们的 `editImage` 是最多 4 张参考图），但「多角度一起给」这条经验照用。
   - 提示词写法：**主题 / 卖点 / 风格氛围 / 视觉元素各一句**。
     这个四段式被我们改写进了 `poster` 与 `product-image-set` 的正文。
   - 换色类的提示词边界很值得抄：「优先描述颜色，不要把换色需求扩写成换材质或换商品；
     用户只是想换商品就该走商品替换，想换背景就该走场景替换。」
     这一条直接变成了我们 `product-restyle` / `scene-swap` / `image-remix` 三条技能的互斥边界。
   - 「保留原场景、保留光影、保留构图」这组保留清单的写法照用——
     它是这类编辑最容易翻车的地方。

## 七、未验证

- 本文全部内容来自一次只读观察，**没有触发过任何生成**，所以「一套 10 张」的实际质量、
  「为您推荐」的命中率、以及算力扣费的实际口径都没有验证过。
- 它的服务端如何把一次请求拆成 10 张带类型的图，外部看不到；
  我们的对应实现是「一张一次 `editImage` 调用」，两边不是同一条路。
