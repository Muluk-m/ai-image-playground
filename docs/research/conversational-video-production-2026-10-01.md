# 对话式视频制作：从故事到可交接的资源包

日期：2026-10-01。状态：研究与待验证建议，不是已接受的产品决策。本文未修改应用代码、技能或既有 ADR。

> 同日修订：用户指出本轮竞品样本偏离国内同赛道。竞品判断以[国内竞品重做报告](china-conversational-video-competitors-2026-10-01.md)为准。下文“文档优先”的形态、三视图优先级和导出排序均降为待验证假设；不再以国外产品或 Adobe 为其主要依据。

## 建议先把产品承诺定在这里

**用对话把一个想法做成可修改的剧本、角色设定、逐镜画面和选定的视频片段，整理成能交给剪辑工具继续制作的资源包。**

“视频脚本生成”低估了用户要完成的工作；“一键成片”又超出了本次需求。暂称“视频创作”，交付物是制作项目和资源包。题材尚未确认，下面以短剧情为研究样本，不代表已经选定漫剧赛道。

核心验证问题：用户能否在多轮对话后知道哪份剧本是当前稿、哪个角色版本被哪几个镜头采用、哪段视频是选定版本，并能把这些关系一起带走？

## 三种产品形态

| 方案 | 主工作面与典型动作 | 优势 | 代价 |
| --- | --- | --- | --- |
| 1. 对话 + 制作稿 | 左侧对话，右侧当前稿；从剧本切换到角色、镜头与交付。选中一段说“改这里”。 | 最贴近当前对话产品；写作、阅读、局部修改自然。 | 批量比较几十个镜头不如看板；要解决长文定位。 |
| 2. 对话 + 镜头看板 | 每张卡代表一个镜头，含首帧、片段候选、选定版本；角色是共享资产。 | 适合反复生成、挑选、只重做一镜。 | 初始故事未成形时，空看板缺少方向。 |
| 3. 阶段制作流程 | 创意 → 剧本 → 角色 → 分镜 → 片段 → 交付；每阶段都有对话和检查点。 | 新手知道下一步，适合重复的标准任务。 | 容易重回旧导演台的僵硬流程；回头修改和跳步必须一开始设计。 |

**尚不选定第一版形态。** 国内小云雀证明阶段定稿和对话修改可以共存，魔因与 LibTV 提供结构化制作和画布的直接参照。应先用同一个故事比较局部修改、资产引用和交接操作，再决定文档、镜头板和阶段引导怎样组合。上轮三个草案只保留为讨论材料。

## 一条完整用户路径

示例：“做一条 30 秒的雨夜短片：女孩把伞留给陌生人，结尾才发现那是未来的自己。”

1. 对话先产出可读的故事稿和可改的假设：目标时长、画幅、风格。只追问会改变故事方向的关键歧义。尚无图片时允许先完成整个文本计划。
2. 用户说“结尾不要解释，让观众自己发现”。同一份剧本更新，显示改了哪个场景；不用从聊天记录翻找最新版。
3. 提取角色与场景。先定角色文字特征与一个满意的形象，再按需要补正面、侧面、背面和细节。已有参考的用户可以直接上传或引用资产。
4. 生成分镜草稿，逐镜记录画面、动作、台词/旁白、景别、预计剪辑时长和角色引用。用户可以先拆镜再定角色，顺序不强制。
5. 选中第 2 镜，说“只让她回头，镜头不要推进”。只修改该镜；同一镜头保留历史候选。
6. 对选定镜头出首帧。角色设定作为身份参考，首帧是具体机位下的完整场景。不要把正侧背拼图直接作为视频首帧。
7. 用户只选第 2、4 镜生成片段。确认真实模型、生成时长、参考图和报价；其余镜头可以只有文本或首帧，不阻塞交付。
8. 下载资源包。预检告诉用户“6 镜，2 段视频，4 镜尚未生成视频”，允许有意导出不完整项目，但文件缺失不得静默忽略。

剧本时长是叙事目标，生成时长受模型档位限制，最终使用时长由剪辑选择。三个值须分别保存：例如计划使用 3 秒，生成 5 秒，建议取 1–4 秒。不能把整片目标 30 秒误当成一次模型生成请求。

## 真正需要做深的四件事

### 当前稿与局部修改

消息记录解释为什么改；结构化项目保存现在是什么。剧本不是每次回复新贴一份的 Markdown 附件。

每个角色、场景、镜头有稳定 ID 和版本。用户手改字段与 Agent 修改走同一个补丁入口，校验基准修订号。插入一个镜头可以改变显示序号，不能改变其他镜头的身份和素材归属。

### 角色一致性与参考语义

角色至少区分人物身份与造型版本。例如同一角色的校服和雨衣，不宜混成一个反复覆盖的角色记录。镜头绑定明确版本，首帧与视频任务记录实际使用的参考，而非运行时追随“最新角色”。

三视图是可选的设定资产，不是每个项目的强制步骤，也不是保证一致性的技术。优先验证一位角色的正面、侧面和两个不同机位是否仍可辨认，再扩生成规模。参考图、首帧、尾帧必须在数据与模型适配层区分。

### 改动影响与候选保留

角色衣服变化后，系统标注“第 2、4 镜使用旧造型，待复核”；不自动删视频，也不自动重花积分。用户可沿用旧版本、更新某一镜的计划，或对选定镜头另发新任务。

把三类状态分开：内容修订状态（草稿/已选定/待复核）、任务状态（等待/运行/成功/失败）、交付状态（本地可取/未下载/缺失）。“任务成功”不等于“当前项目已采用”或“ZIP 有完整字节”。

### 有上下文的交接

资源包要让外部剪辑者知道“这是第几镜、用哪段、配什么台词、哪里还没完成”。只把下载链接或匿名 taskId.mp4 塞进 ZIP 不够。

建议结构（产品提案，尚未实现）：

```text
雨夜来客/
  README.md                  # 使用方式、缺项、建议顺序
  script.md                  # 本次导出的剧本版本
  shots.csv                  # 镜号、画面、台词、计划时长、文件、建议入出点
  project.json               # schemaVersion、稳定 ID、修订与相对文件路径
  characters/char-a/look-01/  # 人物文字设定、正侧背/细节/已有参考
  shots/001_shot-a/
    frame.png                # 选定首帧，实际有才写
    selected.mp4             # 选定原片，实际有才写
    prompt.txt               # 实际提交的生成提示词与参数
  shots/002_shot-b/...
```

默认导出选定候选；“全部候选”是额外选项。每份导出固定一个项目修订，在导出期间继续编辑不改变这次包。manifest 记录 MIME、字节大小与校验信息；不带密钥、内部鉴权头或把临时签名 URL 当作文件本体。SRT 仅在有明确时间对齐时导出；拟定台词可先保存在 shots.csv，不能把估算字幕冒充音频对齐结果。

**ZIP 是容器，既能装通用素材，也能装特定平台草稿。** 国内魔因提供素材与 manifest 的实现，ArcReel 提供按集导出剪映草稿 ZIP 的官方流程。应先确认用户交接目的地并测量手动导入劳动，再决定第一版范围；不承诺尚未实测的软件兼容。详见[国内交接参照](china-video-story-tools-sources-2026-10-01.md)。

## 核心实现建议

1. **一个本地制作项目模型**：`Project → Script/Scene/CharacterLook/Shot → Candidate → GenerationTask`。候选记录来源修订、角色引用、模型参数、任务 ID、文件可用性。项目关联现有会话，但不是会话历史的临时解析结果。
2. **少量结构化读写操作**：读取项目摘要/指定镜头、创建/修改剧本与角色、修改镜头、选择候选、规划导出。Agent 产出补丁，程序验证 ID、字段与 revision；不要允许模型整份覆盖项目。命名只是示意，不预定最终 API。
3. **生成仍复用既有系统**：用当前工具完成出图/改图/生视频，提交快照加上项目、镜头、角色版本引用。后台结果回写原任务绑定的镜头候选；用户期间切项目、重排镜头或改剧本，结果也不能错位。
4. **付费重试是显式动作**：失败、超时或回调重放不得触发隐式再次付费。批处理允许部分成功；旧任务晚到的结果可以收下，但不能覆盖已选定的新候选。
5. **导出是可取消的本地作业**：先冻结修订并做文件可取预检；复用现有 ZIP 能力，评估大包时流式写出或限定规模。现在的 zipSync 会把媒体放进内存，不能未经验证就许诺长剧大包。
6. **存储沿用现行边界**：工程与草稿在本地持久化，刷新后恢复；会话沿用服务器；可复用人物按用户选择存为现有素材。每轮向 Agent 传本次项目快照，服务端不能因缺少本地工程就根据旧聊天假装拥有最新稿。需要跨设备工程时另作存储决策。

仅新增一条 Skill 可用于验证话术和人工流程，但无法交付稳定局部修改、版本绑定、跨轮恢复与可校验导出。真正的开发量集中在结构化项目和结果归属，不在再接一个生视频 API。

## 第一版范围与验证

建议研究样本：一位主要角色、一个 20–60 秒短故事、4–8 镜，仅生成其中 1–2 段视频。数值用于缩小验证成本，不是模型能力或硬编码产品限制。

第一版闭环：故事稿 → 角色参考 → 可修改镜头 → 选镜生成 → 候选选择 → ZIP。保留现有粗剪导出作为辅助；专业剪辑、多轨混音、口型同步、批量长剧、多人协作和平台工程适配后置。

验收必须覆盖：

- 只改第 2 镜，第 1、3 镜内容与选定候选不变。
- 角色改造型，只对真正引用旧造型的镜头提示复核。
- 重排/插镜后，运行中的任务结果仍回到原镜头。
- 一镜失败，其余镜头可用，重试只新建明确选中的任务。
- 刷新恢复当前稿、选定候选和任务状态；关闭页面期间的结果能正确对账。
- 在另一空目录解压，仅依赖包内文件也能理解剧情、镜序和缺项。
- 用用户实际采用的剪辑工具导入选定片段，核对顺序、声音、画幅与建议裁切；未验收前不声称平台兼容。
- 真实生成样本由用户明确选择后执行；本次研究未调用收费生图/视频。

还需用户决定的三个产品问题：首个题材是什么；主要交给哪个外部创作工具；角色是否要跨多个作品持续复用。第一个影响入口话术，第二个影响导出优先级，第三个决定角色是项目附件还是共享资产。
