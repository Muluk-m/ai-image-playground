## 1. 一页结论

### 1.1 四家的共识（≥3 家都这样做）

| # | 共识做法 | 哪几家 | 一句话 |
| --- | --- | --- | --- |
| C1 | **节点画布是主工作面，连线 = 引用关系且有方向** | 即梦🟢 TapNow🔵 LibTV🟢 | 上游提供内容，下游接收并继续生成。连线不是装饰，它决定下游能 `@` 到谁 |
| C2 | **一套输入框承担所有生成；"创作类型"只是它的一个下拉** | 即梦🟢 可灵🟢 LibTV🟢 | 图片/视频/音频不是不同页面。即梦实测同一组件出现在首页、节点下方、Agent 会话三处 |
| C3 | **生成按钮旁常驻预估积分，不做二次确认弹窗** | 即梦🟢 LibTV🟢 TapNow🔵（手动确认模式才有卡片） | 即梦 `✦56`、LibTV `✦6`、TapNow「预计 Tapies」 |
| C4 | **候选不覆盖：再次生成产生新节点/新历史，原结果保留** | 即梦🟢 TapNow🔵 LibTV🟢 | 即梦「节点历史左右切换 + 设为主视频」；TapNow「新结果放进新建节点，沿用原输入连线」 |
| C5 | **主体/元素 = 一组多模态参考的具名集合，不是一张图** | 即梦🔵 可灵🔵 TapNow🔵 | 即梦主图+3 辅图+1 音色；可灵 1 主+1~3 辅+音色；TapNow 名称+描述+图/视频/音频/文本 |
| C6 | **角色三视图（正/侧/背）是一致性的标准工序** | 即梦🔵 可灵🔵 LibTV🟢 | 本轮在 LibTV 公开画布里直接看到标注 `SIDE` / `BACK` 的三视图组（`libtv-public-canvas-turnaround.png`） |
| C7 | **截帧：把视频任一帧取出来当下一镜的首帧** | 即梦🔵 可灵🔵 TapNow🔵 | 即梦「截取帧」、TapNow「截帧（当前帧/首帧/尾帧）」 |
| C8 | **时间线/播放列表是画布上的一个节点，不是独立页面** | 即梦🟢 TapNow🔵 LibTV🟢 | 即梦「时间线节点 + 全屏编辑器」；TapNow「播放列表节点」；LibTV 节点菜单里有「智能剪辑」 |
| C9 | **节点上方浮动工具条承载该类型的编辑能力** | 即梦🟢 TapNow🔵 LibTV🟡 | 选中视频 → 剪辑/替换/移除/延长/重拍/截帧/下载 |
| C10 | **作品可追溯到它的画布，并一键复制继续创作** | 即梦🔵 LibTV🟢 TapNow🔵 | LibTV「查看制作过程」→ 只读画布 + 「复制项目」；即梦「发布画布模板」；TapNow「分享、查看与克隆」 |
| C11 | **按场次/用途给节点编组并命名** | 即梦🔵 TapNow🔵 LibTV🟢 | LibTV 公开画布的组名就是「人物及音色 / 场景图 / 饭店道具 / 日出+路上 / 饭店内-对峙」 |
| C12 | **先造班底（角色+场景+道具），再按场次引用** | 可灵🔵 LibTV🟢 即梦🔵 | 可灵官方三步：生成主体和场景 → 生成分镜图 → 分镜视频；LibTV 公开画布的连线全部从资产组射向场次组 |

### 1.2 常见做法（2 家）

| # | 做法 | 哪两家 |
| --- | --- | --- |
| N1 | **框选一组节点 → 整组执行，确认窗显示整组预计消耗** | TapNow🔵（「整组执行」+「运行整组？」窗）、可灵🔵（批量并行生成 + 批量框选下载） |
| N2 | **Skill / 技能是可被 `/` 调起的具名工作流** | 即梦🟢（`/创作分镜`）、LibTV🟢（`/pixar-animated-ad-creator` 等，且可自建） |
| N3 | **多候选可以堆叠收纳，占一个节点的位置** | TapNow🔵（堆叠，一叠 ≤50，可设置"堆叠/铺开"默认）、即梦🟢（节点历史左右切换，右键「应用全部历史」摊开） |
| N4 | **机位/运镜给一个空间工具而不是只靠文字** | 即梦🟢（导演台 3D 预演，WASD/QE 摆人偶和机位，截图回画布）、TapNow🔵（视频重拍：球体选机位方向 + 正面/侧前/侧后/背面/俯视/仰视预设 + 景别） |
| N5 | **项目/画布可进文件夹、可移到团队空间** | TapNow🔵、LibTV🟢（左栏「项目」「资产」一级入口） |
| N6 | **样片（低清先试）→ 正片（高清沿用）两段式** | TapNow🔵（480P 样片 → 1080P 正片，样片保留）、可灵🔵（Turbo 系列作为试片档） |

### 1.3 特色做法（1 家，需单独判断是否抄）

| # | 做法 | 谁 | 判断 |
| --- | --- | --- | --- |
| S1 | **剧本设定器：题材轮盘 + 六个参数卡 + 爆款预设 Top 8** | LibTV🟢 | **强烈建议抄**。它把"从零起稿"这件最难的事变成了选择题，且每个参数都有明确上限 |
| S2 | **故事板视图：音频/图片/视频三列清单，每条视频下列出它引用的全部缩略图** | LibTV🟢 | **建议抄**。这是"连线"的第二种表达，比画布更适合检查引用是否正确 |
| S3 | **智能剪辑：分析画面变化自动识别镜头切换，把一条长视频拆成多个节点** | TapNow🔵（LibTV 节点菜单里也有「智能剪辑 Beta」🟢） | 第一版不做 |
| S4 | **一次图片生成出整张分镜网格，再「宫格切分」拆成 N 张首帧** | 即梦🔵 | **强烈建议抄**。成本比 N 次图片生成低一个数量级，且同一张图出来的风格天然一致 |
| S5 | **模型是"允许集合"而非单选，权益（VIP）编码在列表里** | 可灵🟢 | 不抄。我们的模型池更窄 |
| S6 | **模型级多镜头（Multi-Shot / 一条 prompt 写 `镜头N，Xs，…`）** | 可灵🔵（即梦官方模板也这么写🟢） | 作为分镜表的**导出格式**抄，不作为交互 |
| S7 | **Apps：外部数据源（会议纪要/Notion/Slack）作为任务输入** | TapNow🔵 | 不抄 |

### 1.4 我们第一版应照搬的清单（按优先级）

1. **节点画布 + 有向连线 + 连线即引用**（C1）。连线在 UI 上具象成下游生成器顶部的一排可删缩略图（即梦实测的做法）。
2. **一个生成器组件，节点选中时出现在节点下方**（C2）。顶部是参考缩略图排（带编号）+「+ 参考图」，中间是 prompt，底栏是模型 / 参数 / 预估积分 / 发送。LibTV 截图 `libtv-node-composer.png` 和即梦实测完全同构。
3. **剧本设定器开局**（S1）。题材 + 六个参数卡（目标受众 ≤2 / 角色设定 / 时代背景 ≤2 / 核心看点 ≤3 / 画风单选 / 剧本结构 + 集数滑杆），每项都可以留「自动」。
4. **先造班底再铺场次**（C12 + C6）。角色三视图 + 场景板 + 道具，各自成组；场次组从资产组连线引用。
5. **分镜网格 → 切分**（S4）作为首帧的默认生产方式，分镜表只定内容不定像素。
6. **候选不覆盖 + 节点历史**（C4）。
7. **时间线是画布上的一个节点**（C8），最后一镜完成时自动串好（已有调研的明确结论，即梦实测的坑）。
8. **故事板清单视图**（S2）作为画布的第二视图，用来核对引用。
9. **节点浮动工具条**（C9）：截帧 / 修剪 / 下载 / 全屏 / 保存为主体。
10. **作品 → 只读画布 → 复制项目**（C10），这是增长闭环，但第一版可以只做"只读画布"不做社区。

### 1.5 已拍板的决定（本报告后续所有建议按此对齐）

产品负责人已定，不再讨论：

| # | 决定 | 对本报告的影响 |
| --- | --- | --- |
| K1 | **视频与图片工作流共用同一个画布入口和界面**，不是只放在视频项目里 | 节点类型清单必须同时容纳图片与视频两条链路；入口不按产物分叉。**四家全部这样做**（见 §3.5 专节） |
| K2 | **第一版服务 AI 短剧 / 漫剧** | 开局方式优先抄 LibTV 剧本设定器（题材/集数/剧本结构全是短剧词汇）；资产优先角色三视图 + 空场景板 |
| K3 | **现有「对话式视频制作」（`features/production` 制作文档）冻结**，可复用部分迁到画布工作流后下线 | §6 的「我们现状」里凡写 `production` 的，读法是「**数据模型和 skill 可迁移，UI 不保留**」 |
| K4 | **跑通标准**：剧本 → 分镜 → 角色图 → 首帧图 → 多片段（可单独重生成）→ **在我们这里合成成片并下载** | 成片不能只靠导出到剪映；§6.6 的 F1/F3/F5 是第一版必做项。「可单独重生成」= C4 候选不覆盖 |
| K5 | **第一版 Agent 要能读写画布节点**（如「把剧本拆成分镜」） | 这是即梦已实测跑通的能力（§3.6 专节）。Agent 的工具面必须包含：搜索节点、建节点、连线、改节点参数、建时间线 |

两个因 K1/K5 需要单独回答的问题，各起一节：**§3.5 图片与视频节点怎么共存**、**§3.6 Agent 怎么操作画布节点**。

### 3.2 TapNow Creative OS —— 文档最完整，机制最清楚

证据全部 🔵（官方中文文档 `docs.tapnow.ai/zh/docs/…`，本轮读取）。界面 ⚪ 未实操。

#### 维度 1：入口与项目模型 🔵

- **画布 = 项目单位**。「每次开始新的创作，都可以新建一张画布。Creative OS 会自动保存画布中的节点、连线、**Agent 对话**和生成结果。」
- 两个空间：**个人画布 / 团队画布**。可以「移动至团队」，移回个人后团队成员失去访问。
- **文件夹**整理：菜单「移动至…」/ 多选「添加到文件夹」/ 拖拽；**把一张画布拖到另一张上会创建新文件夹并放入两者**。
- 画布内左上角点名称旁箭头可**直接切换画布**（下拉带搜索，当前项打勾，底部「新建画布」）。
- 「也可以在首页直接向 Agent 发送任务。Creative OS 会创建一张画布，并把这次对话和 Agent 生成的内容保存在画布上。」—— **发任务即建画布**。

#### 维度 2：开局方式 🔵

- 空白画布 / 首页直接发任务 / **模板**（一组节点+连线结构，分「公共模板 / 我的模板」，可预览后「应用」，加入后是一个**节点组**）/ Brainstorm 对话。
- 模板与素材库、主体的分工（官方原表）：

| 你想再次使用什么 | 使用 |
| --- | --- |
| 一张产品图、一段视频或一份音频 | 素材库 |
| 同一个人物、产品或角色的一组参考资料 | **主体** |
| 一组节点、连线和制作步骤 | **模板** |
| 整张画布及其中的全部内容 | 分享并克隆画布 |

**这张四行表是整个调研里最清楚的一个概念划分，建议直接采用。**

#### 维度 3：画布 🔵

**节点类型**：文字 / 图片 / 视频 / 音频 / 3D / 播放列表 / 堆叠（容器）/ 分组。

**建节点三种方式**（官方原表）：左侧工具栏 `+` → 选类型；**双击画布空白处**（菜单出现在双击位置）；右键菜单。上传支持拖文件进画布。

**引用语义**（这是 TapNow 写得最细的一段）：

> 「连线表示两个节点之间存在参考引用关系。前面的节点是上游内容，后面的节点可以在生成时引用它。」
> 建立连线后：「打开下游节点的 Prompt 输入框；输入 `@`；从列表中选择已经连到这个节点的上游图片。」

**连线 ≠ 自动引用**。连线只是让这个上游**出现在 `@` 列表里**，真正引用还要在 prompt 里打 `@`。这比即梦的"连线即参考列表"更显式。

**从一个节点继续创建**：单击节点 → 两侧出现 `+` → 点右侧 `+` → 选下一步节点类型 → **自动建立连线**。这是最轻的建图方式。

**用途要写进 prompt**（官方示例原文）：

> 「使用 @产品正面标准图 保持瓶身结构和标签位置；@暖色灯光参考 只参考光线，不参考其中的产品。先给我 3 个构图方向，不要直接生成视频。」

官方解释：「这样 Agent 才能区分产品标准和风格参考，不会把两张图当成相同用途。」—— **TapNow 不用"参考模式下拉"，用自然语言写用途**。这正好是我们已有调研里「绝不暴露参考模式下拉」那条建议的另一种实现。

**多候选与堆叠**：
- 「在已经有结果的图片、视频或文字节点上再次点击生成，原来的结果会保留，**新结果放进新建的节点，不会覆盖原节点。新节点沿用原节点的输入连线**，生成次数默认为一次。音频节点仍然直接在原节点上更新。」
- **堆叠**：Shift 多选或框选 ≥2 个节点 → 选区工具栏「堆叠」→ 收成一叠（标数量）。一叠 ≤50。单击展开画廊，拖出单个取回，取到只剩 1 个自动解散。整叠操作：**加入对话 / 保存到素材库 / 下载全部**。
- **画布设置 → 批量生成结果 → 堆叠 / 铺开（默认铺开）**。

**框选批量生成**：
- 选中节点 → 打组 → 节点组工具栏「**整组执行**」→ 弹「**运行整组？**」窗显示**预计 Tapies** → 确认。
- 「估算暂时不可用时，仍可以自行决定是否继续。最终消耗以任务完成后的实际结算为准。」

#### 维度 4：剧本 → 成片 🔵

TapNow **没有专用的剧本/分镜对象**，剧本就是文字节点，分镜靠 Agent 对话推进。它的重心在**片段级的编辑能力**和**播放列表**。

**视频 Toolbar 核心能力**（官方原表，选中视频节点后节点上出现）：

| 能力 | 什么时候用 | 结果 |
| --- | --- | --- |
| **剪辑** | 去片头片尾 | 新建剪辑结果节点，原视频保留。面板内还有「**智能剪辑**」：分析画面变化自动识别镜头切换，**拆成多个独立视频节点** |
| **替换** | 保留镜头只换画面中一个对象 | 拖进度条 → 「添加蒙层」框选被替换物 → 「从画布中选择」一个图片节点作替换物 → 预估 Tapies → 生成。新节点在原视频右侧 |
| **移除** | 去掉画面中的对象 | 蒙层框选 → 预估 → 生成 |
| **延长镜头（Beta）** | 补片头或片尾 | 选方向 / 比例 / **4–30 秒** / 延长方式 → 写内容（可 `@` 引用）→ 新节点出现在原视频**前方或后方**并自动连接 |
| **视频重拍（Beta）** | 重新设计机位、景别、运镜 | **分镜时间轴**：播放头 + 「剪切分镜」把一条视频切成多段，**每段单独设置镜头方案** |
| **截帧** | 取一帧当下一镜首帧 | 当前帧 / 首帧 / 尾帧 → 新建图片节点 |
| 保存到素材库 / 下载 / 全屏预览 | — | — |

**视频重拍的机位模型**（这是四家里最具体的运镜交互）：

每个片段可选四种镜头变化方式：
- **保持不变**：要求保留原视频画面，不改视角和景别
- **固定机位**：拖**左侧球体**决定机位方向，或选右侧预设 `正面 / 侧前方 / 侧后方 / 背面 / 俯视 / 仰视`；再调**景别**（特写→远景）
- **切换视角**：分别设 `开始视角` 和 `结束视角`，中间**直接切**，无连续移动。「适合对话正反打、反应镜头或强调某个瞬间」
- **平滑移动**：同样设两端，视角**连续过渡**。「可以表达环绕、推进、拉远，或从侧面移动到正面」

约束：短于 0.5 秒的片段只能用「保持不变」或「固定机位」；开始与结束视角相同或非常接近时按固定机位处理。官方明确：「球体、预设和分镜说明用于表达镜头意图，**并不等同于逐帧精确的 3D 相机轨迹**」。

> **这是即梦 3D 导演台的"2D 轻量版"**：不建 3D 场景，只用一个球体 + 6 个预设词 + 景别滑块表达机位意图。我们已有调研的建议是「在分镜表里给景别/机位一个下拉或几个预设词，不需要 3D」——TapNow 证明了这条路是可行的，而且可以做到按时间段分段设置。

**播放列表（= 时间线）**：
- 创建：Shift 多选 ≥2 个视频节点 → 选区工具栏「创建播放列表」→ 新节点出现，视频按当前顺序进时间线。或左侧 `+` → 工具 → 播放列表（空的）。
- **图片和音频节点不能直接加入播放列表**。
- 操作：拖序 / 拖两端裁切（不删原视频）/ 播放头 `C` 切割（每段 ≥1 秒）/ `Q` 裁左 / `E` 裁右 / **右键「定位到画布上的源视频节点」**。
- 导出三选项：`下载原始片段(MP4)`（按时间线顺序，同源只下一次）/ `下载合并视频(MP4)` / **`导出到画布`**。

**官方给的预览检查清单**（很实用，可以抄进我们的 UI 提示）：
> 是否有黑帧或多余静止画面；每个镜头的开头和结尾是否干净；相邻镜头是否衔接自然；视频声音是否突然中断或重复；总时长是否符合使用要求。
> 「单独播放每个片段不够，很多问题只会出现在**两个镜头的连接位置**。」

**样片 → 正片两段式**：Seedance 2.5 样片模式先出固定 **480P** 样片，可「样片修改 480P」继续调，或「生成正式片」进正片面板（**自动沿用样片的提示词和素材，只让你选输出清晰度**，1080P）。正式片作为**连接到样片的新节点**出现，样片保留。

#### 维度 5：Agent 与 Apps 🔵

- Agent 在画布内，「会读取你**明确选中**的内容，并把新的结果继续放回画布」。
- **两种生成模式**：`自动生成`（Agent 连续完成多步）/ `手动确认`（弹确认卡片，可改**模型 / 比例 / 时长 / 数量 / 本次使用的参考**，改完点"生成"才调模型）。官方建议表：

| 情况 | 建议 |
| --- | --- |
| 已验证过流程，想连续完成多步 | 自动生成 |
| 第一次尝试新模型、新参考或新方向 | 手动确认 |
| 需要在生成前调整比例、时长、数量或模型 | 手动确认 |
| 已明确规格，只想快速做一组同类素材 | 自动生成 |

- **Apps** 分两类：**工作 App**（连 Notion / Slack 等，读会议纪要、品牌规范、脚本）和**创作 App**（专业修图等，直接用当前项目上下文）。调用方式是在指令里写 App 名 + `@` 引用节点。
- 官方对 Apps 的一条重要提醒：「创作 Apps **只处理当前任务明确提供的输入**。需要保持产品、角色或风格时，把唯一标准放到画布并在任务中引用，**不要期待 App 自动从所有历史内容中找出正确版本**。」
- 多 App 连续工作的推荐节奏（可直接当我们的 Agent 分阶段设计）：读取整理资料 → 确认要求和创意方向 → 生成少量静态候选 → 修正主体和画面细节 → 制作或剪辑视频 → 检查交付文件 → 确认后同步外部。「**每一步都留下可检查的画布节点或文件。某一步结果不对时，可以从这里调整，不需要重跑整条链路。**」

#### 维度 6：布局 ⚪/🔵

文档描述：中央画布 + 左侧工具栏（顶部 `+`，下面素材库、模板）+ Agent 区。画布左下角有**缩放条**、**适应画布**按钮、**小地图**（打开后点小地图跳转，拖白色视口框连续移动）。具体尺寸与配色 ⚪ 未实操。

### 3.5 专节：图片与视频节点怎么共存（对应决定 K1）

**结论：四家没有一家把图片和视频分成两个工作面。** 它们共存的方式高度一致，可以直接照搬。

| **生成器随节点类型变形** | ✅ 同一组件，底栏参数随「创作类型」展开或收起🟢 | ✅ 模型 popover 分 `图片 \| 视频` 两 tab🟢 | ✅ 节点内按模型给不同的「生成方式」与清晰度🔵 | ✅ placeholder 与模型下拉随节点类型变🟢 |

**给我们的做法**（三条，按确定度排序）：

1. **一块画布、一个节点体系、一个生成器组件**。图片节点和视频节点是同级节点，不是两个模式。四家共识，零风险。
2. **用"上游类型决定下游可选类型"把两条链路串成一条有向图**（只有即梦明确这么做 🟢，但它是唯一既有图片又有视频又有时间线的完整实现）。我们的类型表见 §7.2。
3. **类型分流只发生在三个地方**：节点 `+` 菜单（哪些可建）、生成器底栏（哪些参数）、清单视图（分列）。**不发生在入口和画布**。

### 3.6 专节：Agent 怎么操作画布节点（对应决定 K5）

只有**即梦有完整的登录态实测证据**（🟢），TapNow 有完整的文档口径（🔵），可灵有公告口径（🔵），LibTV 有仓库口径（🔵）。

#### 即梦：实测可见的 Agent 工具面 🟢

`/创作分镜` 一次调用，Agent 的步骤行依次出现（`video-workflow-trace.md` §14.7 实测原文）：

```
使用技能：创作分镜
  → 搜索画布节点          ← 读：按条件找到画布上的既有节点
  → 编辑画布中（可展开）   ← 写：一个可展开的批量编辑动作
  → 创建视频节点 ×7        ← 写：建节点
  → (1/3) 运行节点         ← 写：触发节点生成
```

补充实测事实：
- **新节点自动连线到上游参考图**（节点数 13 → 16）。即 Agent 不仅建节点，还建**边**。
- **Agent 给节点起名**（「网球拍广告分镜1：持拍准备」），并把名字作为会话底部 **节点 chip** 的标题；**点 chip 直接缩放定位到画布上那个节点并选中**，chip 带「生成完成」状态。
- **Agent 设定节点的生成参数**，且这些参数在节点生成器里**可见可改**：`即梦 Seedance 1.0 Fast | 自动匹配·720P·1 | 首尾帧 | 5s | ✦10`。
- 第二轮用户回一句「继续」→ Agent **新建一个时间线节点**并把三个视频节点**连线进去**，消息里给出时间线 chip，**本次消耗 0 积分**。

由此反推出的 Agent 工具面（最小集，我们可以直接照着定）：

| 工具 | 读/写 | 即梦实测对应 |
| --- | --- | --- |
| `searchCanvasNodes(query/type)` | 读 | 「搜索画布节点」🟢 |
| `createNode(type, name, position, params)` | 写 | 「创建视频节点 ×7」🟢 |
| `connectNodes(from, to)` | 写 | 新节点自动连线到上游参考图🟢 |
| `updateNode(id, params/prompt/name)` | 写 | 「编辑画布中」🟢 |
| `runNode(id)` / `runGroup(ids)` | 写 | 「(1/3) 运行节点」🟢 |
| `createTimeline(name, clipIds)` | 写 | 「新建时间线节点 + 连线」🟢 |

#### TapNow：Agent 读「你明确选中的内容」🔵

- 「Agent 会读取你**明确选中**的内容，并把新的结果继续放回画布。」
- 「创作 Apps 只处理当前任务**明确提供的输入**。需要保持产品、角色或风格时，把唯一标准放到画布并在任务中引用，**不要期待 App 自动从所有历史内容中找出正确版本**。」
- 两种生成模式：`自动生成`（连续多步）/ `手动确认`（弹卡片可改**模型/比例/时长/数量/本次使用的参考**）。
- 堆叠的整叠操作里有「**加入对话**」：把一叠里的图片、视频、音频送进 Agent 对话作为引用，**文字节点不会进入对话**。

> **这是与即梦最大的分歧**：即梦的 Agent 自己「搜索画布节点」（主动找），TapNow 的 Agent 只读你选中的（被动拿）。

#### 可灵 🔵 / LibTV 🔵

- 可灵官方公告标题就是「**输出（对话+画布）**」，并支持「并行同步生成所有结果并**展示在画布上**」。粒度 ⚪。
- LibTV 官方仓库证实会话绑定项目画布（`{ projectUuid, sessionId, projectUrl }`），会话产物可批量下载；**Agent 是否能逐节点读写 ⚪ 未确认**。

#### 给我们的三条结论

1. **Agent 的工具面按即梦实测那六个工具定**（读 1 个、写 5 个），这是唯一有实测证据的完整集合。
2. **采用「主动搜索 + 显式选中」双通道**：默认读用户选中的节点（TapNow 的安全做法），但提供 `searchCanvasNodes` 让 Agent 在用户没选时也能找到班底资产（即梦的做法）。避免 TapNow 文档里那条警告描述的情况。
3. **Agent 的产出必须在画布上可寻址**：会话底部给节点 chip，点击缩放定位并选中（即梦 🟢）。这比"结果贴在聊天里"重要得多，因为 K4 的跑通标准要求用户能"单独重生成"某一片段。
4. ⚠️ **抄即梦的能力，不抄即梔的边界**：实测里即梦 Agent 零澄清零确认直接扣 30 积分、把三视图当首尾帧的首帧、用户明说 9:16 却出 16:9 且事后才注明、拼接要用户说「继续」。这四条全部是我们要避开的。

## 4. 官方标准流程（原样记录步骤顺序）

本节只记录**官方自己写的推荐步骤**，按原文顺序，不加工不重排。它回答的是「官方认为用户应该怎么走」。

### 4.1 即梦 ——《新画布使用手册》的章节顺序即流程 🔵

来源：即梦帮助中心 →「新画布使用手册」（官方公开飞书文档 `bytedance.larkoffice.com/wiki/X1elw8hpMiqWdLki3Mlc9WWznhd`，2026-09-17 读取，全文见 `video-workflow-trace.md` §11）。

官方定义：

> 「即梦画布是**面向多素材、多镜头创作的一站式 AI 创作空间**。图片、视频、音频、主体资产和时间线集中在同一张画布中，**从灵感梳理、素材准备、内容生成到镜头编排和成片，都可以在这里完成**。」

这句定义本身就是官方的流程顺序：**灵感梳理 → 素材准备 → 内容生成 → 镜头编排 → 成片**。手册的九个章节按这个顺序展开：

```
一、界面五区（画布区 / 工具栏 / 生成器 / 素材与生成历史 / Agent 面板）
二、节点与连线 → 主体资产（选中内容 → 保存为主体）
三、图片生成与编辑工具
四、图片预设（连续分镜图 / 多机位九宫格 / 人物三视图 / 面部三视图 / 产品三视图 / 场景俯视图）
五、视频生成与编辑工具（局部重拍 / 视频编辑 / 截取帧 / 补帧 / 修剪视频）
六、音频（音乐 / TTS 配音）→ 一键加入时间线
七、时间线与成片 → 七种导出
八、发布画布模板
九、积分规则与快捷键
```

官方对连线的使用纪律（原文）：

> 「连线具有方向：**上游节点提供内容或参考，下游节点接收这些输入并继续生成或编辑。** 连接完成后，**建议在执行任务前再次确认下游节点实际引用的内容**。」

官方对时间线的使用纪律（原文）：

> 「**时间线中的排列顺序就是成片的播放顺序。** 调整后建议从头预览一遍，重点检查画面衔接、音画同步和片段边界。」

官方对积分的口径（原文）：

> 「**发起生成或执行相关任务前，系统会展示预计积分，便于提前确认。**」
> 「**若任务因平台原因未成功完成，已预扣积分通常会退回**；已成功完成并交付结果的任务，对应积分不会退回。」

### 4.2 可灵 —— 灵动画布 Agent 的官方三步 🔵

来源：官方更新公告 2026-01-29《灵动画布-Agent 模式重磅上线！一键分镜，轻松出片》（每步都有官方配图，见 `video-product-teardown.md` §2.2）。

官方对输入的口径（原文）：

> 「您上传简单的故事梗概／复杂的剧本／详尽的分镜头描述，Agent 都可以将其扩展为完整故事分镜描述脚本」

**场景 1「故事分镜」的官方三步（原样顺序）**：

```
输入（一句话 + 角色参考图）
  ↓
[步骤 1] 生成主体和场景   → 角色白底立绘一排 + 道具 + 空场景板一排
  ↓
[步骤 2] 生成分镜图       → 4~5 列 × N 行的分镜图网格（官方实例 16 镜 / 20 镜）
  ↓
[步骤 3] 分镜视频
```

**这是四家里最清晰、也最该照搬的一条主干**：先造班底，再出分镜图网格，最后逐镜出视频。官方配图里角色是**标准三视图**（正/侧/背），场景是**无人空板**。

另外两个官方场景：
- **场景 2「多视角分镜」**：输入「请基于这个镜头扩展一批多角度分镜」+ 一张图 → 输出同一场戏的 9 个景别/机位。
- **场景 3「电商组图」**：一张商品图 → 「主图 + 模特图 + 场景图」。

两个官方通用能力：
- **多轮对话智能编辑**：官方列的序列是 `文生图 → 图像编辑 → 图像编辑 → 批量图生图`，标注「Agent 结合上下文识别意图」「Agent 分步输出」。
- **批量生成**：「Agent 可以处理您一次性输入的多个提示词，**并行同步生成所有结果并展示在画布上**，您还可以**批量框选**您需要的素材进行**批量下载**」。

官方的 brief 写法示范（可灵模板 chip 展开的具名样例《竹海听涛》实测原文，🟢）：

```
[图1][图2] 参考以下内容，生成一组可视化分镜
风格: 经典武侠电影质感，参考《卧虎藏龙》和黑泽明的电影美学。
角色:
  一位白发剑客，蒙着眼（盲人），衣着朴素，武器是一根竹杖。
  一位年轻气盛的挑战者，锦衣华服，手持一把削铁如泥的宝剑。
故事:
  开场 (分镜1-3): 大远景，清晨的竹海，雾气缭绕。…
  对峙 (分镜4-6): 盲眼剑客背对着他，仿佛在聆听风声。…
  交手 (分镜7-12): …镜头要快速切换…大量使用过肩镜头和跟拍镜头。
  终局 (分镜13-15): …只留下一句"你的剑，太吵了"。
```

**格式 = `风格 / 角色 / 故事` 三段，故事按幕分并标注每幕占哪几个分镜号。全自然语言，零表单字段。**

官方的逐镜 prompt 写法（VIDEO 3.0 使用指南原文，🔵）：

```
镜头 1，3s，脱口秀开放麦舞台中近景 @参考图，背面是大大的复古霓虹灯大字"KLING"，
       暖金侧逆光勾边，中景，镜头跟随演员，走到麦克风前，手指轻扶麦架，略微调整高度
镜头 2，4s，半身中景特写 @小小书童，开口说"我居然输给了 Kid，他上过几天班呀…"
镜头 3，4s，@小小书童 表情克制轻微嘲笑、停顿自然，"你听听，花 5 分钟，论证了这么个伪命题"
镜头 4，2s，切换到观众哈哈大笑
```

**格式 = `镜号，时长，景别 + 机位 + 主体(@) + 动作 + 台词`。**

### 4.3 TapNow —— 官方给了三条不同粒度的标准流程 🔵

#### (a)「第一次进入画布，建议这样开始」（官方原文六步）

> 1. 把一张图片或一份资料放到画布，它会成为一个节点；
> 2. 选中节点，打开 Agent，并说明要基于这份内容完成什么；
> 3. 如果选择了多份内容，分别告诉 Agent 每个节点的用途；
> 4. Agent 完成任务后，在画布上查看新生成的节点；
> 5. 沿着连线检查新结果使用了哪些输入；
> 6. 拖动节点整理位置，保持当前要使用的内容容易找到。
>
> 「第一次不需要搭建复杂结构。先完成一次"**选择节点 → 交给 Agent → 得到新节点**"的操作，就能理解画布怎样工作。」

官方给的「完成标准」（原文）：

> 知道画布上的内容会以节点保存；可以选择一个或多个节点交给 Agent；**能沿着连线找到结果使用的输入**；Agent 生成的新内容已经出现在画布上；页面显示最近修改已经保存。

#### (b)「怎样让多个 Apps 连续工作」（官方原文七阶段）

> 多个 Apps 可以沿着同一个项目连续工作，但**不要一次把所有动作交给 Agent**。按可验收的阶段推进：
>
> 1. 先读取并整理资料；
> 2. 确认要求和创意方向；
> 3. 生成少量静态候选；
> 4. 修正主体和画面细节；
> 5. 制作或剪辑视频；
> 6. 检查交付文件；
> 7. 确认后再同步到外部平台。
>
> 「**每一步都留下可检查的画布节点或文件。某一步结果不对时，可以从这里调整，不需要重跑整条链路。**」

**这七阶段是四家里唯一一条明确写出「分阶段可验收」纪律的官方流程**，而且它的第 3 步「生成少量静态候选」、第 4 步「修正主体和画面细节」正好对应我们跑通标准 K4 里的「角色图 → 首帧图」。

#### (c)「跟着做一次：把四个生成镜头组合成一条短片」（官方原文七步）

> 1. 按住 Shift，选中四个视频节点；
> 2. 点击选区上方的**创建播放列表**；
> 3. 把开场镜头拖到最左侧，把产品特写放到最后；
> 4. 拖动每个片段两端，裁掉开头和结尾不稳定的画面；
> 5. 在需要缩短的片段中移动播放头，按 `C` 切开并删除多余部分；
> 6. 从头播放一次，检查镜头顺序、黑帧、声音和总时长；
> 7. 选择**下载合并视频（MP4）**。
>
> 「下载完成后，在电脑上重新播放文件，确认它与时间线中的预览一致。」

官方的成片自检清单（原文）：

> 第一遍先把顺序排对，再处理每段视频的具体长度。
> 调整后从头播放一次，重点检查：镜头顺序是否能看懂；相邻镜头是否重复；人物或产品位置是否突然跳动；前后镜头的运动方向是否冲突；整体时长是否接近需要的长度。
> 导出前至少完整检查一次：是否有黑帧或多余静止画面；每个镜头的开头和结尾是否干净；相邻镜头是否衔接自然；视频声音是否突然中断或重复；总时长是否符合使用要求。
> 「**单独播放每个片段不够，很多问题只会出现在两个镜头的连接位置。**」

#### (d) 官方的「素材库 / 主体 / 模板 / 克隆画布」四分法（原文表）

> | 你想再次使用什么 | 使用 |
> | --- | --- |
> | 一张产品图、一段视频或一份音频 | 素材库 |
> | 同一个人物、产品或角色的一组参考资料 | 主体 |
> | 一组节点、连线和制作步骤 | 模板 |
> | 整张画布及其中的全部内容 | 分享并克隆画布 |

### 4.5 四家官方流程的交集

把 §4.1–4.4 四条流程对齐，**所有家都写到、且顺序一致**的只有这五步：

```
① 准备输入（素材放进画布 / 写 brief / 填参数）
② 造班底（角色 + 场景 + 道具，角色出三视图，场景出空板）
③ 出分镜画面（网格一次出 N 张，或逐镜出图）
④ 逐镜出视频（引用班底 + 首帧）
⑤ 排序成片（时间线 / 播放列表）→ 导出
```

**分歧只在 ①→② 之间**：可灵用一句话 + 参考图让 Agent 自己扩写；LibTV 用剧本设定器把它变成六道选择题；即梦让你自己准备或用模板；TapNow 让你先放资料再选中交给 Agent。

**没有任何一家把"写剧本"单独做成一个产品阶段** —— 它要么在 ① 里（brief / 剧本设定器 / 文本节点），要么由 Skill 一次带过。这与 `video-creation-workflow-2026-10-10.md` §1.1 的创作者侧结论一致：**剧本基本不是 AI 独写**。

## 7. 第一版「对齐搭建」建议

### 7.0 先对照跑通标准 K4

### 7.2 节点类型清单（第一版）

按四家交集 + 我们已有数据模型，建议 **8 种节点 + 2 种容器**：

| 节点 | 产出 | 上游可接 | 下游可接 | 依据 |
| --- | --- | --- | --- | --- |
| **文本** | 富文本（剧本/说明/可复用 prompt 块） | — | 全部 | 四家都有；即梦「文本节点作为后续生成要求」 |
| **图片** | 一张图 | 文本、图片、主体 | 图片、视频、主体 | 四家都有 |
| **视频** | 一段视频 | 文本、图片、视频、音频、主体 | 视频、时间线、主体 | 即梦的类型约束 🟢 |
| **音频** | TTS 配音 / 音乐 | 文本、主体 | 视频、时间线 | 即梦两种模式 🔵 |
| **主体** | 名称+描述+多模态参考 | 任意（「保存为主体」） | 图片、视频 | 三家共识 C5 |
| **分镜表** | `ProductionShot[]` | 文本 | 图片（批量铺首帧） | LibTV 脚本生成器 + 我们已有的数据模型 |
| **时间线** | 成片 | 视频、音频 | — | 即梦 C8、TapNow 播放列表 |
| **上传 / 从生成历史** | 把已有东西放进来 | — | 全部 | LibTV 菜单下半段 🟢 |

容器：**分组**（有名字、有背景色，组名用场次或资产类别）、**堆叠**（多候选收纳，≤50，可整叠下载/加入对话）。

**这张表同时就是 K1 的落地**：图片与视频是同级节点，没有任何一行把它们分到不同工作面；两条链路靠「图片 → 视频」和「视频 → 图片（截帧）」两条边连成一张图。"上游可接/下游可接"两列的作用是让节点 `+` 菜单能把不合法的类型置灰（即梦 🟢 的做法，见 §3.5）。

**明确第一版不做**：3D 节点、智能剪辑、逐帧拉片、导演台（3D 预演）、Apps/外部连接器、团队空间、样片→正片两段式。依据：S3/S7 只有 1 家；N4 的即梦版太重（TapNow 的球体版可以二期做）；W4 两段式只有 2 家且与 K4 的跑通标准无关。

### 7.3 引用语义（这是最需要一次定对的地方）

> **2026-10-11 修订**：下文第 3 条「不给参考模式下拉」已被推翻。四家实际都让用户在视频节点上选生成方式（即梦 `input_media_type`、可灵首帧/首尾帧、TapNow 按模型的模式、Flow 的 Frames/Ingredients），最终决定见 `CONTEXT.md`「生成方式」。

采用**即梦 + TapNow 的混合**：

1. **连线建立"可引用"关系**（TapNow 的语义，比即梦的"自动参考"安全）。
2. **连线在下游生成器里具象成一排带序号的缩略图**（即梦 + LibTV 的做法），**可单个移除**，右侧有 `+ 参考图`。
3. **用途写进 prompt，不给"参考模式"下拉**（TapNow 的做法 + 我们已有调研的硬结论）。内部的 `first-frame` / `last-frame` / `reference` 由流程规定死：
   - **首帧**只能来自分镜网格切分或截帧 —— 流程自动绑定，用户不选
   - **参考**只能来自 `@` 主体或 `@` 图片节点
   - 这正好对应已有的 `ProductionClipReference.usage`，无需改数据模型
4. **上游类型决定下游可选类型**（即梦 🟢），不合法的在 `+` 菜单里置灰。
5. **`@` 语法统一**：`@主体名` 和 `@图片3` 共用一套（可灵 🔵）。

## 8. 分歧点（需要拍板）

各家做法不一致、或我们证据不足以直接抄的地方。编号供后续 grill 使用。**已被 §1.5 的 K1–K5 拍板的问题不在此列**（入口是否分叉、第一版做什么内容、production 去留、成片在哪合成、Agent 能否读写节点，都已定）。

**D1. 连线是"自动引用"还是"只是让它出现在 `@` 列表里"？**
即梦：连线 = 参考列表，下游生成器顶部直接出现缩略图 🟢。TapNow：连线只建立"可引用"，还要在 prompt 里打 `@` 才算用 🔵。前者少一步、但即梦自己的 Agent 都会选错用途（把三视图当首帧）；后者更显式、但多一步。

**D2. 分镜由 Agent 一次铺完，还是用户确认分镜表后再铺？**
即梦 Agent 零确认直接建 7 节点并扣 30 积分 🟢。我们已有的判断是"分镜表是闸门 1"。但闸门会不会让"随便试试"的用户觉得慢？是否按**金额分档**（低于 N 积分不问）？

**D3. 开局用剧本设定器（LibTV 六参数）还是具名样例 brief（可灵）？**（已被 K2 部分收敛）
LibTV 的选择题适合完全没想法的人，但六个参数卡 + 题材轮盘是不小的 UI 工程。可灵的"点一个《竹海听涛》把完整 brief 填进输入框"几乎零成本，而且教会用户怎么写 brief。**两者可以叠**（预设 Top 8 = 一键填好参数），但第一版只能做一个。
→ K2 定了短剧/漫剧后，LibTV 那六个参数（目标受众/时代背景/核心看点/画风/集数/剧本结构）**全部是短剧词汇**，契合度明显更高。剩下要拍的是**先做哪一半**：只做「爆款预设 Top N」（≈可灵成本，一点就填好）还是连六个参数卡一起做。

**D4. 道具是独立资产类型，还是归到"场景"里？**
LibTV 把道具按场次拆成多组（饭店道具/墓地道具/饭店2道具）🟢；可灵把 Props 和 Costumes & Accessories 作为独立元素类型 🔵；我们当前只有 character 和 location。加一个 `ProductionProp` 会不会让资产面板过载？

**D5. 多候选是"堆叠"还是"节点历史左右切换"？顺带：「成片」和「片段」要不要做成两类产物？**
TapNow 堆叠（画布上少占位，但要展开才能看）🔵 vs 即梦节点历史（原地切换，但看不到全部）🔵。即梦还有第三种：右键「应用全部历史」把 N 个摊到画布。三选一还是都给？
附问：LibTV 的故事板按 `全部 / 成片 / 片段` 筛 🟢，说明它在数据层区分了两者；TapNow 用"播放列表导出"隐式区分；我们当前 `ProductionClipPlan` 只有片段概念。K4 要求"多片段 → 合成成片"，所以**至少要能区分**，但做成显式类型还是靠"是否进过时间线"推导，还没定。

**D6. Agent 读画布节点是"主动搜索"还是"只读用户选中的"？**（K5 带出来的真实分歧）
即梦实测：Agent 第一步就是「**搜索画布节点**」，自己去找班底资产 🟢。TapNow 官方：「Agent 会读取你**明确选中**的内容」，并警告「**不要期待 App 自动从所有历史内容中找出正确版本**」🔵。
主动搜索省事但容易拿错版本（即梦 Agent 把三视图当成首尾帧的首帧，就是找错了用途 🟢）；只读选中安全但用户每次都要先框一遍。§3.6 建议的是双通道（默认读选中，提供搜索工具兜底），但**默认行为必须定一个**。

**D7. 运镜/机位怎么表达？**
即梦给 3D 导演台（重）🟢；TapNow 给球体 + 6 个预设 + 景别 + 按时间段分段（中）🔵；可灵只写在 prompt 里（轻）🔵。我们已有 `ProductionShot.camera` 是自由文本。要不要升级成"预设词 + 景别"的结构化字段？

**D8. Skill 的粒度与自建开放度？**
LibTV 的 skill 是整条工作流且用户可自建（`+ 创建` + `我的`）🟢；即梦是官方技能市场 🟢；可灵干脆不做 🟢。我们当前 `apps/bff/skills/` 多数是单步能力，且只有 look 类支持用户自建（`createLookSkill`）。要不要把"流程级 skill"做成一等公民，并开放自建？
