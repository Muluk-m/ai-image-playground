2026-10-01 修订；核查基线 `168b5107`。本次按代码与提交历史修正优先级，未运行故障测试。实施队列统一登记在 [ROADMAP](../ROADMAP.md#b3-工程可靠性修复2026-10-01)，本文件保留技术细节。下文 PR 编号是建议切片；PR 1 的实施票已发布为 #968、#969、#970，尚未实施。

## 1. 结论与顺序

复用已有命令幂等、预扣事务、worker lease/fence、归档检查点、异步上游恢复、Agent 用量账本和产物交付隔离，不引入新框架。

| 顺序 | 优先级 | 范围 | 完成标准 |
|---|---|---|---|
| PR 1 / E2 | P0 | 模板超限拒绝、严格输入解析、冻结提交与输入框版本保护 | 必需素材不丢失，失败不提交，异步提交不覆盖新草稿 |
| PR 2 / E1 | P0 下线清理 | 删除无调用方的批量收费端点及专属测试 | 旧 URL 不再创建任务或产生预扣 |
| PR 3 / E3a | P1 | 统一 AgentCanvasView，明确元素类型及可编辑字段 | 观察和编辑来自同一视图，前后端准入规则一致 |
| PR 4 / E3b | P1 | 对象级编辑前置条件、幂等应用与回执 | 旧计划不覆盖新编辑，重放与撤销行为明确 |
| 后续 / E4 | P1 验证 | 归档失败、取消与完成并发两项故障注入 | 不重复生成，终态、产物与扣退费一致 |

P0 清理死端点的理由是收回闲置收费入口，不是给不存在的使用路径建设批量平台。E5 请求编译器、E6 版式导出、E7 成套任务均退出实施队列，先走 `/grill-with-docs` 再决定是否立项。

## 2. PR 1：E2 模板提交正确性

### 已确认的代码问题

- `packages/shared/src/sync-protocol.ts:19` 允许 `slotCount` 最大 8；`look-assembly.ts` 默认 `LOOK_ASSEMBLY_MAX_INPUTS = 4`，仅校验素材条数后以 `slots.slice(0, maxInputs)` 截断。5–8 个素材位且传齐素材时仍返回 `ok: true`，必需素材被静默舍弃，调用方继续普通付费提交。这是现有组装 bug，无需等待编译器建设。
- `apps/web/src/features/library/lib/lookSubmit.ts:48` 在参考图 fetch 非成功时直接 `continue`；`:73–74` 在缓存缺字节时跳过图片，但 prompt 已经按原图片顺序组装，会造成引用错位。
- `submitWithLook` 入口先捕获 `store = useStore.getState()`，之后等待网络；`typed = store.prompt` 虽写在第一次 await 后，读的仍是入口旧状态。随后 `replaceInputImages` 用旧文字覆盖当前输入；提交结束还会恢复旧文字、清空当前模板。代码路径已确认，测试用于固定回归边界。

### 面谈已定边界（2026-10-01，PR 1）

- Q1：本轮仅收口 PR 1，不同时设计整个 B3。
- Q2：取消模板专有 4 张限制，接入现有统一准入（当前平台协议上限 16）。该数不是所有上游模型的能力承诺；同时沿用模型是否接受参考图的校验。
- Q3：素材与模板配置的参考图都必须完整；超过总上限、缺图或加载失败就拒绝，不自动裁掉参考图。不新增 optional 字段。
- Q4：离开生成页面时取消准备中的提交，保留草稿；交给现有生成任务生命周期后继续执行。实现边界放在 `startGeneration` 建任务前（包括持久化素材的 await 之后），不以 HTTP 是否真正出站判断；请求已发出但回执未知不等于未受理。登录触发的恢复按 Q8 作为例外处理。
- Q5：交互与当前 chat 保持一致。核查 `AgentComposer`：提交受理前 `submitting` 防再次发送，输入仍可编辑；受理后释放门禁，不等生成结束。模板复用这一交互原则和 token 化释放：旧操作不能解锁新操作；空输入时沿用发送/停止按钮切换来取消准备。生成进行中可另发请求，但不复制 chat 的服务端 inbox 或取消已执行任务。已定 Q4 的离页取消继续有效。
- Q6：保留原有成功后处理及 `clearInputAfterSubmit` 设置语义（模板路径保留用户文字、移除本次模板）；期间已有新编辑或换模板则保护新草稿，不回写旧状态。组装数据走显式请求，不作为修改 composer 的中转。
- Q7：选择 A。本轮只修准备阶段；未知回执的恢复与“重试即新生成”的语义另列后续修复，不承诺本轮解决网络重试重复收费。
- Q8：保留现有登录后自动续发，作为 Q4 的明确例外。完成此次登录后继续点击时保存的请求；取消登录或主动离开生成页面则撤销对应待发送意图，保留草稿。取消只作用于本次操作，不能清掉后来另一笔待发送；登录恢复必须遵守 Q2/Q3 的完整性校验。

面谈与拆票已确认。PR 1 发布为 [#968](https://github.com/Muluk-m/ai-image-playground/issues/968)、[#969](https://github.com/Muluk-m/ai-image-playground/issues/969)、[#970](https://github.com/Muluk-m/ai-image-playground/issues/970)，均标记 ready-for-agent；#970 被 #969 阻塞。尚未实施。

### 最小修改

1. 在共享组装函数中取消模板专有上限，沿用统一输入准入。完整素材和参考图按现有稳定身份去重后超过有效上限时返回 `ok: false`（如 `input_limit_exceeded`）；调用方显示所需数量与上限，并尽可能在网络加载前预检。素材或参考均不得通过 `slice`/容量循环被静默丢弃，保留已保存的 5–8 位模板。
2. 点击提交时冻结 `LookSubmissionSnapshot`：文字、模板正文及版本、素材/视角、模型参数、当前账号/页面归属、命令 ID 和 composer revision。异步解析不得重新读取这些可变输入。
3. 新增 `resolveLookInputs(snapshot, signal)`，返回完整有序材料或带素材身份的错误。模板完整参考集合及素材图加载失败即停止；本轮没有自动省略的可选参考。成功后再生成引用序号与 prompt。
4. 复用已有 `submitPrepared` → `generationJob.ts` 显式提交入口，补齐完整配置冻结，不能只冻结 profileId 后仍读取提交时的可变设置；保留普通输入框提交包装。移除“修改全局输入框，再让无参提交读取”的中转。
5. 清空/恢复文字和模板前比较 composer revision；用户后来输入或换模板时不改当前状态。解析支持取消，账号或目标 scope 失效后停止准备；仅保留 Q8 明确的登录续发接缝。复用现有缓存和命令幂等。

### 回归验收

- 素材位为 5–8 时，只要完整输入符合统一准入就成功；素材与参考合计达到上限可提交、超过则明确拒绝。更小的有效上限同样生效，不静默删图。
- 首张/中间图片 404、缓存无字节、超时：submit 调用为 0，失败材料保留供重试。
- 完整请求的图片顺序与 prompt 序号一致。
- 在解析及提交期间输入新文字、换模板或改模型；原请求保持冻结，新草稿不被覆盖。离开页面或切账号时尚未发出的请求不提交，已发出请求的状态由既有生命周期确认。
- 登录成功后原请求只续发一次；取消登录或主动离页后不会迟到续发，旧操作取消不能清除新操作；准备期间改模型不改变原请求配置。
- 准备/交接阶段连点不多建任务，交接后主动再次发送是新操作。保留既有数量与槽位展开规则，以及原 `submitTask` 的总生成量检查；防重复不能依赖只覆盖单任务的 clientRequestId。共享组装单测与前端提交行为测试均覆盖；无数据库迁移。

## 4. PR 3：E3a 统一视图与编辑类型规则

`readCanvas`、`arrangeCanvas` 已通过 `loadAgentCanvas` 优先使用发话快照；`editCanvasObject.ts:40` 仍自行查询云端文档。其 `verdict()` 和前端 `agentCanvasSink.editElements()` 都只接受 image，不能仅替换后端查询就声称统一完成。

### 修改边界

- 对象查找、类型判断、计划构建统一走 `AgentCanvasView`。快照存在时（包括空画布）不回退旧云数据；无快照才走已有鉴权云端读取。媒体访问授权仍独立校验。
- 在共享层定义按元素类型和字段的准入规则，BFF 计划检查与前端应用共同使用；同步核对 `lib/projects.ts` 保存校验，避免前端应用成功、保存失败。
- 普通 image 保留现有名称/位置/尺寸修改。普通 text 应与服务端登记对象区别对待：本切片建议允许 x/y 位移；其 width/height 属于测量结果，不直接复用图片缩放语义。正文、字体修改留给后续需求，不在本轮新增文字排版能力。
- 服务端登记的占位和产物字段继续受保护；arrow、freedraw、timeline 等未定义映射的类型明确返回 unsupported，不把所有非图片对象一概解释为服务端保护对象。
- 普通文本与服务端保护对象的身份映射、允许字段需在本切片开工前写成明确规则；前后端同步实现，不先放开后端、让 sink 静默忽略。

### 验收

覆盖快照有/云端无、空快照/云端有旧对象、普通图片、普通文本、受保护对象与未知类型；断言计划、前端应用和保存校验一致。文本内容与测量字段保持原值，位移可撤销。

## 5. PR 4：E3b 编辑前置条件与回执

现有绝对坐标避免重放时累加位移，但没有防止旧计划覆盖用户后续操作。

- 新版计划携带 `operationId`、经现有绑定确认的目标画布身份，以及待改字段的 `expected` 值/摘要。
- 按对象与字段比较：对象已删则拒绝；待改字段变化则冲突；其他对象或无关字段变化不阻塞。
- 同一操作只应用一次、形成一个 undo 步骤；撤销后收到同一事件也不能重新应用。
- 回执逐项返回 applied/skipped/conflicted。工具先报告计划生成，前端应用后再报告真实结果；复用回执通道，不额外启动付费模型轮。
- 复用现有交付 scope/generation 隔离。新生成产物仍按 reservation 交付，不增加“整张画布 revision 未变化”的要求。
- 协议先扩后缩：旧消息可读，旧客户端兼容策略明确；缺前置条件的旧计划不得标为已受冲突保护。

验收覆盖同字段竞争、改名同时拖动、删除、切项目、重复事件、撤销后重放；断言真实对象值、逐项回执和 undo 次数。

## 6. E4：先验证两条扣退费关键路径

| 注入场景 | 技术方法 | 必须断言 |
|---|---|---|
| 图片已生成，对象存储暂时失败 | 在现有 runner/归档测试中注入存储失败，再恢复保存；走真实检查点和归档重试入口 | 上游生成次数不增加，预扣不重复，产物可恢复，最终结算一次且与成功状态一致 |
| 取消与完成并发 | 在终态写入/结算前用闩锁控制两种执行顺序，不用固定 sleep | 按现有状态机只有一个合法终态，扣款/退款不重复且符合胜出的终态，产物与任务状态一致 |

公开测试覆盖任务与恢复；私有 overlay 测试覆盖真实扣退费接缝。测试若暴露缺陷，在同一范围内修复；若已有覆盖充分则补缺口，不为补测新增框架或状态机。

SDK transport 尝试计量、租约接管、断线恢复等并入长期回归维护，出现具体缺口再立项，不占本轮独立 PR。增加自动重试前仍须有逐 HTTP 尝试记录与结算规则。
